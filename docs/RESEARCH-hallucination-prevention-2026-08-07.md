# 환각(사실 조작) 방지 연구 — 디오망데 사고 후속 (2026-08-07)

> 발주: 오너 "이걸 어떻게 방지할 수 있을지 연구를 좀 부탁해" (레알 오피셜이 바르사로 표기된 사고 직후).
> 결론 요약: **환각은 프롬프트로 줄이고, 검증으로 잡고, 관측으로 남긴다.** 한 층으로는 못 막고
> 5개 층을 겹친다 — 이번 주 실사고 5건이 각각 다른 층에서 잡혔거나 뚫렸다.

## 1. 이번 주 실사고 카탈로그 — 환각의 다섯 얼굴

같은 병의 다른 증상들. 전부 "입력에 없는 것을 모델이 사전 지식으로 채운" 사고다.

| 사고 | 유형 | 어디서 | 뚫린 이유 | 현재 상태 |
|---|---|---|---|---|
| 디오망데 "바르사" 오피셜 | **엔티티 환각** (클럽) | VPS 티커 요약 → 사가 추출로 전파 | 원문에 클럽명이 없어 모델이 프라이어로 채움. 후단이 오염 입력을 그대로 신뢰 | 수습 + 사가 추출에 클럽 증거 검사 배포 (`7bf91b2f`) |
| 기마랑이스 "£75m → 1억 유로" | **수치 왜곡** | VPS 티커 요약 | 환율 변환+반올림을 모델이 임의로 (실제 ≈€87m) | 미방어 — 본 연구 P1 |
| 이호재 "독일 진출" | 엔티티 추정 (원문은 "유럽") | VPS 티커 요약 | 잘린 제목의 빈칸을 추정으로 채움 | 미방어 — P0-a·P1 공통 |
| 코디 갓포 표기 | **표기 환각** (음차) | 기사 작성 | 사전에 옛 표기가 있었지만 발행 경로에 교정 없음 | 발행 치환+네이버 검증 루프 배포 (`644e6fc4`) |
| UCL 결승 "승부차기 4-3 승리" | **방향 해석 오류** | 리뷰 생성 (레퍼런스 작업 중) | 홈-원정 순 원표기의 방향 해석을 모델에 맡김 | 계산된 팩트 주입으로 수정 (`d546b373`) |

## 2. 실측 — 얼마나 자주 일어나나

최근 30일 transfer 티커 17건 수기 감사: **명백 오류 1(디오망데) + 수치 왜곡 1(기마랑이스) + 의심 1(이호재) ≈ 12~18%**.
표본은 작지만 "드문 일"이 아니라는 데는 충분하다. 특히 **원문이 짧거나 잘렸을 때** 집중 발생.

## 3. 원리 — 왜 생기고, 무엇이 통하나

- LLM은 빈칸을 못 견딘다. 원문에 클럽이 없으면 "디오망데 = 과거 바르사 링크" 같은 학습 프라이어로 채운다. 확신도까지 1로 뽑는다 — **모델의 자기 확신은 근거가 아니다.**
- 업계 공통 결론 ([검증 파이프라인 사례](https://arxiv.org/html/2605.27700v1), [실무 가이드](https://www.getmaxim.ai/articles/llm-hallucination-detection-and-mitigation-best-techniques/)): 생성 단계 프롬프트만으로는 부족하고, **출력에서 사실 요소를 뽑아 원문과 기계적으로 대조**하는 후단 검증이 핵심이다. "출력에는 있는데 원문에 없는 요소 = 환각 후보로 제거"가 표준 패턴 ([구조화 추출+대조](https://arxiv.org/pdf/2607.03325), [스팬 단위 검출](https://arxiv.org/pdf/2607.00895)).
- 고위험 출력은 검증기 LLM + 의심 시 2차 리뷰어의 **계단식 게이트** ([CiteCheck 구조](https://arxiv.org/html/2605.27700v1)) — 우리 검사관(fail-closed) 패턴과 동형.
- 우리가 이미 증명한 것: 갓포(네이버 검색량 대조), 클럽 증거 검사(substring), 승부차기(계산 팩트 주입) — 전부 "**모델 판단을 결정론 검증으로 감싸기**"였다.

## 4. 방어 5계층 — 우리 파이프라인 지점별 설계

```
L1 생성 규칙   "원문에 없으면 쓰지 마라, 모르면 비워라" (프롬프트)
L2 증거 검사   출력의 엔티티·수치가 원문에 실존하는지 결정론 대조 (코드)
L3 교차 일관성  같은 선수의 최근 소식들과 모순 검사 (DB — 우리만 가진 무기)
L4 검증 게이트  고위험(오피셜)만 2차 검증 LLM + 외부 대조 (비용 집중)
L5 관측·회귀   근거 탈락을 원장에 기록 + 골든셋에 함정 박제 (건틀릿)
```

디오망데 사고를 이 판에 놓으면: L1 없었음(VPS) → L2 없었음(당시) → **L3이 있었다면 잡혔다**
(전날 "레알" 티커 3건과 정면 모순인 "바르사" 1건) → L4 없었음 → 사람 눈(오너)이 L5 역할.

## 5. 실행 제안 — 우선순위 × 비용 × 지점

| # | 방안 | 층 | 지점 | 비용 | 근거 |
|---|---|---|---|---|---|
| P0-a | **VPS 요약 프롬프트 한 줄** — "클럽·리그·금액은 원문에 명시된 경우만. 없으면 선수명 중심으로" | L1 | VPS `/opt/crawlers` | 승인+5분 | 발원지 차단. 오너 승인 대기 중 |
| P0-b | **시계열 일관성 가드** — 오피셜/breaking 티커 유입 시 같은 선수의 최근 7일 티커·사가 클럽과 불일치하면 `/transfer` 노출 보류 + 디스코드 운영 알림 | L3 | repo `lib/transfer/feed.ts` 또는 티커 소비 지점 | 반나절 | 디오망데를 기계로 잡았을 유일한 층. 오탐(진짜 하이재킹)도 "보류+알림"이라 안전 — fail-closed |
| P1-a | **수치 증거 검사** — 헤드라인의 금액·연차 숫자가 원문 숫자 집합(±통화 변환 허용범위)에 없으면 강등 | L2 | 티커 소비 지점 + 뉴스 게이트 | 반나절 | 기마랑이스형. 정규식만으로 가능 — LLM 불요 |
| P1-b | **오피셜 전용 외부 대조** — 오피셜 티어(하루 0~2건)만 웹 검색 1콜로 클럽 확인, 불일치·확인불가 시 보류 | L4 | 뉴스 게이트·사가 승격 전 | 1일 | 오늘 내가 수동으로 한 검증(레알 공식 페이지 확인)의 자동화. 건수가 적어 비용 무시 가능 |
| P1-c | 클럽 증거 검사 **확장** — 뉴스 기사 작성 경로(제목·본문의 클럽 단정)에도 동일 substring 가드 | L2 | `lib/news` 게이트 | 반나절 | 사가에만 넣은 가드의 일반화 |
| P2-a | 골든셋 함정 케이스 — "클럽명 없는 오피셜 제목" 유형을 G-뉴스 골든셋에 박제 | L5 | 건틀릿 | 라벨 몇 건 | 회귀 방지 |
| P2-b | 관측 지표 — 증거 탈락률(dropped clubs/숫자)을 원장·어드민에 노출. 급등 = 상류 오염 신호 | L5 | cron 응답·모니터 | 반나절 | "조용한 실패 금지" 원칙 |

### 설계 원칙 3줄 (전 지점 공통)

1. **빈칸은 빈칸으로** — 클럽 미상 오피셜은 "얀 디오망데 이적 공식 발표"로 낼 수 있다. 틀린 단정보다 낫고, 사가는 선수 identity로 연결되므로 기능 손실도 없다.
2. **방향·변환은 계산해서 주입** — 홈/원정, 환율, 승부차기 승패처럼 뒤집힐 수 있는 것은 모델에게 해석시키지 않고 코드가 계산한 결과를 팩트로 준다.
3. **모순은 보류로** — 교차 검사에서 걸리면 자동 수정하지 않는다(진짜 반전 기사일 수 있다). 보류 + 사람 알림이 정답.
