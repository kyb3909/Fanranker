# 정기 기사 작성과 데스킹 보충

## 운영 흐름

- VPS `/opt/news-scanner/run.sh`가 15분마다 실제 뉴스 원문을 수집하고 초안을 저장한다.
- 작성기는 `/api/news/correction-examples`에서 상시 편집 원칙, 승인된 교정 지침, 수정 전후 사례와 표기 사전을 읽는다. 자료나 정책 버전을 확인하지 못하면 해당 회차의 작성을 보류한다.
- 원고의 `raw.editorial_guidance`에 작성 시점과 적용한 규칙·교정 지침 ID를 기록한다. 이는 입력 기록이며, 각 지침 준수를 보장하는 검수 결과는 아니다.
- Vercel `/api/cron/news-desk`가 매시 12·27·42·57분에 수정 기록 학습과 실제 기사 보충을 실행한다. 별도 연습 원고를 재생성하지 않는다.
- 새 기사 자동 대기분은 기본 6개, 하루 자동 추가 한도는 한국 시간 기준 12개다. VPS 전체 생성량을 제한하는 설정은 아니다. 설정은 데스킹 화면의 **새 기사 자동 보충 설정**에서 조정한다.

## 보충 조건과 보존 범위

최근 24시간에 작성한 축구 기사 중 원문이 보관되어 있고 현재 활성 규칙 전체를 불러온 뒤 작성한 원고를 연결한다. 동일 기사 ID 또는 원문 URL, 이미 검수한 원고는 다시 추가하지 않는다. 기존에 직접 불러온 과거 기사와 숨겨진 연습 원고는 새 기사 대기 목표에 포함하지 않는다.

`origin.auto_queue`로 자동 추가 원고를 구분한다. 기사 본문과 공개 상태는 보충 과정에서 변경하지 않는다. 공개 글은 기존 글, 미발행 글은 기존 초안에 연결한다. 저장·검수 완료의 반영 범위와 버전 충돌 처리는 기존 데스킹 RPC가 담당한다.

자동 보충과 관리자 추가 요청은 동일한 5분 작업 잠금을 사용한다. 대기 수와 당일 추가 수는 DB에서 정확히 집계한다. 실패하면 잠금을 해제하고 오류를 설정과 크론 실행 기록에 남긴다.

## 2026-09-16 규칙 충돌 수정

정기 작성기의 예전 지시에 존대체 예문과 “첫 문장은 누구의 보도인지로 연다”가 남아 있었다. 활성 규칙을 입력받아도 이 지시와 충돌해 실제 바르셀로나 기사에서 출처로 시작하는 리드가 생성됐다. 예전 지시를 제거하고, 상시 규칙이 과거 교정 예시보다 우선함을 명시했다. 교정 사례의 편집자 메모도 작성기에 전달한다.

존대 종결과 출처로 시작하는 리드는 해당 활성 규칙 ID에 따라 실제 출력에서 검사한다. 위반하면 한 차례 전체 원고를 다시 작성하고, 재검사도 실패하면 저장을 보류한다. 직접 인용의 종결은 보존한다. 재작성 후 기존 날짜·인물·한국어 제목 검사도 다시 적용한다. 이 검사는 두 가지 문체 결함만 판정하며, 모든 편집 규칙의 의미적 준수나 사실성을 보장하는 검수가 아니다.

실제 바르셀로나 원고를 재작성해 첫 문단은 핵심 소식, 둘째 문단은 보도 출처가 되도록 바뀐 것을 확인했다. 문체·날짜·이름 검사와 기존 원문 대조 검사를 통과했다. 검증 중 원고가 자동 발행돼 기존 초안 수정은 동시 변경 검사에서 취소됐다. 비교 결과는 `output/live-desking/style-repair-result.json`에 보관한다.

데스킹 화면은 기사 작성 시각과 작업 목록에 추가한 시각을 구분한다. 규칙 개수는 작성기에 전달한 참고 기록이며 검수 합격 표시가 아니다.

운영자 후속 지시에 따라 두 작성 경로 모두 현재 활성 규칙을 최우선으로 삼는다. 과거 원고는 오류가 남을 수 있는 부분 교정 기록으로 전달하며, 전체 문체·구성을 모방하라는 지시는 제거했다. 현재 원문의 사실과 확정 표기를 지키면서 현재 규칙, 그에 부합하는 승인된 교정 지침, 과거 수정의 의도 순으로 참고한다.

이 변경의 작성 정책 버전은 `2026-09-16.1`이다. 새 원고의 작성 입력 기록에서 이전 버전과 구분할 수 있다.

## 2026-09-16 과거 초안 자동 발행 차단

`hermes-reddit-1wgwzfy`(더 타임스 데 제르비·솔란케 기사)는 9월 15일 20:06 KST에 작성됐지만 9월 16일 05:38 KST에 자동 발행됐다(`publish.auto=true`, 공개 글 `6a111dfc-3e97-445e-84b2-bd0fbdcc8165`). 작성 지침 기록이 없고 존대 종결·출처로 시작하는 리드가 남아 있었다. 작성기 갱신만으로 이미 저장된 발행 대기 원고를 보호하지 못한 사례다.

자동 발행 크론은 현재 활성 규칙을 읽고 본문을 검사한다. 현재 정책 버전·활성 규칙 ID 전체·규칙 수정 이후의 자료 로딩 시각이 없으면 `editorial_rules_stale`, 실제 본문에 존대 종결이나 출처 우선 리드가 있으면 `editorial_style_violation`으로 데스킹 대상(`needs_human`)에 남긴다. 초안 본문·공개 상태를 자동 수정하거나 반려하지 않는다. 재작성 또는 사람이 검수한 뒤 수동 발행할 수 있다.

공통 발행 함수도 게시글 삽입 직전에 규칙을 다시 읽고 최종 본문을 검사한다. 검사 중 규칙이 바뀌거나 크론의 사전 검사를 우회한 자동 호출에도 적용된다. 규칙 조회 장애는 재시도 대상으로 남긴다. 사람의 명시적 검수 발행은 기존 흐름을 유지한다.

검증: 제보된 원고 그대로의 자동 발행 차단, 최신 지침 기록이 있어도 잘못된 본문 차단, 규칙 기록 누락·구버전·수정 전 로딩 차단, 정상 원고 발행, 검사 중 규칙 변경, 조회 장애, 공통 발행 함수 직접 호출, 기존 중복·품질 검사 회귀 테스트와 TypeScript 검사. 자동 검사는 위 두 문체 결함과 지침의 최신 여부를 확인하며, 발언의 진위·전망 기간·경기 기록 시점 등은 별도 원문 대조가 필요하다.
