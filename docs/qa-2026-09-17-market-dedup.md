# 승부예측 회차 중복 수정 — 2026-09-17

상태: **2026-09-17 04:04 KST 운영 반영 완료.** 로컬 구현, 분리 배포본 자동 검증 및 운영 Supabase 읽기 전용 검증 완료. 운영 DB 변경 없음. 남은 QA 목록 중 첫 번째 항목만 수정했다.

## 변경 동작

- 같은 종목·리그·홈/원정 원문·킥오프·마켓 종류·기준점의 선택지는 배당이 달라도 최신 회차 하나만 표시한다. 날짜 표기 방식이 다른 동일 시각도 같은 경기로 비교한다.
- 회차 안에서 전반전·SUM을 제외한 다음 `gm_ts` 순서를 비교한다. `gm_ts`가 없는 구형 데이터는 `year/round`를 사용한다. 회차 정보가 없거나 순서가 모호하면 오류를 반환한다.
- 최신 행을 선택한 뒤 판매 상태를 적용한다. 최신 회차가 취소·완료·진행 중이거나 배당이 0이어도 구회차 선택지로 되돌리지 않는다. 배당 0은 기존 UI의 선택 불가 동작을 유지한다.
- 목록, 그룹, 전체 건수는 같은 최신 행 집합을 사용한다. 서로 다른 핸디캡·언더오버 기준점은 보존한다.
- 로그인 사용자의 기존 예측은 구회차 `game_id`와 `locked_odds`를 그대로 조회한다. 기존 경기·예측·슬립을 삭제하거나 최신 행으로 이동하지 않는다.
- 제출 API는 선택한 경기의 모든 회차와 전반전 분류 문맥을 500행씩 조회한다. 구회차 ID, 재조회 중 바뀐 판매 상태·기준점은 볼 차감 전에 `409 MARKET_CHANGED`로 거부한다.
- 클라이언트는 선택 당시 `expected_odds`를 보낸다. 서버 배당과 다르면 차감 전에 재선택을 안내한다. 클라이언트는 응답에서 지정한 선택만 제거하고 경기 목록을 갱신하며, 다른 선택·사용 볼 수는 보존한다.
- 새 예측에는 검증한 배당과 해당 경기의 회차 ID를 저장한다. 슬립 배당 계산도 같은 검증값을 사용한다. 이미 접수된 멱등 요청은 기존 접수 결과를 반환한다.

## 주요 파일

- `lib/betman/market-dedup.ts`: 가격과 독립된 경기·시장 식별 및 회차 순서.
- `lib/betman/market-scope.ts`: 신규 제출용 모든 회차 조회. 정산의 기존 회차별 조회 함수는 유지.
- `lib/betman/games-payload.ts`: 최신 목록·건수와 기존 예측 조회. SSR 캐시 키 버전 변경.
- `app/api/betman/prediction/route.ts`: 차감 전 최신 여부·선택 배당 검사 및 고정 배당 저장.
- `hooks/use-betting-slip.ts`: 선택 배당 전송과 변경 안내.

## 남은 검증과 구현 경계

- 앞선 `pnpm test:e2e:check`에서 로컬 `supabase_db_community` 연결/스키마 확인이 실패했다. 실제 DB에 예측을 저장하고 취소·정산하는 회원 브라우저 E2E는 미실행이다. 운영 DB에 테스트 예측을 만들지 않았다.
- 운영 반영 후 실제 브라우저에서 로그인 사용자의 과거 예측 조회와 오래 열린 탭의 재선택 안내를 추가 확인할 수 있다. 이번 배포는 빌드·도메인·크론 연결과 운영 Supabase 읽기 전용 결과를 검증했으며, 운영 사이트에 추가 테스트 예측을 제출하지 않았다.
- 수집 완료를 표시하는 별도 회차 플래그는 현재 없다. DB에 실제로 존재하는 최신 행을 사용하며, 신규 행의 일일 라운드가 미배정이면 제출을 허용하지 않는다. 회차 전체 수집 완료 여부를 새로 추정하지 않는다.
- 검증 조회와 기존 차감·삽입은 하나의 DB 트랜잭션이 아니다. 마지막 조회 이후 동기화와의 경쟁까지 원자적으로 막는 구조는 이번 수정에 포함하지 않는다.
- `expected_odds`는 구형 요청 호환을 위해 선택 입력이다. 새 클라이언트는 항상 선택 배당을 전송한다. 구형 요청은 서버의 검증 시점 배당으로 저장하며, 구회차 ID 차단은 배당 입력 유무와 관계없이 적용된다.
