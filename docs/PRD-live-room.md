## 1. 제품 개요

### 1.1 제품명

**라이브 응원방** (Live Match Room)

### 1.2 한 줄 설명

진행 중인 스포츠 경기에 맞춰 자동 생성되는 픽셀아트 경기장에서, 최대 20명의 팬이 팀 유니폼을 입은 아바타로 입장하여 실시간 응원 채팅을 하는 공간형 소셜 기능.

### 1.3 제품 목표

- 경기 시청 중 "같이 보는 느낌"을 제공하여 체류시간과 재방문율을 높인다
- 기존 텍스트 게시판/예측 기능에 실시간 소셜 레이어를 추가한다
- 팀 유니폼 구매를 통해 포인트 경제의 소비처를 확장한다
- 일반 스포츠 커뮤니티, 디스코드와 차별화되는 비주얼 경험을 만든다

### 1.4 현재 서비스와의 관계

이 기능은 gongnori.fan의 기존 인프라 위에 구축된다.

| 기존 시스템 | 연동 방식 |
|------------|-----------|
| Clerk 인증 | 로그인된 사용자만 입장. 기존 계정 그대로 사용 |
| profiles 테이블 | 닉네임, 아바타 정보 연동 |
| user_tokens (볼) | 유니폼 구매 시 볼 차감 |
| token_transactions | 유니폼 구매 내역 기록 |
| betman_games | 경기 데이터 기반 방 자동 생성 |
| betman_predictions | 해당 경기 예측 여부 표시 가능 |
| Supabase | Realtime (Presence + Broadcast) 활용 |
| Vercel | 기존 배포 파이프라인 그대로 |

## 2. 문제 정의

### 2.1 현재 한계

| 문제 | 설명 |
|------|------|
| 실시간 소통 부재 | 경기 중 흥분을 나눌 곳이 없음. 게시판은 비동기적 |
| 공간감 없음 | 텍스트 채팅은 "같이 보는 느낌"을 주지 못함 |
| 포인트 소비처 부족 | 매일 1,000볼 지급되지만 예측 베팅 외에 쓸 곳이 제한적 |
| 경쟁 서비스 대비 차별점 약함 | 타 스포츠 커뮤니티, 디스코드 대비 시각적 차별화 요소 부족 |

### 2.2 해결 방향

경기에 연동된 픽셀아트 경기장에 아바타를 배치하고, 말풍선 기반 실시간 채팅을 제공하여, "경기장 관중석에 같이 앉아있는" 경험을 만든다.

## 3. 성공 지표

### 3.1 핵심 KPI

| 지표 | 목표 (MVP 런칭 후 4주) |
|------|----------------------|
| 응원방 입장 유저 수 / 경기 | 평균 5명 이상 |
| 입장 후 첫 메시지 전송률 | 70% 이상 |
| 평균 세션 길이 (응원방 내) | 15분 이상 |

| 응원방 경험 후 D7 재방문율 | 40% 이상 |

### 3.2 추적 이벤트

- `live_room:enter` - 방 입장
- `live_room:message_sent` - 메시지 전송
- `live_room:leave` - 방 퇴장 (체류시간 포함)
- `uniform:purchase` - 유니폼 구매
- `uniform:equip` - 유니폼 착용 변경

## 4. 타겟 사용자

### 4.1 핵심 타겟

gongnori.fan의 기존 유저 중:
- 경기 예측에 참여하는 활성 유저
- 커뮤니티 게시판에서 경기 중 실시간 반응을 올리는 유저
- 특정 팀 팬덤 성향이 강한 유저

### 4.2 페르소나

**A. 경기 같이 보고 싶은 팬**
- 혼자 집에서 경기 보면서 다른 팬들과 같이 떠들고 싶음
- 디스코드는 귀찮고, 커뮤니티 게시판은 느림
- "같은 팀 유니폼 입은 사람들이 있는 공간"에 끌림

**B. 예측 게임 유저**
- 이미 betman 예측에 참여 중
- 경기 결과를 기다리면서 다른 예측 유저와 이야기하고 싶음
- 응원방이 예측 결과 확인과 자연스럽게 이어짐

**C. 방 운영자/모더레이터**
- 특정 경기방의 분위기를 관리
- 도배/욕설 유저를 제재

## 6. 사용자 시나리오

### 6.1 메인 플로우: 경기 응원

```
1. 유저가 gongnori.fan에 로그인한 상태
2. GNB 또는 경기 페이지에서 "라이브 응원방" 진입
3. 현재 열린 방 목록이 보임 (진행 중 경기 우선 정렬)
   - "토트넘 vs 아스널 | 🟢 진행중 | 14명 참여"
   - "두산 vs LG | ⏳ 30분 후 시작 | 3명 대기"
4. 방을 클릭하면 픽셀아트 축구장/야구장이 로드됨
5. 내 아바타가 빈 좌석에 자동 배치됨
   - 유니폼을 구매했으면 해당 팀 유니폼 착용 상태
   - 없으면 기본 회색 캐릭터
6. 다른 접속자들의 아바타와 닉네임이 보임
7. 하단 입력창에 "ㅋㅋㅋ 골!!!" 입력 → 엔터
8. 내 아바타 위에 말풍선 표시 + 채팅 패널에 메시지 추가
9. 다른 유저의 메시지도 실시간으로 말풍선 + 채팅에 표시
10. 경기 종료 후 방은 30분간 유지된 뒤 자동 닫힘
```

### 6.2 유니폼 구매 플로우

```
1. 응원방 입장 시 또는 상점에서 유니폼 목록 확인
2. "토트넘 홈 유니폼 - 300볼" 선택
3. 구매 확인 → 볼 차감 → user_uniforms에 기록
4. 즉시 착용 또는 나중에 설정에서 변경
5. 다음 응원방 입장 시 해당 유니폼 아바타로 표시
```

### 6.3 방 라이프사이클

```
경기 시작 1시간 전  → 방 자동 생성 (상태: waiting)
경기 시작           → 상태 변경 (상태: live)
경기 종료           → 상태 변경 (상태: ended)
경기 종료 + 30분    → 방 닫힘 (상태: closed), 접속자 전원 퇴장
```

모바일에서는 경기장이 상단, 채팅 패널이 하단으로 쌓임.

### 7.2 말풍선 규칙

| 항목 | 값 |
|------|-----|
| 표시 시간 | 5초 후 fade out |
| 최대 글자 | 30자 (초과 시 말줄임) |
| 최대 줄 수 | 2줄 |
| 동시 표시 | 유저당 최신 1개만 |
| 겹침 방지 | 고정 좌석이므로 겹침 없음 |

### 7.3 채팅 규칙

| 항목 | 값 |
|------|-----|
| 최대 글자 | 100자 |
| 도배 방지 | 3초 쿨다운 |
| 빈 메시지 | 전송 불가 |
| XSS 방지 | 서버/클라이언트 양측 sanitize |
| 시스템 메시지 | 입퇴장 알림 (채팅 패널에만, 말풍선 없음) |

### 7.4 좌석 시스템

- 방별 최대 20석 (4행 5열 또는 3행 7열 등 배경에 따라 배치)
- 입장 시 빈 좌석 자동 배정 (앞줄부터)
- 좌석 좌표는 배경 이미지에 맞춰 사전 정의
- 퇴장 시 좌석 반환
- MVP에서는 좌석 이동 불가

### 7.5 유니폼 시스템

| 항목 | 설명 |
|------|------|
| 구매 화폐 | 볼 (기존 user_tokens.token_balance) |
| 가격 | 팀당 300~500볼 (조정 가능) |
| 소유 | 영구 소유. 여러 팀 유니폼 보유 가능 |
| 착용 | 한 번에 1개만 착용. 설정에서 변경 가능 |
| 미착용 시 | 기본 회색 픽셀 캐릭터 |
| 표시 | 응원방 내 아바타 + 채팅 패널 닉네임 옆 팀 뱃지 |

## 8. 기술 아키텍처

### 8.1 기술 스택

| 레이어 | 기술 | 근거 |
|--------|------|------|
| 프론트엔드 | Next.js 15 (App Router) + React 19 | 기존 스택 |
| 방 렌더링 | DOM 기반 absolute positioning | Canvas 대비 구현 단순. 20명이면 성능 충분 |
| 실시간 통신 | Supabase Realtime (Presence + Broadcast) | 별도 서버 불필요. 기존 Supabase 프로젝트에서 바로 사용 |
| 인증 | Clerk → Supabase JWT | 기존 인증 흐름 그대로 |
| DB | Supabase PostgreSQL | 기존 DB |
| 이미지 | Supabase Storage 또는 public 폴더 | 픽셀아트 에셋 저장 |
| 배포 | Vercel | 기존 배포 |

### 8.2 Supabase Realtime 설계

**별도 WebSocket 서버 없이** Supabase Realtime으로 MVP 전체를 구현한다.

```
Channel: live-room:{roomId}

Presence (접속 상태):
- track: { userId, nickname, seatIndex, uniformId }
- 입장 시 track, 퇴장 시 untrack
- presence_state로 현재 접속자 목록 동기화

Broadcast (메시지):
- event: "chat" → { userId, nickname, text, timestamp }
- event: "system" → { type: "join"|"leave", nickname }
```

**장점**: 인프라 추가 없음, Supabase 무료 티어에서 동시 200 연결 가능, Clerk JWT 인증 그대로 적용.

### 8.3 방 라이프사이클 관리

```
크론 (betman-sync, 30분마다)
  └→ 새 경기 감지 시 live_rooms 레코드 자동 생성 (status: scheduled)
  └→ 경기 시작 1시간 전 → status: waiting
  └→ 경기 시작 → status: live
  └→ 경기 종료 → status: ended
  └→ 종료 + 30분 → status: closed
```

| GET | /api/uniforms/my | 내가 소유한 유니폼 + 현재 착용 정보 |
| POST | /api/uniforms/purchase | 유니폼 구매 (볼 차감) |
| PATCH | /api/uniforms/equip | 착용 유니폼 변경 |

### 10.3 실시간 (Supabase Realtime, API 아님)

프론트엔드에서 직접 Supabase Realtime Channel 사용:
- Presence: 입퇴장 관리
- Broadcast: 채팅 메시지 송수신

## 14. 비기능 요구사항

### 성능
- 방 입장 후 2초 이내 렌더링 완료
- 메시지 전송 → 다른 유저 수신: 체감상 즉시 (< 500ms)
- 20명 동시 접속 시 60fps 유지 (DOM 기반)

### 안정성
- Supabase Realtime 자동 재연결
- Presence heartbeat로 좀비 세션 정리
- 방 status 전환은 서버 사이드 (크론)에서만 수행

### 보안
- Clerk 인증된 사용자만 방 입장
- Supabase Realtime 채널 접근에 JWT 인증 적용
- 메시지 sanitize (XSS 방지)
- 유니폼 구매 API에 rate limit 적용

## 18. 수용 기준 (Acceptance Criteria)

**AC-01**: 유저가 방 목록에서 열린 응원방을 확인하고 입장할 수 있다.

**AC-02**: 입장 시 픽셀아트 배경 위에 본인 아바타와 닉네임이 표시된다.

**AC-03**: 메시지를 전송하면 본인 아바타 위에 말풍선이 표시되고 5초 후 사라진다.

**AC-04**: 다른 유저의 메시지가 실시간으로 해당 아바타 위 말풍선 + 채팅 패널에 표시된다.

**AC-05**: 유저의 입퇴장이 다른 유저 화면에 실시간으로 반영된다.

**AC-06**: 볼로 유니폼을 구매하면 아바타 외형이 해당 팀 유니폼으로 변경된다.

**AC-07**: 방 정원(20명) 초과 시 입장이 거부된다.

**AC-08**: 도배(3초 이내 재전송)가 클라이언트에서 차단된다.
