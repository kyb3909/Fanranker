# 반복 사용 프롬프트 가이드

## 1. 코드 품질 개선 (주 1회)
```
코드베이스 감사해줘. 중복 코드, 미사용 import, any 타입,
하드코딩된 색상, 에러 핸들링 누락을 찾아서 수정해줘.
```

## 2. 성능 점검 (주 1회)
```
next build 실행하고 번들 사이즈 분석해줘.
큰 청크, 불필요한 dependency, 이미지 최적화 여부 확인하고 개선해줘.
```

## 3. 보안 점검 (월 1회)
```
API 라우트 전체 보안 감사해줘. 인증 누락, 입력 검증 부재,
SQL injection 가능성, rate limiting 필요한 곳 찾아서 수정해줘.
```

## 4. DB 최적화 (월 1회)
```
Supabase 쿼리 성능 점검해줘. 느린 쿼리, 누락된 인덱스,
N+1 문제, RLS 정책 최적화 필요한 곳 찾아서 개선해줘.
```

## 5. UX/접근성 개선 (격주)
```
컴포넌트 접근성 감사해줘. aria-label 누락, 키보드 네비게이션,
다크모드 대비, 모바일 반응형 깨지는 곳 찾아서 수정해줘.
```

## 6. 새 기능 추가 시
```
[기능명] 구현해줘. 기존 코드 패턴 따르고, 에러 핸들링,
로딩 상태, 다크모드, 모바일 대응 포함해서 만들어줘.
```

## 7. 장애/버그 대응
```
[증상 설명]. 관련 코드 찾아서 원인 분석하고 수정해줘.
같은 패턴의 버그가 다른 곳에도 있으면 함께 수정해줘.
```

## 8. 배포 전 체크 (배포 전마다)
```
배포 전 점검해줘. build 에러, TypeScript 에러,
lint 경고, 콘솔 로그 남아있는 거 확인하고 정리해줘.
```

## 9. 종합 점검 (월 1회)
```
docs/TODO.md 업데이트해줘. 완료된 항목 체크하고,
코드베이스 전체 감사해서 새로운 TODO 항목 추가해줘.
```

---

**팁:** 매번 세션 시작할 때 `이어서 해줘`도 좋지만, 위 프롬프트 중 하나를 골라서 목적을 명확히 지시하면 더 집중된 결과를 얻을 수 있다. 주기별로 돌려가면서 사용하면 서비스 품질이 꾸준히 올라간다.
