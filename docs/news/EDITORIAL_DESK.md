# 기사 데스킹과 교정 학습

사용자가 제공한 2026-09-14 AI News Writer Skill을 작성 기준으로 사용한다.
Accuracy > Clarity > Speed > Style. 모르는 것은 쓰지 않고, 보도를 공식 사실로 바꾸지 않는다.

## 사용

관리자 또는 편집자가 `/admin/news-review/desk`에서 원문, 사실 목록, AI 초안을 함께 확인한다.
제목/본문을 수정하고 선택적으로 이유를 적은 뒤 `수정 저장·학습`을 누른다.
수정 전후와 편집자 메모는 트랜잭션으로 먼저 보존한다. 변경 구절과 이유의 분석은 그 뒤 수행한다.
학습 이력의 AI 설명을 수정하거나 해당 항목을 비활성화할 수 있다.
`검수 완료`는 연습 대기함에서 작업을 마치는 기능이며 공개 발행이 아니다.
기존 뉴스의 발행 검수는 `/admin/news-review`에서 계속 수행한다.

자동 작성은 매시간 1건, 기본 대기 6건·한국 시간 하루 12건까지다.
15분 주기 cron은 예정 시각과 대기/일일 한도를 확인하며 한 번에 생성 1건과 학습 재시도 1건만 처리한다.
관리자는 자동 작성을 멈추고 한도를 조정하거나 수동으로 1건을 추가할 수 있다.
실패한 작성도 하루 생성 한도에 포함한다. 정지 전 시작한 작업은 완료될 수 있다.
최근 기사 80건, 교정 160건, 수정 회차 120건을 화면에 제공하며 DB 기록은 유지한다.

## 작성 절차

1. 기존 수집기의 실제 원문이 있는 최근 72시간 축구 뉴스 중 아직 연습하지 않은 소재를 고른다.
2. 공식 구단/리그/기관과 신뢰 매체의 확인된 도메인만 소재로 사용한다. 커뮤니티는 독립 사실 출처로 사용하지 않는다.
3. 원문·출처명·URL·보도 시각·수집 시각·출처 등급을 보존한다. 작성자/수정 시각/독립성을 알 수 없으면 미확인으로 표시한다.
4. 같은 인물/사건의 앞선 원문을 최대 3건까지 배경으로 붙인다. 자체 AI 기사는 사실 근거로 사용하지 않는다.
5. 집필 전 별도 모델 호출로 사실/보도/주장/의견과 근거 구절을 추출한다. 근거 구절이 실제 원문에 있는지 코드로 검사한다.
6. 확인한 사실 목록과 활성 교정을 입력해 한국어 기사를 독립적으로 작성한다.
7. 기존 원문 대조 검사관의 결과를 초안에 보존하고 확인할 항목을 편집자에게 제시한다.

출처가 여러 개여도 같은 최초 보도를 재인용하면 독립 검증이 아니다. 배경 자료도 현재 사건의 추가 확인으로 세지 않는다.
현재 소재의 핵심 사실이 없거나 원문 구절을 대조할 수 없거나 핵심 충돌이 있으면 정상 기사 생성을 보류한다.
별도 웹 검색을 수행했다고 주장하지 않는다. 단일 신뢰 매체의 보도는 MEDIUM으로 유지한다.
공식 인터뷰의 주장과 평가는 그 주체에게 귀속하며 공식 사이트라는 이유로 내용 자체를 사실로 바꾸지 않는다.

2026-09-15 공홈 인터뷰 검수 보강: 핵심 발언의 이유·조건·경기 상황을 취재 노트부터 함께 추출한다.
기사의 핵심 평가를 이해하는 데 필요한 설명을 누락하거나 질문자/답변자/제3자의 전언을 섞으면 검수에서 지적한다.
경기 전후와 발언/게시 시점, 판정에 대한 의견과 공식 오심 인정도 구분한다.
문맥을 보존한 간접 인용과 필요한 답변만 고른 요약은 허용하며, 원문에 없는 질문·이유를 요구하지 않는다.
이 기준은 작성·검수 정책의 개선이다. 편집자가 저장한 수정 사례나 학습 완료 건수로 계산하지 않는다.

공유 작성 원칙은 `scripts/vps-news-scanner/writer-policy.mjs`에 있다.
날짜/금액/인물/계약·이적 단계/기술 발표와 출시/인용 맥락/후속 기사/짧은 기사/자체 검수 원칙을 포함한다.

## 학습의 범위

모델 가중치를 재훈련하지 않는다. 지속 저장된 교정 사례와 이유를 다음 작성의 입력에 제공한다.
활성 교정 중 최근 최대 12건을 연습 작성과 실운영 Hermes 작성에 함께 사용한다.
새 초안에는 적용한 학습 ID를 보관한다. 비활성화는 이후 생성부터 적용되며 이미 생성한 글을 다시 쓰지 않는다.
사실/숫자/시각/인명 정정은 사례로 남기고 구체적인 값은 다음 기사에 전달하지 않는다.
대신 해당 원문을 다시 대조하라는 확인 원칙을 전달한다. 다른 선수로의 정정을 이름 별칭 사전에 넣지 않는다.
표현/출처 귀속/확신 수준/인용/맥락/구조의 교정은 수정 구절과 이유도 참고한다.
AI가 뽑은 구절은 수정 전후에 각각 실재해야 저장할 수 있다.

## 운영과 복구

- `news_desk_items`: 비공개 원문 스냅샷·사실 목록·최초/현재 초안·검수 결과.
- `news_desk_revisions`: 수정 버전, 작성자, 전후 기사, 수정 이유, 학습 상태.
- `news_desk_lessons`: 변경 구절, 분류, 설명, 반복 방지 원칙, 활성 여부.
- `news_desk_settings`: 자동 생성 설정, 일일 한도, 동시 실행 임대.
- `claim_news_desk_item`: 모델 호출 전에 소스/쿼터를 원자적으로 예약. 생성 임대는 10분.
- `save_news_desk_edit`: 버전 충돌은 409. 다른 편집자의 변경을 덮어쓰지 않는다.
- 학습 임대는 3분, 자동 재시도 최대 3회. 모델 오류 시에도 수정본은 남는다.
- 모든 테이블/RPC는 service_role만 접근한다. 관리자 API가 Clerk의 admin/editor 역할을 확인한다.
- 비용이 드는 신규 생성과 운영 한도 변경은 admin만 허용한다. API rate limit과 DB 원자적 한도를 함께 적용한다.
- 새 모델 호출은 공통 파라미터 함수와 사용량 기록 래퍼를 사용한다.

배포: 정확한 추가 마이그레이션 적용과 타입 생성 → 앱 배포 → VPS scanner/match-news/writer-policy 3개 모듈을 잠금 아래 교체한다.
중지/롤백 시 설정의 enabled=false로 새 생성을 중지하고 앱/VPS 코드를 이전 배포로 되돌린다. 수정 기록은 삭제하지 않는다.

UI는 기존 wc-paper/card/ink/mute/line/burgundy 토큰과 공용 Button/Input/Textarea를 사용한다.
작업 목록과 편집 영역은 큰 화면에서 두 열, 작은 화면에서 한 열로 배치한다.
