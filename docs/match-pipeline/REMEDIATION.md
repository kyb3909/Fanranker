# 경기 파이프라인 수정 — 2026-09-05

로컬 코드 수정 기록이다. 커밋·push·배포·운영 DB 변경·VPS 변경은 하지 않았다.
기존 타로·굿즈 및 다른 작업의 변경 사항은 보존했다.

## 후속 수정: 베트맨 미판매 경기 연결

인기팀 LFA 전용 경기에 독립 UUID를 부여해 기존 매치센터·라인업·스탯·불판·MOM 경로에
연결했다. 베트맨 마켓은 생성하지 않는다. 상세 범위·테스트·마이그레이션 적용 순서는
[LFA_ONLY_FIXTURES.md](./LFA_ONLY_FIXTURES.md)를 참고한다. 운영 DB 적용·배포는 미실시다.

## 후속 수정: 같은 슬롯 + 한 팀 확정 매핑

운영자 규칙에 따라 앞서 도입한 **양 팀 일치 필수** 조건을 변경했다.

- 베트맨 대회 코드 ↔ LFA 대회 ID를 먼저 제한하고, 같은 날짜·킥오프 분만 후보로 삼는다.
- 홈 또는 원정 한 팀의 전체 이름/사전 별칭이 확실하고 상대 팀의 확인된 충돌이 없으면 연결한다. 미등록 하부리그 팀명은 그 자체로 거절 사유가 아니다.
- City/United 같은 구단 구분을 보존한다. 맨시티–리버풀을 맨유–리버풀에 붙이지 않는다. 공통 토큰의 느슨한 겹침은 확정 근거로 사용하지 않는다.
- 홈/원정 반전·확인된 상대 팀 불일치·다중 후보는 보류한다. 시간이 바뀐 경기를 리그 전체에서 찾아 임의 연결하던 상세 해석 폴백은 제거했다.
- 일정 병합과 매치 상세 해석은 `matchLfaCounterpart` 하나를 공유한다. 결과는 matched / missing / ambiguous / conflict로 구분하고 확정 근거(home / away / both)를 반환한다.
- 앞 경기에서 소비한 후보를 제외해 다중 후보가 단일 후보로 바뀌지 않도록 일정 병합에서도 슬롯 전체를 대조한다.

직접 관련 테스트 45개, 전체 199개 파일 / 2,148개 테스트 통과. 타입 검사·수정 파일 ESLint·diff 공백 검사도 통과했다.
전체 시험 첫 실행에서 시간 초과와 후속 단언 실패가 발생해 `--maxWorkers=4`로 재실행했으며, 테스트의 시간 제한이나 판정 조건을 완화하지 않고 전부 통과했다.
기존에 저장된 잘못된 매핑을 삭제·재작성한 것은 아니며, 운영 배포·VPS 변경도 하지 않았다.
시간 변경·미등록 별칭 등으로 보류된 경기는 사전/일정 확인 후 재판정해야 한다. 이 규칙만으로 매핑의 무오류를 보장하지 않는다.

## 아직 별도 작업이 필요한 것

- **인기 팀의 LFA 전용 경기:** 독립 ID와 매치센터·라인업·스탯·불판·MOM 연결은 로컬 구현했다. 신규 테이블의 운영 적용과 실제 경기 체인 검증은 남았다. Soccerway 기사 리포트 및 화이트리스트 밖 친선전 확대는 이번 범위에서 제외했다.
- **팀 식별:** 자동 매핑은 위 후속 수정의 전체 이름/사전 별칭·한 팀 확정 규칙을 사용한다. 관제의 기존 `linkTeamsAgree`에는 느슨한 토큰 비교가 남아 있어 별도 정렬이 필요하다. 잘못되거나 모호한 사전 항목 자체는 안정적인 팀 ID/검증된 별칭으로 더 강화해야 한다.
- **동시성의 남은 한계:** 불판은 동일한 형제 ID 집합에서 대표 ID를 공유한다. 동시 실행 중 새 형제가 추가되는 경우까지 보장하려면 경기 단위 DB 제약/잠금이 필요하다. 캐시의 인스턴스 간 동시 쓰기도 DB 차원의 버전 조건부 갱신으로 보강할 수 있다.
- **기존 저장분 복구:** 이미 잘못 연결된 상세·예상 라인업·중복 글·scheduled 리셋 행을 일괄 수정하거나 삭제하지 않았다. 정확한 대상 확인 후 별도 처리해야 한다.
- **지연 상한:** 외부 피드 지연, 캐시 SWR, cron/방문 빈도가 겹치므로 120초를 종단 화면 지연 보장으로 해석하면 안 된다. 실제 배포에서 계측해야 한다.

## 운영 적용 순서 — 아직 실행하지 않음

1. 변경 파일을 검토한다. LFA 전용 경기 변경을 함께 배포할 때는 `LFA_ONLY_FIXTURES.md`의 순서대로 `20260905_lfa_fixtures.sql`을 먼저 검증·적용한다. 그 뒤 사이트를 배포하고 새 캐시 키가 적용되는지 확인한다.
2. **실제 VPS `/opt/betman/sync.sh`를 읽어 현재 운영본과 대조한 후** 일정 payload의 status 제거를 반영한다. 저장소의 두 sync.sh는 복사본이고 자동 반영되지 않는다. 운영본을 확인 없이 통째로 덮어쓰지 않는다.
3. 다음 :10 일정 동기화 직전·직후와 :15~:17 결과 수집 뒤를 읽기 전용으로 비교한다. completed/in_progress/cancelled가 scheduled로 돌아가지 않는지 확인한다.
4. 이미 손상된 행은 결과 수집의 정상 복구를 먼저 관찰하고, 남은 행만 별도 검토한다. LFA 점수로 정산 결과를 추측해 채우지 않는다.
5. 새벽 04~06시 경기를 기준으로 불판 생성·LFA FT·홈 밴드·리포트 실패 사유를 확인한다. Discord 웹훅 설정과 경보 수신도 확인한다.

초기 보완에는 DB 마이그레이션이 없었으나, 후속 LFA 전용 경기 구현에서 `20260905_lfa_fixtures.sql`을 추가했다. 2026-09-06 운영 적용과 권한 검증을 마쳤으며 `DB_APPLIED_20260906.md`에 기록했다. 기존 posts의 match_game_id unique 인덱스가 운영 DB에도 실제 존재하는지는 별도 배포 점검 항목이다.
