# 베트맨–LFA 매핑 자동 복구

## 변경한 동작

- 기존의 같은 리그·킥오프 분 매칭을 먼저 사용한다. 실패하면 같은 리그에서 킥오프 차이 30분 이내의 후보를 재검사한다. 복구 후보는 홈·원정 **두 팀 모두** 전체 이름/확인된 별칭/팀 ID로 일치해야 한다. 팀 ID가 모순되거나 후보가 여러 개면 연결하지 않는다.
- 일정 병합과 LFA 상세·라인업 해석이 같은 복구 판정기를 사용한다. 일정 병합에서는 서로 다른 베트맨 경기 두 개가 같은 LFA 후보를 주장하는 경우도 거절한다.
- 현재 매치데이의 저장된 LFA 일정도 후보에 포함한다. 피드 목록이 일시적으로 비어 있어도 나중에 발표된 베트맨 행과 연결할 수 있다. 새 피드가 있으면 저장된 일정 내용보다 우선한다.
- 이미 연결된 경기의 UUID/연결은 보존한다. 연결 저장은 `betman_game_id IS NULL` 조건부 UPDATE로 수행한다. 기존 PK/unique 제약을 사용하며 새 스키마는 없다.
- 사전 조회 오류는 캐시에 저장하지 않는다. 사전 캐시를 1시간에서 5분으로 줄여 사전 보충 후 다음 정기 조회에서 재매핑할 수 있게 한다.

## 연결 후 재개

- 기존 일정 조회 크론들이 재매핑을 반복한다. 별도의 알림 확인이나 수동 재개가 필요하지 않다.
- 실황 수집은 기존 lfa-live가 담당한다. lfa-warm은 오늘·어제 매치데이에서 킥오프 +4~24시간 경기를 확인하고, 미확정/없는 라인업을 먼저 수집한 뒤 필요한 상세를 수집한다.
- 완성된 저장 자료는 재구매하지 않는다. 내용이 빈 종료 상세는 복구 회차에서만 +24시간 안에 다시 수집할 수 있다. 기본 상세 캐시 정책은 유지한다.
- 회당 복구 시도는 최대 24경기, 작업 시작 제한은 90초다. 오래된 경기부터 처리하고, 이미 완료된 경기는 시도 상한을 쓰지 않는다. 실패/시간 부족은 다음 정기 회차가 다시 확인한다.
- 불판·MOTM·리포트는 기존 생성 조건/시간 창/예산으로 계속 처리한다. 종료된 경기에 새 라이브 불판을 소급 생성하거나, 리포트 작성 예산을 초기화하지 않는다.
- MOTM은 연결 전 베트맨 키와 연결된 경기 ID의 기존 투표까지 확인해 재사용한다. 기존 투표 조회 실패 때 새 투표를 생성하지 않는다.

## 검증 및 적용 범위

- 회귀 테스트: 15분 시간 차이, 늦은 베트맨 발표, 피드 중단 시 저장 일정 사용, 중복 후보/역방향/다른 리그/다음 날/팀 ID 충돌 거절, 확정 연결 보존, 상세 수집·저장 재개, 단계별 재사용, 빈 종료 캐시 복구, 시간/건수 예산, 기존 투표 재사용.
- 운영 DB 변경/마이그레이션/배포는 수행하지 않았다. 자동 복구는 배포 후 크론에서 실행된다.
- 자동 복구는 확인 가능한 후보 및 기존 작업 시간 창 안에서 수행한다. 30분 넘는 시간 변경이나 모호한 대진을 추측해서 연결하지 않으며, 24시간을 넘긴 신규 자료 복구 큐는 이번 범위에 추가하지 않았다.
- 정산 결과·예측 마켓·전반전 제외 정책은 수정하지 않았다.
