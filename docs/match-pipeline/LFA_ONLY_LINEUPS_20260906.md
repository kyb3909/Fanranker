# 라인업·매치센터 LFA 단일 공급자 전환

## 범위와 상태

2026-09-06 사용자 지시: Soccerway는 유료 LFA 구매 이전의 차선책이며 라인업·매치센터의 공급자로 쓰지 않는다.
2026-09-06 푸시 전 검증 기록이다. 배포 성공과 실제 경기 종료 후 리포트 생성은 별도로 확인해야 한다.

## 변경

- 베트맨 경기와 LFA 추가 경기 모두 LFA match ID로 라인업을 조회한다. 기존 대회·시각·양 팀 검증을 유지한다.
- 라인업 취득과 LFA 이벤트 이름 처리에서 Soccerway 호출을 제거했다. `lineup-types`와 `lineup-store`로 공급자 중립 경계를 분리했다.
- `projected=false`인 명단만 영구 저장한다. 선발은 양쪽 11명을 확인한다. 예상 또는 일시 오류가 확정 명단을 덮지 않는다.
- 출처가 없는 과거 명단은 저장된 LFA 상세의 match ID와 event ID가 일치할 때만 재사용한다. 기존 DB 행을 삭제하지 않는다.
- 예상 ready도 60초 재조회하며 명시적 확정 후에만 멈춘다. 숨겨진 탭은 쉬고 복귀 시 재시도한다. 경기 이동/서버 갱신을 반영한다.
- 배지는 실제 클라이언트 명단과 함께 갱신한다. API는 no-store이며 서버 LFA 캐시는 120초다. 자동 구매 범위는 킥오프 −150분~+48시간이다.
- 불판이 이미 있어도 명단 갱신을 생략하지 않는다. MoTM 후보도 같은 LFA 명단 경로를 사용한다.
- 새 라인업과 타임라인은 LFA 선수 ID로 교체·득점·퇴장을 연결한다. ID가 충돌하면 이름 추정으로 다른 선수에게 붙이지 않는다.
- 매치센터 표시 스탯의 Soccerway 폴백만 제거한다. 종료 리포트는 Soccerway 원문으로 계속 생성하며 기존 저장 리포트도 보존한다.

## 구분해야 할 잔여 범위

사용자 재확인: **라인업·실시간 점수·스탯은 LFA, 경기 종료 후 리포트는 Soccerway 원문**이다. 리포트 배치 중단은 잘못된 범위 해석으로 취소했다. `match-reports` 크론·사가 리뷰·종료 페이지의 리포트 생성 트리거를 복구했다. 스탯으로 매치 리포트를 만드는 신규 경로는 추가하지 않는다. 기존 팀 사전의 `soccerway_team_id`는 DB 식별자이며 그 필드를 읽는 것 자체는 외부 호출이 아니다.

LFA 발표 지연/장애, 실시간 데이터 도착, 종료 후 MoTM까지의 실제 운영 종단 검증은 단위 테스트만으로 보장하지 않는다. 15분 LFA 예열 및 10분 불판 크론 주기는 변경하지 않았다.

## 검증

- 리포트 경로 복구 후 최종 전체 단위 테스트: 209개 파일 / 2,212개 통과 (04:46 KST 실행). TypeScript `tsc --noEmit` 및 수정 코드 ESLint 통과.
- 디자인 토큰 자동 검사는 기존 스크립트의 Unix `find app components -name`이 Windows `find.exe`로 실행되어 검사 시작에 실패했다. 권한 승격 후에도 같은 플랫폼 문제였다. 이 검사를 통과했다고 간주하지 않으며 공용 스크립트/사용자 토큰 예산은 변경하지 않았다.
- 회귀: 예상→확정, 서버 props 교체, 경기 이동, 실패 재시도, 확정 유지, 공급자 선택, 부분 선발 거절, 출처/ID 검증, API 캐시, 선수 ID 이벤트 연결, 기존 불판의 명단 갱신.
- 로컬 브라우저 `/dev/match-preview`: 확정 배지와 포메이션→선수 명단 전환 확인, 콘솔 오류 0건. 가상 데이터이므로 실경기 종단 증거는 아니다.
- 실경기 감시는 수정 전 운영 코드의 DB를 읽는 별도 기록이다. 04:19 KST 기준 로마–아탈란타와 비야레알–데포르티보 모두 확정 라인업·불판·라이브 스탯 저장을 확인했다. 이는 새 코드의 배포 증거가 아니다.
