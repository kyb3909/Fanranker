# 인터뷰·기자회견 뉴스와 배경 자료

2026-09-14 변경. 일반 뉴스 피드의 수집·작성·검수를 대상으로 한다.

## 수집

VPS의 기존 15분 cron과 잠금(run.sh)을 사용한다. 배포 단위는 이제
scripts/vps-news-scanner/news-scanner.mjs와 match-news.mjs 두 파일이다.

인증된 GET /api/news/briefing에서 전후 48시간 축구 경기 일정과 팀명 별칭을 읽는다.
경기 팀의 공식 뉴스 목록은 회당 최대 4개 구단을 순환하고 BBC·Sky Sports·Guardian
축구 RSS도 함께 확인한다. 회당 직접 발견 후보는 10건, 소스당 3건이다.
Reddit 수집과 합쳐 기존 LLM 호출 예산(기본 30)을 사용하고 작성은 실행 시작 후
11분에서 신규 후보 처리를 멈춘다. 이후 기존 화력 수집의 14분 예산을 적용한다.

공식 목록의 링크, RSS, JSON-LD, JSON 컴포넌트 props를 읽는다. 원문은 HTML 문단과
공개 rich text hydration 데이터를 JSON으로 해석한다. 페이지 스크립트는 실행하지 않는다.
질문·답변을 문단 단위로 보존하고 22,000자 한도에서 문단 중간을 자르지 않는다.
직접 발견한 기사는 실제 게시 시각이 확인되고 48시간 안에 있을 때만 작성한다.
원문·시각을 확인하지 못한 후보는 자동 통과시키지 않는다.

수집 실패는 seen으로 표시하지 않고 별도 seen.json.retries.json에 기록한다.
후보별 최대 4회, 30/60/120/240분 간격으로 재시도하며 한도를 넘기면 운영 로그에
원문/작성 확인 필요로 남긴다. 재처리가 필요하면 해당 후보만 확인 후 재시도 기록을
제거한다. seen 파일 전체를 지우면 기존 기사까지 재수집되므로 하지 않는다.

## 작성과 증거

POST /api/news/briefing은 최근 30일 발행 기사 중 저장된 원문을 검색한다.
우리 AI 본문을 새로운 사실의 근거로 사용하지 않는다. 같은 원문 URL, 게시 시각이
없는 자료, 새 기사보다 나중에 수집됐거나 게시된 자료, 관련 어휘가 부족한 자료는 제외한다.
원제목의 인물·구단 이름도 원문에 있어야 한다. 복수 단어 이름은 전체 이름을 대조하고
악센트 차이는 정규화하므로 흔한 인터뷰 표현이나 다른 동명의 선수만으로 연결하지 않는다.
최대 3개 배경 자료를 질문/앞 문단과 함께 전달한다. 검색 결과라는 이유만으로 사용하지
않으며 작성기가 현재 사건과의 관련성을 다시 판단한다.

작성 순서는 상황과 질문, 실제 발언, 필요한 이전 경위다. 배경은 출처와 당시 시각을
밝혀 1~3문장으로 설명한다. 발언자가 설명하지 않은 심리나 동기를 단정하지 않는다.
구단 홈페이지의 인터뷰와 구단 공식 성명도 구분한다.

agent-draft는 원제목, subreddit, 전체 원문과 raw.evidence(version=1)를 함께 저장한다.
evidence에는 원문 URL·게시 시각·수집 시각·이전 원문 발췌·수집에 사용한 경기 ID가 있다.
match_ids는 수집 대상 연결 힌트이며 기사 속 경기의 정체를 증명하는 자료가 아니다.
원문과 배경은 작성기·날짜/이름 가드·품질 검사기에 같이 전달한다.

## 발행

자동발행 opt-in, 회당 발행 2건, 표기·이미지·원문 검증은 유지한다.
검사 API 장애·불완전 응답은 내용 불합격과 구분해 quality_retry로 기록한다.
최대 4회 재검사하며, 기존의 검사 장애 사유로만 막힌 살아있는 초안도 같은 경로로 회복한다.
실제 내용 결함이나 사람의 반려는 이 예외에 포함하지 않는다.

원문 URL이 같으면 기존처럼 중복이다. 제목이 비슷하지만 URL이 다르면 기존 발행
본문과 새 원문을 대조한다. 새 발언·공식 해명·제재 등 추가 정보가 원문 구절로
뒷받침되어야 후속 기사로 진행한다. 대조 실패는 재시도 대상으로 남긴다.

별도 interview_cards 수집기도 Hermes 필드와 구형 필드를 함께 읽는다.
시즌 사가가 있는 아스널·리버풀·첼시 범위 및 사람의 카드 승인 절차는 유지한다.

## 배포와 확인

1. 새 앱 API와 검사기부터 배포한다.
2. VPS에서 기존 파일의 해시를 확인하고 백업한 뒤 두 mjs 파일을 함께 설치한다.
   node --check와 import 검사를 수행하고 기존 run.sh 및 cron 잠금을 사용한다.
3. cron.log의 경기 전후 수집 진단, 작성 근거의 원문/배경 건수, 재시도 로그를 확인한다.
4. news_reservoir.raw.evidence와 news_candidate_events의 quality_check_unavailable,
   quality_retry_exhausted, followup_check_unavailable 및 post_published를 확인한다.

차단·JS 변경 등으로 일부 구단 원문을 읽지 못할 수 있다. 소스별 후보 수/오류와
실제 초안·발행 건수를 함께 봐야 하며, HTTP 200만으로 정상 수집이라고 판단하지 않는다.
