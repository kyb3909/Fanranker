# 관제 센터 통합 구현 계획 (2026-09-08)

감사·토론 문서의 결정안을 실제 코드로 옮긴 기록이다. **설계 문서와 현재 코드가 다르면 코드를 기준으로 삼았고, 차이는 §5에 적었다.**

## 1. 통합 방향

`/admin` 이 유일한 관리자 진입점이 된다. `/admin2` 는 별개 홈으로 남기지 않고 대응 화면으로 넘긴다.

| 현재 | 통합 후 |
| --- | --- |
| `/admin` 관제실 (전황판 13행 + 참여 + 뉴스 검수 + 표기·스쿼드) | `/admin` 관제 센터 — 관측 상태 → 지금 할 일 → 업무별 현황 → 기다리는 일 → 최근 결과. 기존 인라인 검수(뉴스·표기·스쿼드)는 그대로 아래에 유지 |
| `/admin2` 작업대 (파이프라인 4 + 큐 8 + 돈 2) | `/admin` 에 흡수. 파이프라인 판정(`lib/admin/pipeline-status`)과 돈 정합성 조회를 관제 센터 API 가 그대로 사용 |
| `/admin2/news`, `/admin2/agg`, `/admin2/reports`, `/admin2/saga` | 각각 `/admin/news-review`, `/admin/agg-review`, `/admin/content/reports`, `/admin/news-review` 로 **쿼리스트링 보존** 이동 |

`/admin2` 는 editor 도 들어올 수 있는 유일한 입구였다(`requireStaff`). `/admin` 레이아웃은 `requireAdmin` 이라 editor 가 막힌다. 통합하면서 **editor 를 잃지 않도록** `/admin` 레이아웃을 staff 허용으로 바꾸고, 화면·API 단에서 admin 전용 항목을 걸러낸다. 서버 권한 검사는 각 API 가 그대로 수행한다(메뉴 숨김과 별개).

## 2. 첫 화면 구성과 데이터 출처

| 영역 | 내용 | 데이터 |
| --- | --- | --- |
| 관측 상태 | 확인한 범위 / 마지막 성공 / 확인 불가 / 미연결 / 오래됨 | 소스마다 조회 성공 여부를 개별 기록. `count ?? 0` 을 쓰지 않는다 |
| 지금 할 일 | 긴급도·피해·기한·최장 대기 순. 건수는 마지막 동점 처리에만 | content_reports, pending_refunds, metaverse_user_reports, betman_games(결과 대기), news/agg/saga 검수, invariant_findings, cron 실패 |
| 업무별 현황 | 영역별 미해결·최고령·상태·바로가기. 정상 0건은 접되 확인 성공은 남김 | 위와 동일 + 정상 영역 |
| 기다리는 일 | 자동 재시도 / 결과 확인 중 / 사람 대기, 다음 확인 시각, 기한 초과면 위로 복귀 | match_report_attempts(held), betman 결과 대기, 정산 크론 |
| 최근 처리 결과 | 판정 / 실제 적용 / 부분 성공 / 확인 중 | admin_audit_log(있으면), cron_run_log, match_reports |

## 5. 문서와 코드의 차이

- 토론 문서 6개(`README` · `ux-review` · `admin-review` · `mod-review` · `pm-decision` · `moderator-brief`)는 모두 저장소에 있다.
- 토론 문서는 `/admin2` 를 "검토용 병렬 버전"으로 기술한다. 코드도 같다(`app/admin2/layout.tsx` 의 "새 버전" 배지와 `기존 관리자 →` 링크). 이번 작업으로 그 병렬 상태를 끝낸다.
- `moderator` 역할은 관리자 패널 권한이 **아니다**(`lib/admin/roles.ts`). 문서 주장과 코드가 일치한다. 이번 작업에서 moderator 에게 어떤 접근권도 추가하지 않는다.

## B. 실제 연결한 업무와 미연결

관측 17곳 중 **15곳 조회 성공, 2곳 미연결**(실측, 324ms).

연결됨: 신고 · 검토 중 신고 · 메타버스 신고 · 뉴스 오류 제보 · 환불 대기 · 환불 실패 ·
판매자 미지급 · 정산 누락 의심 · 경기 결과 대기 · 미정산 슬립 · 뉴스 검수 · 이름 막힘 ·
사가 검수 · 커뮤글 검수 · 선수단 사전 · 스티커 · 불변식 경보 · 예약 작업 실패 · 크롤러 실패.

미연결(0건으로 세지 않음): **문의**(접수 경로 없음) · **경품 전달**(전달·수령 기록 없음).

읽기는 되지만 처리 화면이 없는 업무는 `actionWired: false` 로 표시한다 — **판매자 미지급**이
그렇다. 종전에는 쓰기만 하고 읽는 코드가 없어 화면 어디에도 안 나왔다.

## C. 우선순위 규칙

기한 초과 → 긴급도 → 최장 대기 → 건수. 건수 가산점 상한(900)이 티어 간격(최소 4,000)보다
작아 **건수가 긴급도를 뒤집지 못한다.** 기한 초과 묶음 안에서도 긴급도로 다시 정렬한다 —
실데이터에서 24시간 넘긴 일반 신고가 미지급 환불보다 위로 오는 것을 확인하고 고쳤다.

## D. 실행 안전성에서 바꾼 것

| 경로 | 종전 | 지금 |
| --- | --- | --- |
| 신고 인정 | `id` 조건만으로 update → 재실행 시 카드 중복 발급 | 현재 상태를 WHERE 에 넣어 한 번만 전이. 두 번째 요청은 409 + 제재 미실행 |
| 신고 인정 | 카드 insert 실패가 200 으로 감춰짐 | `verdict: partial` 로 드러냄 |
| 신고 인정 | 정지 insert 오류 미확인인데 `suspended: true` | 오류를 확인하고 "정지가 걸리지 않았다"고 보고 |
| 신고 인정 | 실행 후 토스트로만 효과 통보 | 실행 전 효과 미리보기(카드 종류·누적·정지 여부·같은 콘텐츠의 다른 신고 수). 누적 정지만 추가 확인 |
| 신고 대상 | `post` 아니면 무조건 `comments` 조회 (ticker 오작동) | 작성자를 특정할 수 있는 대상만 카드 발급 |
| 옐로 만료 | 로컬 타임존 자정 기준 | UTC 기준 |
| 환불 재시도 | 상태 확인 → RPC → 갱신 사이 잠금 없음 | attempts 낙관적 잠금. 동시 요청 중 하나만 RPC 실행 |
| 환불 큐 종료 | 클라이언트가 항상 `paidConfirmed: true` 전송, 실질 게이트는 브라우저 프롬프트 | 서버가 사유 4자 이상을 요구. 상태 조건부 종료로 중복 방지 |
| 메타버스 조치 | 일반 신고와 같은 "조치 완료" | 상태 기록일 뿐 제재가 아님을 화면과 결과 문구에 명시 |

**주장하지 않는 것**: 지급 경로 전체의 안전은 확보되지 않았다. 환불 RPC 성공 뒤 상태 갱신
전에 프로세스가 죽으면 다음 재시도가 다시 지급할 수 있다. 원장 대사는 후속 작업이다.
새 빠른 실행·일괄 실행·자동 실행은 열지 않았다.

## E. 권한

`/admin` 레이아웃이 `requireStaff()` + 경로 허용목록으로 바뀌었다. **접근이 넓어지지 않는다** —
editor 는 통합 전 `/admin2` 에서 실제로 도달하던 화면(홈·뉴스 검수·커뮤글 검수)만 열 수 있고
나머지는 거부다. 경로를 모르면(미들웨어 헤더 유실) 거부한다. 각 API 는 자기 권한을 따로 검사한다.

현재 DB 실측: `admin` 2명, `user` 529명, **`editor` 0명, `moderator` 0명.** `moderator` 는
관리자 패널 역할이 아니며 이번 작업에서 어떤 접근권도 부여하지 않았다.

## G. 남은 정책 결정과 후속

1. **신고 SLA** — 화면의 1시간/24시간은 코드 관행이고 운영자가 승인한 값이 아니다. 관제 센터의
   기한 계산이 이 값을 쓴다.
2. **같은 위반의 여러 신고** — 지금은 각 신고마다 카드가 나간다. 미리보기가 "다른 신고 N건"을
   알리기만 하고 정책은 바꾸지 않았다. 사건 경계·처분 유일성은 운영 책임자가 정해야 한다.
3. **판매자 미지급 처리 화면** — 숫자는 보이지만 지급·기록 경로가 없다.
4. **문의 접수·답변 배선**, **경품 전달 기록**.
5. **환불 지급 대사** — 원장 확인 후 자동 종료. 그 전에는 자동 재지급을 열지 않는다.
6. `admin_audit_logs` 에 `resolveNote` 는 남지만 `pending_refunds` 행에는 없다. 큐에서 바로
   읽으려면 컬럼 추가가 필요하다.
