# Discord 뉴스봇 서버 설계 — 팀 뉴스 · 속보 · 데일리 다이제스트

> 작성: 2026-07-19. FEATURES.md F13의 상세 설계.
> 목표: 사이트를 닫은 유저에게 도달하는 무료 재소환 채널. 디스코드 서버 = **공지형 메일링**(잡담 커뮤니티 아님 — 게시판 자기잠식 금지).

## 1. 한 줄 요약

이미 돌아가는 엔진 3개(티커 크롤러 · 뉴스 검수 발행 · 23:00 볼 리셋 크론)에 **웹훅 발송만 얹는다.**
신규 인프라 0, LLM 추가 비용 0, 개발 2.5~3일. 콘텐츠는 3층 구조:

| 층 | 무엇 | 주기 | 소스 (이미 있음) | 링크 대상 |
|---|---|---|---|---|
| **속보 단신** | 팀/리그 채널에 헤드라인 1줄 | 준실시간 (10~15분 폴링) | `news_ticker_items` — Vultr 크롤러가 10분마다 `headline_kr`·`summary_kr`·`importance` 생성 완료 | 원문 + 커뮤니티 링크 병기 |
| **검수 기사** | 발행된 뉴스 전문 티저 | 발행 즉시 | `news_reservoir` → `/api/admin/news-review` publish → 공놀이봇 게시글 | **gongnori.fan/post/{id}** (사이트 회귀) |
| **데일리 다이제스트** | 볼 충전 + 오늘의 경기 + 인기 뉴스 TOP 3 | 매일 23:00 KST 1회 | 볼 리셋 크론(23:00) + `GET /api/betman/games`(슬레이트도 23:00 flip — 타이밍 일치) + 공놀이봇 글 24h 조회수 상위 | **/prediction** (UTM 부착) |

"리포트식이냐 속보식이냐"의 답: **둘 다, 역할이 다르다.** 속보 = 서버가 살아있어 보이는 이유(체류 신호), 다이제스트 = 매일 돌아오게 하는 리듬(재소환), 검수 기사 = 품질 + 사이트 회귀. 셋 중 하나만 있으면 각각 시끄럽거나, 심심하거나, 뜸하다.

## 2. 기존 엔진 → 발송 지점 매핑 (코드 근거)

### 2-1. 속보 단신 — `news_ticker_items` 폴링
- 스키마가 이미 방송용이다 (`prod_schema.sql:5819-5839`): `headline_kr`(한국어 헤드라인, NOT NULL), `summary_kr`, `importance`(smallint, 기본 3), `ticker_tag`(기본 'breaking'), `source_id`, `external_url`, `thumbnail_url`, `posted_at`. 48시간 후 자동 삭제(`cleanup_old_ticker_items`).
- **팀 라우팅**: `source_id` → 채널 매핑 테이블(코드 상수)로 해결.
  - `reddit-gunners`→#아스날, `reddit-liverpoolfc`→#리버풀, `reddit-chelseafc`→#첼시
  - `reddit-coys`·`reddit-reddevils`·`reddit-mcfc`·`reddit-premierleague`·`reddit-soccer` 등 나머지 축구 → #해외축구-종합
  - `naver-kleague` → #국내축구 (활성 시)
- **발송 방식**: 신규 Vercel 크론 `/api/cron/discord-news-dispatch` (10~15분 간격).
  `SELECT ... WHERE id > 워터마크 AND importance >= 4 ORDER BY id` → 채널별 웹훅 발송 → 워터마크 갱신.
  - ⚠️ **Vultr 크롤러(`/opt/crawlers/runner.js`)는 건드리지 않는다** — git 밖 파일 수정 리스크(betman fetch-results 사례). 발송은 전부 Vercel 쪽 폴링으로.
  - 워터마크 + 일일 발송 카운터용 마이그레이션 1개: `discord_dispatch_state (channel_key pk, last_ticker_id bigint, sent_today int, sent_date date)`.
- **노이즈 가드**: `importance >= 4`만 (기본값 3 = 평범한 글은 제외), 채널당 일일 상한 12건, 초과분은 조용히 스킵. 티커는 **검수 없는 자동 파이프라인**이므로 문제 소스 발견 시 매핑 테이블에서 즉시 제외할 수 있게 상수 구조로.
- **링크 트레이드오프(정직하게)**: 티커 아이템은 사이트 글이 아니라 외부 원문이다. embed 제목 링크 = `external_url`(즉시성 가치), 하단에 "공놀이 축구 게시판에서 얘기하기 → /community/football?utm_source=discord" 병기. 사이트 회귀는 검수 기사·다이제스트 층이 담당.

### 2-2. 검수 기사 — publish 훅
- `app/api/admin/news-review/route.ts`의 publish 블록(`:96-121`)이 공놀이봇 글을 insert하고 `post.id`를 얻는 지점에 웹훅 호출 1개 추가.
- 라우팅: `news_reservoir.entities`/`tags`(jsonb, 팀·선수 엔티티 이미 추출됨)에서 3팀 매칭 → 해당 팀 채널, 실패 시 #해외축구-종합.
- 메시지: 제목 + 본문 첫 문장 + 썸네일(`image`) + **gongnori.fan/post/{id}?utm_source=discord** 링크. 전문 게재 금지(티저만) — 클릭해야 읽힌다.
- 실패 삼킴 원칙 유지 (`discord-notify.ts`와 동일 — 알림 실패가 발행을 깨면 안 됨).

### 2-3. 데일리 다이제스트 — 23:00 크론
- **별도 크론** `/api/cron/discord-daily-digest`, `"5 14 * * *"` (23:05 KST — 볼 리셋 `"0 14 * * *"` 직후, 리셋 크론에 인라인으로 붙이지 않음: 유저 수 늘면 리셋 배치가 길어지므로 분리).
- 조립 재료 (전부 기존):
  1. 볼 충전 안내 — 고정 카피 "🏐 오늘의 볼 10개 충전 완료"
  2. 새 슬레이트 경기 — `lib/betman/daily-round`의 `getDailyWindow()` 로직 재사용해 서비스 롤로 직접 조회 (self-fetch 대신 lib 함수). 종목별 상위 6~8경기: `리그 · 홈 vs 원정 · 킥오프 시각`
  3. 인기 뉴스 TOP 3 — `posts WHERE user_id='user_bot_soccer_kr' AND created_at > now()-24h ORDER BY view_count DESC LIMIT 3`
  4. CTA — "예측하러 가기 → gongnori.fan/prediction?utm_source=discord&utm_medium=digest"
- 멘션: `<@&데일리알림롤ID>` — **@everyone 절대 금지** (매일 @everyone = 서버 뮤트 = 채널 전체 사망).
- 이벤트 기간엔 섹션 5 추가: 팬덤 대항전 참여 현황(참여자·슬립 수 — 실시간 공개 허용 지표만. 팀 순위는 주 1회 정책 준수).

### 2-4. 발송 모듈 — `lib/discord/news-notify.ts` (신규, 기존 일반화)
- `lib/discord-notify.ts`의 embed 빌더·타임아웃·실패 삼킴을 재사용하되, **웹훅 URL을 파라미터로** 받는 범용 함수로. 기존 `notifyDiscordOps`는 손대지 않는다(운영 알림과 유저 알림은 채널·env 분리).
- env 추가 (`lib/env.ts` zod 갱신): `DISCORD_NEWS_WEBHOOK_ARSENAL / _LIVERPOOL / _CHELSEA / _FOOTBALL / _DIGEST` — 미설정 채널은 조용히 no-op (기존 원칙 동일).

## 3. 디스코드 서버 설계 (운영자가 직접 만드는 부분)

### 3-1. 채널 구조 — 시작은 작게 (팀 채널 3개만)

```
📌 안내
 ├ #환영-규칙        (Rules 채널 — 서버 성격: "뉴스·알림 서버입니다. 대화는 gongnori.fan에서")
 └ #공지             (운영 공지, 이벤트 안내)

⚽ 뉴스 (전부 공지 타입 채널)
 ├ #해외축구-종합     (전원 열람. 속보 단신 기본 채널)
 ├ #아스날 🔴        (@아스날 역할만 표시)
 ├ #리버풀 🔴        (@리버풀 역할만 표시)
 └ #첼시 🔵         (@첼시 역할만 표시)

🏐 공놀이
 ├ #오늘의-공놀이     (23:05 데일리 다이제스트)
 └ #대항전-현황       (이벤트 기간 한정 — 주간 순위 발표)

💬 (선택) #피드백     — 유일한 쓰기 가능 채널. 버그 제보·건의만.
                       고정 메시지로 "경기 얘기는 게시판에서" + 링크
```

- **팀 채널을 14개 소스만큼 만들지 않는다.** 이벤트 3팀만 열고, 나머지 축구 소스는 전부 #해외축구-종합으로. 채널이 많고 비어 보이는 것보다 적고 꽉 차 보이는 게 낫다. 유입 규모 보고 분화.
- 뉴스 채널은 **공지(Announcement) 타입**으로 생성 — 다른 서버가 "팔로우"할 수 있어서, 유튜버가 자기 서버에서 우리 채널을 팔로우하면 **그쪽 서버에 우리 뉴스가 자동 중계**된다(입점 협상이 "채널 팔로우 한 번"으로 줄어듦).

### 3-2. 역할 설계

| 역할 | 부여 방법 | 효과 |
|---|---|---|
| @아스날 / @리버풀 / @첼시 | 서버 온보딩 질문에서 선택 | 팀 채널 표시 + 팀 속보 멘션 대상 |
| @데일리알림 | 온보딩 질문 "매일 밤 경기+볼 알림 받기?" | 다이제스트 멘션 대상 (옵트인) |
| @운영 | 수동 | 관리 |

### 3-3. 서버 개설 체크리스트 (운영자 작업 — 코드 0줄, 약 반나절)

> 실제 진행할 때는 한 단계씩 같이 하면 됨. 여기선 전체 목록만.

1. 서버 생성 → **서버 설정 > 커뮤니티 활성화** (온보딩·공지채널·규칙 기능 해금)
2. 위 채널 구조 생성. **@everyone의 "메시지 보내기" 권한을 서버 단위로 OFF** (#피드백만 예외로 ON) — 이게 "공지형 서버"의 뼈대
3. 뉴스 채널들을 공지(Announcement) 타입으로 전환
4. **서버 설정 > 온보딩(Onboarding)** 구성: 질문① "어느 팀 팬이세요?" → 팀 역할 3개 + "그냥 축구 다" 옵션, 질문② "매일 밤 오늘의 경기·볼 충전 알림 받을래요?" → @데일리알림
5. 각 발송 채널마다 **채널 설정 > 연동 > 웹훅 생성** → URL 5개를 Vercel env에 등록
6. **AutoMod** 켜기(멘션 폭탄·스팸 링크 차단), 인증 레벨 '중간'(가입 5분 미만 계정 차단) — 공지형이라 이 정도면 관리 부담 거의 0
7. 무기한 초대 링크 생성 → 사이트 노출 (아래 3-4)
8. (이벤트 확정 시) 유튜버 3채널에 서버 링크 + "채널 팔로우" 안내 전달

### 3-4. 초대 링크 노출 지점 (사이트 쪽, 개발 포함)

우선순위 순:
1. **예측 완료 다이얼로그** (`PredictionSuccessDialog`) — 검증된 최대 레버 자리. "매일 밤 경기 알림 받기 → Discord"
2. 홈/예측 사이드바 배너 1장
3. 이벤트 랜딩(/worldcup 후속 이벤트 페이지) 참여 안내 섹션
4. 발행 뉴스 게시글 하단 (뉴스 소비자 = 뉴스 알림 수요자)

## 4. 비용

### 4-1. 금전 비용
| 항목 | 비용 |
|---|---|
| Discord 서버·웹훅·공지채널 | **0원** (전부 무료 기능. Nitro/부스트 불필요) |
| LLM | **0원 추가** — `headline_kr`·`summary_kr`은 크롤러가 이미 생성, 다이제스트는 템플릿 조립 |
| Vercel 크론 2개 추가 | 기존 Pro 플랜 내 (현재 9개 등록, 한도 여유) |
| DB | 워터마크 테이블 1개 (행 5개 수준) — 무시 가능 |

### 4-2. 개발 비용 (합 2.5~3일)
| Phase | 내용 | 공수 |
|---|---|---|
| 0 | 서버 개설·채널·온보딩·웹훅 (운영자, §3-3) | 0.5일 (코드 0) |
| 1 | `lib/discord/news-notify.ts` + env + **검수 기사 publish 훅** + **다이제스트 크론** | 1~1.5일 |
| 2 | **속보 크론** (`discord-news-dispatch` + 워터마크 마이그레이션 + 상한/매핑) | 1일 |
| 3 | 초대 링크 사이트 노출 (완료 다이얼로그·사이드바) | 0.5일 |

Phase 1까지만 해도 "검수 기사 + 매일 밤 다이제스트" 서버로 성립한다. 속보(Phase 2)는 채널 활력 부스터로 그다음.

### 4-3. 운영 비용
- 뉴스 검수는 **기존 업무 그대로** (발행하면 자동 전파 — 추가 작업 0).
- 서버 관리: AutoMod + 쓰기 차단 구조라 주당 ~10분 (가입자 확인, #피드백 답변).
- 유일한 지속 의무: **발행 케이던스**. 검수 발행이 하루 0건이면 검수 기사 채널이 침묵 — 속보 층이 이 공백을 메꾸는 보험이기도 하다.

## 5. 가드레일 (요약)

1. **@everyone 금지** — 다이제스트는 @데일리알림, 속보는 팀 역할 멘션만. 하루 멘션 총량 체감 2~3회 이하.
2. **잡담 채널 없음** — 대화 수요는 전부 게시판 링크로 회귀 (콘텐츠 전환 1% 과제와 정면 배치되는 자기잠식 방지).
3. **전문 게재 금지** — 티저+링크. 디스코드에서 다 읽히면 재소환이 아니라 대체재가 된다.
4. **속보 오보 리스크** — 티커는 무검수 자동이므로: importance≥4 필터 + 일일 상한 + 소스 매핑에서 즉시 제외 가능 구조 + embed footer에 "출처: r/xxx" 명시.
5. **저작권** — 헤드라인+요약 1줄+원문 링크 수준 유지 (본문 전재 금지 — 기존 자유게시판 애그리게이터 원칙과 동일).
6. **도박 프레임 금지** — CTA는 "예측/응원" 언어. 배당·수익 표현 없음 (COMMUNITY_STRATEGY 원칙).
7. **모든 사이트 링크에 UTM** (`utm_source=discord`, medium=channel) — 이벤트 P0 퍼널 계측과 연결. 4주 후 디스코드발 세션·가입 수로 확대/유지/철수 판단.

## 6. 성공 기준 (4주 시점 제안)

- 서버 가입: 이벤트 유입의 10%+ (이벤트 랜딩·완료 다이얼로그 노출 기준)
- @데일리알림 옵트인율: 가입자의 40%+ (온보딩 질문이라 높게 나와야 정상)
- 다이제스트 → 사이트 클릭: 발송 대비 8~15% (UTM 측정)
- 판단: 클릭률 5% 미만이 2주 지속되면 다이제스트 구성 교체(경기 중심 ↔ 뉴스 중심), 서버 성장 0이면 노출 지점 재배치.
