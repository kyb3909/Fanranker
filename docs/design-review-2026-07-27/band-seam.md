# 밴드 이음매 진단 — "상단 다크와 본문이 따로 논다"

> 측정: 로컬 프로덕션 `http://localhost:3100`, Chromium, viewport 1440×1000 (일부 스크린샷 1280).
> 좌표는 문서 절대좌표(px). 대상: `/`, `/prediction`, `/community/football`, `/explore`.
> 비교 기준: 채택 시안 `mockups/a-matchday.html`, 타이포 규약 `type-accent.md`.

---

## 0. 한 줄 결론

**이음매가 아니라 시스템이 두 개다.**
상단 밴드는 시안 A "매치데이"(웜 다크 · 크림 · 버건디 대기 · 어그로체 + Barlow Condensed)이고,
그 아래 본문은 `globals.css`가 스스로 이름 붙인 **"KT BizMeka-inspired Clean Design System"**(쿨 스틸 뉴트럴 `#f1f1f3` / `#eceef2` / `#e2e5ea`, Pretendard 단일)이다.
두 시스템이 공유하는 것은 좌우 1280 랩 하나뿐이고, 색온도·질감·서체·숫자·이미지 그레이딩 **어느 축도 넘어가지 않는다.**

정량으로:

| 시안 A 시그니처 | 밴드(다크) | 본문(라이트) | 목업 본문 |
|---|---|---|---|
| `.gn-num` (콘덴스드 tabular 숫자) | 20 | **0** | **18** |
| `.gn-thumb` (채도 down 그레이딩) | 3 | **0** | **7** |
| `.gn-kicker` / `.gn-lockup` / `.gn-stat` / `.gn-head` / `.gn-on-dark` | — | — | — |

마지막 행이 핵심이다. `type-accent.md`가 정의한 클래스는 **`a-tokens.css`에 하나도 착륙하지 않았다.** 스펙은 문서로만 존재한다.
그리고 `.gn-num`이 실제로 쓰인 파일은 5개 — `matchday-band`(9), `explore` 밴드(5), `page-band`(3), `site-footer`(2), `section-header`(1). **전부 다크 존이거나 밴드 안이다.**
`.gn-thumb`은 사이트 전체에서 **단 1곳**, 밴드 히어로뿐이다.

즉 A의 어휘는 "밴드 + 푸터"라는 봉인 구역 안에서만 산다. 밴드는 페이지의 머리가 아니라 **옛 사이트 위에 볼트로 붙인 이물질**이다.

## 1. 전환의 급작스러움 — 이음매에 아무것도 없다

### 실측: 이음매의 "죽은 구간"

| 페이지 | 밴드 마지막 콘텐츠 ↓ | 밴드 끝 | 본문 첫 요소 ↑ | 빈 다크 | 빈 그레이 | **죽은 구간 합** |
|---|---|---|---|---|---|---|
| `/` | 596 | **624** | 648 (좌) / 664 (중앙) | 28px | 24px / 40px | **52 ~ 68px** |
| `/prediction` | ~203 | **235.2** | 259.2 | 32px | 24px | **56px** |
| `/community/football` | ~246.6 | **278.6** | 302.6 | 32px | 24px | **56px** |
| `/explore` | (카드가 관통) | **303.2** | — | **0px** | **0px** | **0px** |

`/`, `/prediction`, `/community` 는 이음매에 **52~68px짜리 무인지대**를 두고 그 한가운데를 칼로 자른다.
위쪽 절반은 아무것도 없는 검정, 아래쪽 절반은 아무것도 없는 회색. 두 개의 빈 여백이 하나의 직선으로 맞붙는다 —
이게 "면이 끝났다"로 읽히는 물리적 이유다. 흐름이 끊긴 게 아니라 **애초에 흐를 것이 없다.**

### 이음매가 하필 밴드에서 가장 납작한 지점에서 일어난다

`.gn-band` 배경 스택:

```
radial-gradient(1100px 420px at 78% -10%,  rgba(150,30,55,.28), transparent 60%)
radial-gradient( 700px 300px at  8% 110%,  rgba(150,30,55,.14), transparent 65%)
var(--gn-night)  /* #16141a */
```

`/` 기준 밴드 높이 530px에서 계산하면:

- 1번 래디얼: 중심 y = −53, 세로 반경 420 → **y = 367에서 소멸**. 밴드 하단 163px에는 전혀 닿지 않는다.
- 2번 래디얼: 중심 y = 583(밴드 밖), x 중심 = 114 → **좌측 1/3 하단에만 alpha .14의 희미한 온기**.

결과: **밴드의 아래 모서리, 특히 오른쪽 2/3는 순수 `#16141a` 평면**이다.
버건디 대기는 전부 위쪽·왼쪽으로 빠져나가고, 라이트와 만나는 바로 그 선에서 밴드는 가장 차갑고 가장 납작하다.
`fin-home.png` 하단부를 보면 우측 절반이 완전한 무채색 검정으로 죽어 있다.

### 목업은 어떻게 했나 — 솔직하게

**목업도 이음매 자체는 똑같이 비어 있다.** `.me-grid { padding-bottom: 30px }` + `.main { padding-block: 26px 56px }` = 56px 죽은 구간. 구조가 같다.
그러니 "목업엔 전환 장치가 있고 구현엔 없다"는 진단은 **틀렸다.** 목업이 안 끊겨 보이는 이유는 이음매 처리가 아니라 **양쪽 존이 같은 가족이라서**다(§4, §5).
→ 처방은 "이음매에 장치를 넣는다"만으로는 부족하고, **본문 쪽을 밴드 가족으로 되돌리는 것**이 본체다.

## 2. 정렬 축 — 두 페이지는 8px 어긋나 있다

밴드 내부 콘텐츠 좌측선은 전 페이지 동일: **x = 96.5**
(`max-w-[1280px]` 랩 좌측 72.5 + `sm:px-6` 24px)

| 페이지 | 밴드 콘텐츠 L | 본문 콘텐츠 L | **Δ** | 본문 `<main>` 클래스 |
|---|---|---|---|---|
| `/` | 96.5 | 96.5 | 0 ✅ | `px-4 sm:px-6` |
| `/prediction` | 96.5 | 96.5 | 0 ✅ | `px-4 sm:px-6` |
| `/community/football` | 96.5 | **88.5** | **8px** ❌ | `container … px-4` |
| `/explore` | 96.5 (걸친 카드) | **88.5** | **8px** ❌ | `container … px-4` |

원인은 단순하다. 밴드는 `px-4 sm:px-6`(≥640에서 24px)인데, 아래 두 페이지의 `<main>`은 `px-4`만 있고 **`sm:px-6`이 빠졌다** → 16px.

이건 감상이 아니라 눈에 보인다. `fin-explore.png`에서 밴드에 걸친 `축구` 카드의 좌측 모서리보다 그 아래 `실시간 인기글` 카드의 좌측 모서리가 8px 더 왼쪽으로 튀어나와 있다.
`band-board.png`에서도 `축구` 제목(24)과 `이적시장` 카드(16)가 어긋난다.
**아이러니: 유일하게 잘 이어져 보이는 두 페이지가 유일하게 좌측선이 어긋난 페이지들이다.** 걸침이 그 결함을 덮고 있다.

해당 파일: `app/community/[slug]/page.tsx:274,377` · `app/explore/explore-content.tsx:252` (+ 일관성상 `app/post/[id]/page.tsx:262`)

## 3. 폭 리듬 — 세로선이 단 하나도 이어지지 않는다

`/` 기준 실측:

**밴드 내부** (`grid gap-4 lg:grid-cols-[1.35fr_1fr]`, gap **16px**)
```
96.5 ├──────── 톱스토리 698.5 ────────┤ 795  ▏16▕  811 ├──── 오늘의 경기 517.5 ────┤ 1328.5
```

**본문** (`grid grid-cols-12 gap-5 lg:gap-6`, gap **24px**, 컬럼 80.66px)
```
96.5 ├── 레일 290 ──┤ 386.5 ▏24▕ 410.5 ├──── 피드 604 ────┤ 1014.5 ▏24▕ 1038.5 ├── 사이드 290 ──┤ 1328.5
```

- 밴드의 유일한 내부 세로선 **795 / 811**은 본문 중앙 컬럼(410.5–1014.5) **한복판에 떠 있다.** 아래에 대응하는 선이 없다.
- 본문의 강한 세로선 **386.5 / 410.5 / 1014.5 / 1038.5**는 밴드에 대응이 없다.
- **거터 값부터 다르다: 밴드 16px vs 본문 24px.** 같은 리듬이 아니라 다른 박자다.
- 12칼럼 환산: 밴드 좌측 698.5px ≈ 6.8칼럼, 우측 517.5px ≈ 5.0칼럼 — 7|5로 정수 스냅되지도 않는다(7|5라면 805.1/829.1이어야 함, 실제 795/811 → **10px, 18px 어긋남**).

즉 밴드와 본문은 **좌우 바깥 테두리만 공유하고 안쪽 구조는 완전히 무관하다.** 풀블리드 다크가 아래 그리드를 전혀 예고하지 않으니, 다크가 끝나는 순간 "다른 페이지가 시작"된다.

> 정직한 단서: **목업도 이 축은 안 맞다.** 목업 밴드 `1.35fr 1fr / gap 20`(720.3 / 740.3) vs 본문 `218px 1fr 300px / gap 24`(242 / 908 / 932) — 역시 공유선 0.
> 따라서 컬럼 정렬은 **진짜 원인이지만 주범은 아니다.** 우선순위를 낮게 잡아야 한다(Rx H).

## 4. 색·질감 연속성 — **온도가 뒤집혀 있다** (진짜 주범)

### 색온도 실측 (R−B, 양수 = 웜)

| 역할 | 목업(채택 시안) | 현재 구현 | R−B |
|---|---|---|---|
| 밴드 크림 텍스트 | `#f5efe7` | `#f5efe7` | **+14 웜** |
| **본문 캔버스** | `--paper #faf9f7` | **`--background #f1f1f3`** | 목업 **+3 웜** → 구현 **−2 쿨** |
| **본문 라인** | `--line #e8e5e0` | **`--border #e2e5ea`** | 목업 **+8 웜** → 구현 **−8 쿨** |
| **본문 서피스** | — | **`--muted/secondary/accent #eceef2`** | **−6 쿨** |
| 본문 보조 텍스트 | `--ink-3 #8d8794`(웜그레이) | **`--muted-foreground #5c6470`**(스틸) | 웜 → **쿨** |

`app/globals.css:25–58`은 이걸 스스로 문서화하고 있다:

```css
/* ===== KT BizMeka-inspired Clean Design System ===== */
--background: #f1f1f3;
--secondary: #eceef2;  /* 쿨 뉴트럴 — hover/chip 서피스 */
--muted:     #eceef2;  /* 쿨 뉴트럴 */
--border:    #e2e5ea;  /* steel line */
--muted-foreground: #5c6470;  /* steel mute */
```

밴드는 크림·버건디의 **웜 세계**, 본문은 스틸의 **쿨 세계**. 이음매에서 색온도가 부호를 바꾼다.
사람은 명도 점프(다크→라이트)는 "존이 바뀌었다"로 받아들이지만, **명도 점프 + 색온도 반전은 "제품이 바뀌었다"로 받아들인다.** 이게 "따로 논다"의 물리적 정체다.

### 명도 차 — 캔버스가 3배 더 세다

| | 캔버스 | 카드 | Δ |
|---|---|---|---|
| 목업 | `#faf9f7` | `#ffffff` | **5** |
| 구현 | `#f1f1f3` | `#ffffff` | **14 (2.8×)** |

목업의 라이트 존은 "종이 한 장" — 카드가 종이에서 거의 떠오르지 않는다(에디토리얼).
구현의 라이트 존은 "회색 판 위의 카드 그리드" — 네이버/다음 포털 문법이다.
포스터 밴드 + 포털 캔버스는 서로를 부정한다.

### 질감 — 밴드의 그레이딩이 본문으로 전혀 넘어가지 않는다

`.gn-thumb`(`saturate(.82) contrast(1.06) brightness(.9)` + 하단 스크림)은 **사이트 전체에서 밴드 히어로 1곳**뿐이다.
목업은 같은 `.thumb`를 본문 피드 카드에 **7번** 걸었다.
결과: 밴드 히어로는 무겁게 그레이딩된 야간 사진, 바로 아래 피드 썸네일은 원본 채도 그대로 → **같은 사진가가 찍은 화면이 아니다.**

그레인(`.gn-band::before`, opacity .05)도 밴드 박스 안에만 그려진다. 라이트 존에 질감 메아리 0.

### 버건디 — 색은 있는데 문법이 다르다

본문에 버건디 요소 자체는 있다(측정 20개: 활성 필 `오늘의 떡밥`, 월드컵 배너, `축구 게시판 보러 가기` 버튼).
그러나 **밴드의 버건디는 "대기"(래디얼 글로우 + 사선 플레이트 면)이고, 본문의 버건디는 "페인트"(솔리드 필)**다.
같은 색을 전혀 다른 문법으로 쓰면 색상 연속성이 생기지 않는다. `/prediction`이 특히 잔인하다 —
근사 블랙 밴드와 진한 버건디 월드컵 배너가 **24px짜리 쿨 그레이 띠 하나를 사이에 두고** 떨어져 있다. 붙었으면 융합했을 두 웜 다크 면을 회색 틈이 갈라놓는다.

## 5. 타이포 연속성 — 사다리에 중간 칸이 없다

| | 밴드 | 본문 |
|---|---|---|
| 디스플레이 | 어그로체 42px / 700 / `-0.035em` | **없음** |
| 콘덴스드 라틴·숫자 | Barlow Condensed (`MATCHDAY`, `TOP STORY`, `6 MATCHES`, `TUE 7/28`, `06:24:36`, `18:30`) — **20슬롯** | **0슬롯** |
| 키커 (자간 .2em 라틴 대문자) | 12.5–13px, 전 페이지 | **0** |
| 본문 서체 | — | Pretendard 단독 |

- 최대 42px → 본문 최대 ~17px, **2.5배 점프를 한 칸에 뛴다.** 중간 계단(콘덴스드 키커 / 큰 숫자)이 라이트 존에 하나도 없다.
- 본문은 숫자 천지인데(`135` `134` `133`, `추천 0`, `2일 전`, `오늘 글 0 · 전체 135`, `볼 10개`, `07.28 오후 06:30`) **전부 Pretendard 프로포셔널**이다.
  콘덴스드 숫자는 A 어휘 중 **가장 이식 비용이 낮은데도(span 하나) 0% 적용**됐다.
- `type-accent.md`가 정의한 `.gn-kicker`, `.gn-lockup`, `.gn-stat`, `.gn-head`, `.gn-hl`, `.gn-on-dark`, `.gn-plate` — **`a-tokens.css`에 단 하나도 없다.** 규약이 코드에 착륙하지 않았다.
- `components/section-header.tsx`는 "본문 섹션 헤드"인데 그 자체가 **또 다른 다크 블록**이다. 라이트 존이 쓸 수 있는 A 타이포 컴포넌트는 사실상 존재하지 않는다. (그리고 다크 확산은 금지 조건 → 이 경로는 막혀 있다.)

## 6. 운동장만 나은 이유 — 걸침의 원리

### 실측

```
        x=96.5                                    x=546.5
          ┌────────────────────────────────────────┐  y=250.4
  다크 ▓▓▓│         축구 · 오늘글 0 전체 135        │  ← 카드의 52.8px 가 다크 위
━━━━━━━━━│━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━│━━━━━━  y=303.2  밴드 끝
  라이트 │                                        │  ← 카드의 48.0px 가 라이트 위
          └────────────────────────────────────────┘  y=351.2
                shadow: 0 18px 38px -18px rgba(0,0,0,.62)  → 라이트 존에 낙하
```

카드 높이 100.8px가 **52.8 / 48.0 = 거의 정확히 반반**으로 이음매를 관통한다.
`.gn-band-open`(= `overflow: visible`)이 클리핑을 풀고, 아래 `<main>`이 `pt-[72px]`(48 걸침 + 24 숨)로 자리를 비켜준다.

### 왜 이게 연결감을 만드는가 — 원리 3개

1. **경계의 성격이 바뀐다.** 걸침이 없으면 그 선은 *두 도형이 맞닿은 윤곽선(figure edge)*이다 — 시각계는 "다른 물체"로 판정한다.
   걸침이 있으면 같은 선이 *하나의 면 위를 지나가는 사건(surface event)* — 물체 위에 그림자가 드리운 것으로 판정한다. 게슈탈트 좋은 연속성이 물체 편을 든다.
2. **소유권이 양쪽에 걸린다.** 카드는 다크 존의 자식(DOM상 `PageBand`의 children)이면서 시각적으로는 라이트 존에 절반이 있다. "누구 것인가"가 미결이면 뇌는 두 존을 **한 장면**으로 묶는다.
3. **다크가 라이트에 흔적을 남긴다.** `0 18px 38px -18px rgba(0,0,0,.62)`가 **라이트 캔버스 위에** 떨어진다. 다크의 물성이 라이트 쪽으로 새어 나온 유일한 지점이다.
   (보너스: 걸친 카드 안의 `오늘 글 0 · 전체 135`가 `.gn-num`이다 — 사이트에서 **콘덴스드 숫자가 밝은 면에 놓인 유일한 자리**가 하필 유일하게 이어져 보이는 자리다. 우연이 아니다.)

**단, 이 원리는 "밴드에 카드를 물려 놓기"가 아니라 "두 존이 하나의 물체·하나의 빛을 공유하기"다.** 처방은 걸침 복제뿐 아니라 §4의 온도 통일까지 가야 완결된다.

## Rx A — 이음매 2단 처리: 밴드 하단 웜 워시 + 라이트 존 잔광 🥇

**무엇** — ① 밴드 배경 스택에 하단을 겨냥한 버건디 래디얼 하나 추가. ② 밴드 바로 다음 형제의 첫 132px에 아주 옅은 웜 잔광.

**왜 이음매를 만드는가** — §1에서 밝힌 대로 지금 전환은 **밴드에서 가장 차갑고 납작한 지점(순수 `#16141a`)** 에서 일어난다.
하단 워시를 넣으면 라이트와 만나는 마지막 픽셀이 **버건디 기 있는 웜 다크**가 되어, 이음매의 **색상 점프가 사라지고 명도 점프만 남는다.**
명도만 바뀌는 경계는 "존이 바뀌었다"로, 명도+색상이 함께 바뀌는 경계는 "제품이 바뀌었다"로 읽힌다 — 후자를 전자로 강등시키는 조치다.
잔광은 §6-③ "다크가 라이트에 흔적을 남긴다"를 **전 페이지에 무료로 이식**한다. 다크 면적은 1px도 늘지 않는다(제약 준수).

**코드** — `app/a-tokens.css`, `@layer components` 안의 `.gn-band` 규칙 교체 + 1개 추가:

```css
  /* ── 다크 밴드 ── */
  .gn-band {
    position: relative;
    overflow: hidden;
    color: var(--gn-cream);
    background:
      radial-gradient(1100px 420px at 78% -10%, rgba(150, 30, 55, 0.28), transparent 60%),
      /* ▼ 추가: 하단 모서리 웜 워시.
         기존 래디얼 2개는 위(y≤367)·좌하(밴드 밖)를 향해 밴드 아래 모서리가
         순수 #16141a 로 죽는다 → 이음매가 가장 차가운 지점에서 일어난다.
         이 한 줄이 마지막 픽셀을 버건디 쪽으로 끌어와 색상 점프를 지운다.
         104% 로 밴드 밖에 중심을 두므로 밴드가 141px 든 530px 든 하단만 물든다. */
      radial-gradient(1500px 210px at 50% 104%, rgba(150, 30, 55, 0.34), transparent 70%),
      radial-gradient(700px 300px at 8% 110%, rgba(150, 30, 55, 0.14), transparent 65%),
      var(--gn-night);
  }

  /* 라이트 존 첫 132px 에 다크의 잔광을 남긴다 (운동장 카드 그림자와 같은 역할).
   * 인접 형제 선택자라 JSX 수정 0 — 밴드가 있는 모든 페이지에 자동 적용된다.
   * 측정: /, /prediction, /community, /explore 모두 밴드 다음 형제는 <main>이고 배경이 transparent → 충돌 없음. */
  .gn-band + * {
    background-image: linear-gradient(180deg, rgba(150, 30, 55, 0.06), rgba(150, 30, 55, 0) 132px);
    background-repeat: no-repeat;
  }
```

**위험** — 최저. CSS 한 블록, JSX 0, 레이아웃 이동 0, 롤백 1줄. `@layer components` 안이라 Tailwind `bg-*` 유틸이 항상 이긴다.

## Rx C — 캔버스 온도 교정: 쿨 스틸 → 웜 페이퍼 🥉

**무엇** — 라이트 존 중립 토큰 6개를 목업 값 계열로 되돌린다.

**왜 이음매를 만드는가** — **§4가 진짜 주범이고, 이게 그 처방이다.**
`#faf9f7`(웜 페이퍼)은 밴드의 크림 `#f5efe7`과 같은 가족이다. 라이트 존이 "밴드의 크림을 최대 밝기까지 올린 것"으로 읽히면
이음매는 **다른 시스템 사이의 경계가 아니라 한 시스템 안의 명도 단계**가 된다. 색온도 부호 반전(§4 표)이 사라진다.
덤으로 캔버스/카드 대비가 14 → 5로 떨어져 "포털 회색 판" 인상이 걷히고 에디토리얼 종이로 바뀐다.

+ /* ===== 시안 A "매치데이" 라이트 존 — 웜 페이퍼 =====

+  * 쿨 그레이(#f1f1f3/#eceef2/#e2e5ea)는 밴드와 색온도 부호가 반대라

+ --background: #faf9f7;

- --muted:     #eceef2;   /* 쿨 뉴트럴 */

**위험** — 기술적으로는 낮음(순수 색값, 레이아웃 무변화, 1커밋 롤백). 대비는 오히려 개선(`#111` on `#faf9f7`).

## Rx D — `.gn-num` 라이트 존 전개

**무엇** — 본문의 숫자 슬롯에 콘덴스드 tabular 숫자를 입힌다. 목업 본문은 18곳, 현재 0곳.

**왜 이음매를 만드는가** — §5. 콘덴스드 숫자는 A 어휘 중 **이식 비용이 가장 낮은 시그니처**(span 하나)이면서
밴드의 `06:24:36` / `18:30` / `6 MATCHES` / `TUE 7/28`과 **문자 그대로 같은 글자꼴**이다.
본문 카운트가 그 글자꼴을 쓰기 시작하는 순간, 라이트 존은 밴드의 연장으로 읽힌다. 다크를 1px도 안 쓰고 만드는 연속성이다.
운동장이 통하는 숨은 이유 중 하나이기도 하다(§6 보너스).

**대상**
- `components/post-card/post-card-meta.tsx` — 추천/댓글/조회 카운트 (38, 41, 63, 66, 175, 186, 199–202행 부근)
- `app/community/[slug]/page.tsx` — 목록 번호·추천 수 (`135` `134` `133`, `추천 0`)
- `app/explore/explore-content.tsx` — 본문 쪽 `오늘 글 / 전체` (밴드 카드엔 이미 적용됨)
- `/prediction` 경기 시각 `07.28 오후 06:30`, 볼 잔액 `10개`

**코드 패턴**

```tsx
// ❌ 한글 섞인 줄 전체에 걸지 말 것 — Barlow Condensed 는 라틴 전용,
//    한글이 폴백으로 떨어져 줄 안에서 서체가 두 개로 갈린다 (a-tokens.css:35 주석)
<span className="gn-num">전체 {total}</span>

// ✅ 숫자만 분리
전체 <span className="gn-num">{total.toLocaleString()}</span>
```

**위험** — 낮음. 단 위 함정 하나만 기계적으로 지킬 것. `.gn-num`은 이미 `a-tokens.css`에 있어 신규 CSS 0.

## Rx E — 걸침(straddle) 확산: 운동장 원리를 `/prediction`·`/community`로

**무엇** — 각 페이지의 **본문 첫 요소를 `PageBand`의 children으로 옮겨** 밴드에 걸치게 한다. 운동장과 동일한 구조.

- `/prediction` → 탭 바(`오늘의 경기 / 랭킹 / 통계 / 마이페이지`)
- `/community/[slug]` → 채널 카드 행(`이적시장 / 월드컵 / 캣스날`)

**왜 이음매를 만드는가** — §6의 원리 3개(경계 성격 전환 / 소유권 양분 / 빛의 낙하)를 그대로 이식한다.
특히 이 두 페이지는 **밴드가 141px에 내용이 제목 한 줄뿐**이라 지금은 "빈 검정 띠"로 읽힌다.
걸침은 그 빈 다크에 실체를 주면서 동시에 이음매를 지운다 — **밴드를 키우지 않고 밴드를 살리는 유일한 방법**이다.

**코드**

```tsx
<PageBand kicker="PREDICTION" title="승부예측" description="…">
  {/* children 을 넘기면 gn-band-open(overflow:visible) + pb-6 로 자동 전환된다 */}
  <div className="grid gap-4">
    {/* 기존 탭 바를 그대로 여기로 이동 */}
  </div>
</PageBand>

<main className="container mx-auto max-w-[1280px] px-4 sm:px-6 pt-[72px] pb-10">
  {/* pt-6 → pt-[72px] : 걸침 48 + 숨 24. 운동장과 동일 값 */}
```

**튜닝 지침** — 걸치는 요소는 **불투명 흰 카드**여야 하고, 걸침 비율은 **다크 : 라이트 ≈ 50:50**(운동장 실측 52.8/48.0)이 가장 잘 먹는다.
그림자 `0 18px 38px -18px rgba(0,0,0,.62)`를 반드시 함께 가져갈 것 — 라이트 존에 떨어지는 그 그림자가 §6-③이다.

**위험** — 중간. JSX 이동 + 반응형(모바일에서 걸침이 깨지지 않는지, `<640`에서 밴드 패딩/카드 높이) 검증 필요. 효과는 구조적 처방 중 최대.

## Rx F — `.gn-thumb` 피드 썸네일 전개

**무엇** — 밴드 히어로에만 걸린 이미지 그레이딩을 본문 카드 썸네일·카드뉴스로 확장. 목업 본문 7곳, 현재 0곳.

**왜 이음매를 만드는가** — §4 질감 축. 밴드 히어로는 `saturate(.82) contrast(1.06) brightness(.9)` + 하단 스크림으로 무겁게 잡혀 있는데
바로 아래 피드 썸네일은 원본 채도다. 사진 톤이 갈리면 **두 존이 다른 매체로 보인다.**
그레이딩을 통일하면 밴드 히어로와 피드 카드가 "같은 지면의 다른 크기 사진"이 된다 — 매거진의 기본 문법이다.

**코드** — 신규 CSS 0. 썸네일 래퍼에 클래스만 추가:

```tsx
<div className="gn-thumb relative aspect-video overflow-hidden rounded-lg">
  <img … />
</div>
```

- 히어로가 아닌 일반 카드는 `gn-thumb`만 (하단 스크림 약한 버전). `gn-thumb-hero`는 밴드 전용 유지.
- `.gn-thumb img`가 `width/height:100%` + `object-fit:cover`를 강제하므로, 래퍼에 **명시적 비율(`aspect-video` 등)이 있어야** CLS가 안 난다. (홈 CLS 0.276 사고 이력 — `project_perf_lcp_cls_feed`)

**위험** — 낮음~중. 썸네일 렌더 지점이 여러 컴포넌트에 흩어져 있어 누락 시 톤이 섞인다 → 한 번에 전부 or 전부 안 함.

## Rx G — 타이포 중간 계단: `type-accent.md` 클래스 착륙 + 라이트 존 키커

**무엇** — ① `type-accent.md`가 정의만 하고 코드에 없는 `.gn-kicker` / `.gn-lockup` / `.gn-stat` / `.gn-head` / `.gn-on-dark`를 `a-tokens.css`에 실제로 넣는다.

밴드의 `MATCHDAY` / `TOP STORY` / `OPEN BOARDS`와 **같은 콘덴스드 라틴 키커**가 본문 섹션 머리에 등장하면

**위험** — 낮음(순수 CSS + 마크업). 다만 라틴 라벨 카피는 사람 판단이 필요 → 운영자 확인 후 진행.

## Rx H — 밴드 내부 세로선을 본문 12칼럼 리듬에 편입 (부분 처방)

**무엇** — 밴드 그리드를 본문과 **같은 12칼럼 · 같은 24px 거터**로 갈아탄다.

**왜 이음매를 만드는가** — §3. 지금은 거터 값부터 다르고(16 vs 24) 밴드의 유일한 내부 세로선이 본문 중앙 컬럼 한복판에 떠 있다.
같은 칼럼 시스템을 쓰면 밴드의 분할선이 최소한 **본문과 같은 격자 위에 놓인다.**

**코드**

```diff
- <div className="grid gap-4 pb-7 lg:grid-cols-[1.35fr_1fr]">
+ <div className="grid grid-cols-12 gap-6 pb-7">
-   {slides.length > 0 && <TopStoryCarousel slides={slides} />}
-   {matches.length > 0 && <TodayFixtures matches={matches} />}
+   {slides.length > 0 && <div className="col-span-12 lg:col-span-7"><TopStoryCarousel slides={slides} /></div>}
+   {matches.length > 0 && <div className="col-span-12 lg:col-span-5"><TodayFixtures matches={matches} /></div>}
  </div>
```

7|5로 가면 밴드 분할선이 **805.1 / 829.1** — 12칼럼의 7↔8 경계에 정확히 스냅된다(현재 795/811, 각 10px·18px 어긋남).

**⚠️ 솔직한 한계** — 본문 홈 그리드가 **3|6|3**이라, 밴드 분할선이 본문의 실제 세로선(386.5 / 410.5 / 1014.5 / 1038.5)과 **일치시키려면 3|9 또는 9|3밖에 없다.**
9|3이면 `오늘의 경기` 카드가 290px로 줄어 `18:30 · KBO · LG트윈스 vs 키움 히어로즈` 한 줄이 깨진다. **완전 정렬은 한쪽을 재설계하지 않는 한 불가능하다.**
그리고 **채택 목업도 이 축은 안 맞았다**(§3 각주). 따라서 이건 "격자와 거터를 공유한다"까지가 현실적 목표이고, 효과는 A~F보다 확실히 작다. **마지막에 둔다.**

**위험** — 중간(밴드 레이아웃 실변경 + 반응형 재확인). 효과 대비 위험이 가장 나쁘다.

# 🚫 하면 안 되는 것

1. **한쪽 면 색깔 액센트 보더** (`border-left: 3px solid …` 류) — 영구 금지. 이 문서의 어떤 처방도 이걸 쓰지 않는다.
   Rx A의 하단 워시는 **보더가 아니라 배경 스택의 래디얼**이다. 이음매에 `border-bottom`을 그리고 싶은 유혹이 오면 그것도 금지로 취급할 것.
2. **본문을 다크로 끌어올리기.** 베팅 카드 다크는 이미 기각됐다. 다크는 밴드·푸터 등 **선언 영역 3존에 잠금.**
   `components/section-header.tsx`(본문 안 다크 블록)를 더 확산시키는 것도 같은 위반이다.
3. **밴드 하단에 다크→그레이 선형 그라데이션.** `#16141a` → `#f1f1f3` 사이의 중간값은 **채도 0의 진흙 회색**이다.
   "부드러운 전환"이 아니라 "더러운 전환"이 되고, 밴드가 흐지부지 사라져 선언성까지 잃는다. 전환은 **색상(웜)** 으로 하고 **명도 점프는 유지**한다.
4. **밴드에 `border-radius`를 주거나 본문 칼럼 안으로 밀어넣기.** `page-band.tsx:24–26` 주석의 금지 사항 — 페이지마다 폭·모서리가 달라져 일관성이 깨진다.
   밴드는 **그리드 바깥 풀블리드**를 유지한다.
5. **밴드를 `box-shadow`로 띄우기.** 밴드는 카드가 아니라 페이지의 지면이다. 띄우면 "얹힌 물체"가 되어 분리감이 **더** 커진다.
   그림자는 §6대로 **밴드에 걸친 카드**만 가진다.
6. **`/prediction`·`/community`의 빈 밴드를 높이로 해결하기.** 141px 밴드의 문제는 **높이가 아니라 비어 있음**이다.
   늘리면 빈 다크만 커진다. 답은 Rx E(걸침)다.
7. **밴드 하단 패딩을 0으로 깎아 콘텐츠를 이음매에 붙이기.** 숨을 죽이는 것과 이어지는 것은 다르다. 답답해지고 연결은 안 생긴다.
8. **밴드 안에 목록·긴 글·폼 넣기** (`page-band.tsx:34`). 읽기 영역은 라이트가 낫다. 걸치는 것은 **요약 카드/탭**까지다.
9. **타이포로 밴드 흉내내기** — 본문에 어그로체 42px을 반복하면 밴드의 선언성이 죽는다. 라이트 존이 가져갈 것은 **키커와 숫자**(작은 것)이지 디스플레이(큰 것)가 아니다.
   한글 `letter-spacing > 0.05em`도 금지(`type-accent.md` 금지 #6).
10. **Rx D에서 한글 섞인 줄 전체에 `.gn-num` 걸기.** Barlow Condensed는 라틴 전용 — 한글이 폴백으로 떨어져 한 줄 안에 서체가 둘로 갈린다.
    반드시 **숫자만** `<span>`으로 분리한다.
11. **Rx G에서 대문자 키커 남발.** 화면당 대문자 블록 3개 초과 금지. 밴드가 이미 2–3개를 쓰므로 라이트 존은 1–2개까지.
