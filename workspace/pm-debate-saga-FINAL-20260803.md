## 1. 대립 지점 판정

### 충돌 A — "variable reward 콘텐츠"(V) vs "클릭 기대 불일치"(C)

**판정: 결론은 C가 맞고, C가 댄 근거는 틀렸다. 수정 방법이 달라진다.**

C는 "`ScrollToOpenArticle`이 JS로 열어야 하므로 실패 시 기사를 못 본다"고 했다. 코드는 그렇지 않다.

- `page.tsx:293` — `<details open={a.postId === from}>`. **펼침은 서버 렌더 결과**다. JS가 죽어도 기사는 펼쳐져 있다.
- `scroll-to-open.tsx:11-12` — 이 컴포넌트는 `scrollIntoView`만 한다. 즉 JS가 담당하는 건 **스크롤뿐**이다.
- `from` 불일치 우려도 낮다. `card-news-feed.tsx:456`이 `from=${card.id}`를 직접 박고, `searchParams`를 읽는 순간 이 페이지는 동적 렌더로 떨어지므로 `revalidate = 30` 캐시가 `from`을 섞을 일이 없다.

**그런데 문제는 그대로 남는다.** `page.tsx:65` — 연표는 `occurred_at ascending`. 방금 클릭한 최신 기사는 **구조적으로 항상 맨 아래**다. 착지 첫 화면은 `⚠️ 확정되지 않은 이적설입니다` 배너(:138) → 스테퍼(:169) → 투표(:200) 순이다.
즉 진짜 결함은 "펼침 실패"가 아니라 **"첫 화면 정보 배치 실패"**다. 뉴스를 기대하고 누른 유저가 스크롤 없이는 뉴스를 못 본다.

→ **V의 variable reward 논리는 첫 화면을 통과한 유저에게만 성립한다.** 스테퍼가 한 칸 움직인 걸 보고 기뻐하려면 먼저 재방문을 해야 하고, 재방문하려면 첫 방문이 만족스러워야 한다. 순서상 C의 문제가 먼저다. V의 주장은 폐기가 아니라 **후순위**다.

→ **수정 방향도 C의 제안과 달라진다.** JS 제거가 아니라, `?from=` 진입 시 해당 기사를 헤더 바로 아래에 렌더하고 연표에서는 접는다. `articlesByEntry`(`page.tsx:72`)를 한 번 더 참조하면 끝이고 스키마 변경은 없다.

### 충돌 B — "재방문 축으로 KPI 재설정"(V) vs "언론사 지표 구조적 누수"(C·R)

**판정: C·R 승. 단 V의 방향 주장은 살아 있다 — 축을 되돌릴 게 아니라, 재설정했다고 선언한 그 축을 실제로 켜라.**

V는 "언론사 설득 축을 검색 유입이 아니라 재방문·체류로 이미 재설정해 놓은 게 맞는 방향"이라고 했다. 방향은 맞다. 문제는 **재설정된 새 축도 계측이 0이라는 것**이다. 확인 결과:

- `app/saga/[slug]/page.tsx` 372행 전체에 `trackEvent` 호출이 **0건**. `usePostViewTracker`도 없음.
- `card-news-feed.tsx:360-362` — `openPost(id)`는 목적지가 `/saga`든 `/post`든 동일하게 `cardnews_card_open_post`만 쏜다. **카드→사가 전환율을 지금은 GA4에서 분리할 수 없다.**
- R이 지적한 대로 `post_read`는 발사 지점이 없고 `board_view`는 프로모 카드 라벨로 오용 중이다. 즉 **사가 이전에 이미 옛 축도 죽어 있었다.**

**단, C의 "지표가 샌다"는 표현은 정정이 필요하다.** 원 기사 본문은 사가 안에서 실제로 렌더된다(`page.tsx:320-323`, `renderTipTapToHTML`). 유저는 기사를 읽고 있다. 기록만 안 될 뿐이다.
→ **손실이 아니라 미기록.** 이게 좋은 소식인 이유: 되찾는 비용이 fire-and-forget 호출 한 줄이다. 되찾을 게 없는 게 아니라, 주우면 되는 상태다.

**결론:** V의 "사가는 재방문을 만든다"는 주장은 현재 **증명도 반증도 불가능한 상태**다. 8/22에 트래픽이 들어와도 마찬가지다. 8/2 메모의 "소급 불가" 경고가 그대로 적용된다.

### 충돌 C — 검수 마찰을 더할 것인가 (C ③) vs 검수가 이미 병목일 수 있다 (R ③④)

**판정: 정면충돌이고, R의 실측이 선행이다. 그다음 C의 마찰을 "신규 생성 건에만" 적용하면 둘 다 만족한다.**

C는 오추출 방지를 위해 승인 전 원문 열람 강제를 요구한다. R은 검수 처리량이 이미 병목일 수 있고 그 지연이 그대로 W4(9/1 정산) 물량으로 전가된다고 경고한다(`④의 리스크는 ③에 종속`). 마찰을 더하면 R의 리스크가 커진다.

해소는 C 자신의 제안 안에 있다 — `created:true`(신규 사가 생성)와 `created:false`(기존 사가 매칭)를 나누는 것. 오추출의 폭발 반경은 **신규 slug 생성에 집중**된다. 기존 사가에 기사가 잘못 붙는 건 문서 하나의 오염이지만, 철자 오류로 새 slug가 생기는 건 실존하지 않는 선수의 공개 문서 생성이다. 마찰을 신규 건에만 걸면 총 검수 시간 증가는 미미하고 리스크는 대부분 잡힌다.
**단 순서는 R 먼저** — 하루 queued 건수를 모르는 상태에서 마찰을 설계하면 안 된다.

### 충돌 D — 8/22 유입과의 결합: 폭발(V ②) vs 학습비용(C ①⑤)

**판정: 둘 다 맞다. 같은 유저를 반대로 읽었을 뿐이고, 여기서 실제 액션이 나온다.**

유튜버발 라이트 유저는 **팬덤 정체성은 강하고 이적 도메인 리터러시는 낮다.** 이 둘을 분리하면 충돌이 사라진다.

- "나간다 / 남는다" 투표 — 리터러시 0으로 참여 가능. 팬덤 정체성 행동 그 자체. **V가 맞다.** 이벤트의 "커뮤니티 활동 3회" 게이트를 채울 저마찰 액션으로도 정확히 들어맞는다.
- "관심 → 접촉 → 제안 → 협상 → 메디컬" 스테퍼 — 도메인 리터러시를 요구한다. 첫 화면 1순위 정보로는 부적절. **C가 맞다.**

→ **투표는 살리고 스테퍼는 첫 화면에서 내린다.** 충돌 A의 수정(기사 우선 렌더)과 같은 작업으로 동시에 해결된다.

### 충돌 E — 이적시장 폐장 (C ④ 단독)

V·R 모두 다루지 않았다. C 단독 지적이고 치명도 중이 맞다. 다만 C가 놓친 부작용이 하나 더 있다: `SAGA_WINDOW_KEY`가 `identity_key`에 박히므로(`lib/saga/config.ts:5`) 겨울 창에는 같은 선수라도 새 사가가 열린다 — **유저 입장에선 자기 투표·댓글 이력이 사라진 것처럼 보인다.** "살아있는 위키"라는 약속과 정면으로 어긋나지만 Phase A 범위 밖이라 지금 고칠 일은 아니다. 킬 스위치만 심어두면 된다.

예측 슬립 제출 완료 모달에 방금 베팅한 팀 관련 진행 중 사가를 카드로 삽입.
`sagas.subject`와 `betman_games` 팀 매핑 조인. 새 스키마 불요.

**왜 4순위인가:** 방향은 세 관점 중 가장 크고, 7/1부터 있던 진단("예측 완료 직후가 최대 레버")을 처음 채울 재료가 맞다. 그러나 **#1이 안 되면 이 위젯의 효과도 측정할 수 없다.** 계측 뒤에 놓는 게 맞다.
붙일 때 `saga_view`에 `entry: "prediction_modal"` 파라미터를 실어 유입원을 분리할 것 — #1을 먼저 하는 이유가 여기서 회수된다.

### #5. 킬 스위치 + 적용 범위 축소 옵션
**[기대효과: 유령도시·오추출 폭주 시 즉시 복구 / 개발규모: 1~2시간 / 제안: C ④⑤]**

`lib/saga/config.ts`에 boolean 상수 하나 추가 — 카드 클릭을 `/saga`가 아니라 `/post/[id]`로 되돌리는 스위치. 소비처는 `lib/feed/cardnews.ts`의 `attachSagaLinks`(`:244`) 한 곳뿐이라 `card.sagaSlug = null`로 끝난다.

용도 두 가지:
- 이적시장 폐장 후 Phase B 지연 시, 신규 엔트리 0인 위키를 억지로 노출하지 않기.
- 8/22 유입 중 문제 발견 시 즉시 되돌리기.

C가 제안한 "tier1/official 기사만 사가로 우회"는 **채택하지 않는다.** 8/22 트래픽에서 표본을 줄이면 #1로 켠 계측이 무의미해진다. 전면 적용으로 데이터를 받고, 문제가 실제로 관측되면 스위치로 끄는 게 낫다.

## 5. 하지 말 것

- **소환 예약 배지 / 팬덤 사이드바(V ③-1·③-3)를 계측보다 먼저 붙이는 것.** 둘 다 좋은 아이디어지만 효과 측정 수단이 없는 상태에서 붙이면 "뭐가 통했는지 모르는 기능"이 하나 더 늘 뿐이다. #1 이후로.
- **롤백.** 데이터 손실이 없고 수정 비용이 반나절 단위인 개편을 되돌리면, 이미 링크된 기사와 8/31 정산 물량을 함께 버린다.
- **8/22 전 사가 적용 범위 축소.** 표본을 줄이면 계측이 무의미해진다. 스위치는 심되 켜두고 간다.
- **`?from=` 착지 화면에서 경고 배너를 지우는 것.** 위치는 내리되 제거는 안 된다 — 선수 실명 명예훼손 방어선이다.
