# Realist

## 1. 데이터가 "차별화 콘텐츠" 요구에 대해 실제로 말해주는 것

**결론부터: 이 데이터는 "콘텐츠가 매력이 없어서 이탈했다"를 지지하지 않는다. "재트리거 장치가 아예 없어서 이탈했다"를 지지한다.** 훅 모델로 보면 끊긴 고리는 보상(Reward)이 아니라 **트리거(Trigger) 재발화**다.

- 훅 루프 1바퀴(트리거=유튜버 영상 → 행동=가입/등록 → 보상=월드컵 참여감·경품기대 → 투자=슬립 제출)는 실제로 돌았다. 등록자의 62%가 최소 1회 이상 슬립을 냈고, 18%(83명)는 6건 이상 낸 진성 유저다. **1바퀴는 콘텐츠 문제가 아니라 정상 작동**했다.
- 문제는 **2바퀴째를 돌릴 재트리거가 시스템에 없었다**는 것. 06-29 주 217명 피크 → 07-06 주 60명(-72%)은 이벤트 자체 로직 변화(등록 마감, 배당 변화 등)가 없었던 시점에 발생 — 즉 콘텐츠·게임 품질과 무관하게 **유튜버 홍보라는 외부 트리거가 꺼지자마자 자연 감쇠**한 것. 사이트 자체가 "왜 오늘 다시 와야 하는가"를 유저에게 말해주는 내부 트리거(알림/이메일/카톡/디스코드 DM 등 owned 채널)를 하나도 못 만들었다.
- 커뮤니티 전환 1.5%(7명)는 "콘텐츠가 별로라서"가 아니라 **애초에 유저가 사이트에 온 이유(예측)와 콘텐츠 소비가 별개의 동기**였다는 뜻에 더 가깝다. 참여 정점(217명)에서도 콘텐츠 소비는 거의 0이었다 — 즉 사람이 많이 있을 때조차 콘텐츠가 훅으로 작동한 적이 없다. 그런데 이번 안건은 "콘텐츠로 재방문을 만들자"인데, 데이터는 오히려 **콘텐츠보다 재트리거 채널(발송 메커니즘) 부재가 훨씬 큰 병목**이라고 말한다. 콘텐츠를 아무리 잘 만들어도 유저에게 "그게 나왔다"를 알릴 채널이 없으면 3바퀴째는 여전히 안 돈다.
- 종료 즉시 100% 이탈(0명)은 "콘텐츠 매력 부족"의 증거로 오독하기 쉽지만, 더 단순한 설명이 있다: **이벤트 종료 = 그 유저들이 사이트에 올 유일한 이유(월드컵 슬립)가 소멸**한 시점과 정확히 일치한다. 대체할 다음 트리거(콘텐츠든 뭐든)가 준비되어 있지 않았다.
- **진단 완성을 위해 확인해야 할 것** (현재 브리프에 없음 → 추측 금지):
  - 이탈자들이 사이트를 다시 "안 왔다"인지, 왔지만 "콘텐츠를 안 봤다"인지 — `board_view` 계측이 죽어 있어(브리프 5번) 이 둘을 구분할 수 없다. 이게 구분되기 전엔 "콘텐츠 문제"라는 진단 자체가 성립 불가능.
  - 새 콘텐츠 후보를 push할 owned 채널의 실제 도달률(디스코드 서버 가입률/온보딩 전환율, 웹 알림 옵트인율) — 없으면 아무리 좋은 콘텐츠도 도달 자체가 안 된다.
  - 7/6 절벽이 "홍보 감쇠"인지 "콘텐츠 실망"인지는 유저 목소리(CS/피드백)가 전무해 확인 불가 (브리프 4-4). 최소 1회성 이탈 설문(예: 마지막 활동 후 3일 경과 유저에게 이메일/디스코드 DM 1문항 폴)이라도 있어야 이 축 자체를 논할 수 있다.

## 2. 1인 개발 1주 + 운영 주 1시간 이하 실현 가능 후보 3개

기각 축(퀴즈/타 커뮤니티 인덱스/베팅 연관/대규모/AI 그림 퀄 의존/커뮤니티 활성화 전제/유틸 보드 아류) 전부를 피하는 조건으로 좁힌 후보.

### 후보 A — 빅매치 프리뷰 카드 (배당 제외, 폼/역사 중심 원 콘텐츠)
- **데이터 소스 (기존 것만)**: betman 경기 일정(`lib/betman/`), `standings-scrape`로 이미 쌓인 순위 데이터, 팀별 최근 5경기 결과(기존 games 테이블). *배당(odds)은 의도적으로 제외* — 안 그러면 "베팅 연관" 기각 축에 다시 걸림.
- **구현 경로**: `data/agents/core/`에 신규 generator 모듈 1개 추가 (기존 뉴스 에이전트 LLM 파이프라인 재사용, 프롬프트만 신규 — "다음 빅매치 프리뷰: 최근 폼 + 순위 격차 + 한 줄 코멘트"). 발행은 기존 `posts` 테이블/발행 플로우 그대로 사용 (신규 테이블 불필요). 아스날 경기가 있는 주만 트리거하는 필터 로직 추가.
- **운영 루프**: 주 1회 수동 실행 (기존 "뉴스 에이전트 cron 자동화 금지" 원칙과 일치, 비용 통제), 발행 전 5분 검수. 주 1시간 이내 여유.
- **실패 조건**: 인터내셔널 브레이크 등 빅매치 없는 주는 콘텐츠 없음 → 자동 스킵 필요 (억지로 만들면 품질 저하). 조회수가 기존 뉴스 기사 평균과 비슷하거나 낮으면 "차별화 효과 없음"으로 즉시 판별 가능.
- **리스크 표시**: "최근 폼" 수치가 배당처럼 읽힐 수 있어 문구에서 예측/베팅 뉘앙스를 의도적으로 제거해야 함.

### 후보 B — 이주의 담벼락 베스트 (자사 콘텐츠 재활용 리캡)
- **데이터 소스 (기존 것만)**: `posts` 테이블의 view_count/vote count, 기존 categories. 새 AI 생성 불필요 — 정렬 쿼리 + 템플릿 문구.
- **구현 경로**: `scripts/weekly-recap.ts` (tsx 스크립트) 신규 추가 — 지난 7일 view+vote 상위 3건 쿼리 → 템플릿 문장으로 조합 → 기존 post 생성 API로 발행 (팀 담벼락 또는 global notice 패턴 재사용). Vercel cron에 주 1회 등록 (`vercel.json` + `app/api/cron/weekly-recap/route.ts`, `CRON_SECRET` 검증).
- **운영 루프**: 완전 자동화 가능 — LLM 호출도, 수동 검수도 필요 없음(순수 데이터 재배열). 월 1회 정도 문구 점검이면 충분 (사실상 주 1시간보다 훨씬 적음).
- **실패 조건**: 트래픽이 낮아 "상위 3건"이 view 3~5회 수준이면 오히려 "이 사이트 콘텐츠 소비 없음"을 유저에게 광고하는 역효과 → 최소 view 임계치(예: 20회) 미달 시 발행 스킵하는 안전장치 필수.
- **주의**: 이 자체는 약한 훅이다. 디스코드 다이제스트(이미 존재, 23:05)에 얹어 배포해야 "재트리거" 역할을 한다 — 콘텐츠만으론 도달이 안 된다는 1번 진단과 직결.

### 후보 C — 호칭 달성 공유 카드 (기존 Fan Identity 트리거 재사용)
- **데이터 소스 (기존 것만)**: `apply_flair_score()` 트리거, `user_unlocked_titles`, `flair_titles` — 이미 존재하는 팬 정체성 시스템 (마이그레이션 20260502b/c/d, 이미 배포됨). 신규 데이터 수집 불필요.
- **구현 경로**: `components/profile/`에 카드 컴포넌트 1개 추가, `html-to-image` 류 클라이언트 사이드 렌더링(서버 비용 0, AI 그림 생성 아님 — 팀 컬러/기존 뱃지 아이콘 조합한 결정론적 템플릿 디자인이라 "AI 그림 퀄 의존" 축을 피함). 트리거는 기존 unlock 이벤트 훅에 연결 — DB 변경 없음, 프론트 이벤트 리스너만 추가.
- **운영 루프**: 트리거·렌더링 전부 자동. 디자인 1회 작업 후 유지보수 사실상 0.
- **실패 조건**: 이건 명확히 "이미 활동한 유저를 더 활동하게" 만드는 리텐션 부스터이지 신규 유입 훅이 아니다. 커뮤니티 활동(글/댓글/투표) 자체가 1.5% 수준이라 unlock 이벤트 발생 빈도가 낮을 수 있음 — 이 경우 발동 자체가 드물어 효과 측정이 불가능해진다. 배포 후 1주 unlock 이벤트 발생 건수가 한 자릿수면 폐기.

## 3. 며칠 안에 성공/폐기를 가를 지표

측정 인프라(`board_view` 등)가 죽어 있는 현재 상태를 그대로 두면 아래 지표도 부정확하다 — **최소한 발행 URL 단위 view_count와 클릭 유입원 파라미터(UTM 유사 쿼리스트링) 정도는 반드시 계측**해야 판단 자체가 가능하다.

- **후보 A/B 공통**: 발행 후 48시간 내 해당 post의 view_count가 같은 기간 일반 뉴스봇 기사 평균 대비 몇 배인가 — 1배 이하면 "차별화 효과 없음"으로 즉시 폐기 판단.
- **후보 A/B (디스코드 배포 시)**: 디스코드 웹훅 링크 클릭 수 대비 실제 사이트 방문 전환율. 클릭은 있는데 사이트 재방문(로그인 세션)으로 안 이어지면 콘텐츠가 아니라 "사이트에 올 이유" 자체(로그인 필요성)가 문제 — 이건 콘텐츠 후보를 바꿔도 안 풀린다.
- **후보 B 전용**: 발행 대상이 된 "상위 3건" 게시물이 리캡 발행 이후 추가로 조회수가 늘었는가 (역주입 효과) — 안 늘면 리캡 자체가 발견 경로로 기능하지 않는다는 뜻.
- **후보 C 전용**: 배포 후 1주일 unlock 트리거 발생 건수. 한 자릿수면 표본 자체가 없어 판단 불가 → 폐기(다음 시즌 오픈 이벤트로 커뮤니티 활동이 늘 때 재검토).
- **공통 폐기 신호**: 어떤 후보든 발행 후 3일 내 "발행 시점 대비 신규 세션 증가"가 노이즈 수준(±10% 이내)이면, 콘텐츠 품질이 아니라 **1번 진단대로 재트리거 채널(알림/카톡/이메일) 부재가 원인**이므로 콘텐츠 후보를 더 만드는 대신 owned 발송 채널 구축을 먼저 해야 한다는 결론으로 전환할 것.
