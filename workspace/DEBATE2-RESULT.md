## 1. 토론 지도 — 충돌 → 무너진 주장 → 살아남은 것

### 라운드 1 구도
| | Visionary | Contrarian | Realist |
|---|---|---|---|
| 통합안 | **B+C 혼합** (스트립+앵커 스레드 동시) | **B + 즉시 언히든** ("합치기"가 아니라 "보이게") | **B + 언히든** (피드 무변경, 추가 섹션만) |
| 운영자 가설 | IA=필요조건, 콘텐츠=충분조건 (둘 다) | "분리가 문제" 아니라 **"숨기고 방치한 버그"** (과잉일반화 경계) | 둘 다지만 무게 다름, IA 수정 선행 |
| 앵커 재설계 | 기각 사유 **완전 해소** | **절반만** (부작용 제거≠매력 증명) | **부분 해소** (안전하게 만들수록 C는 B로 수렴) |
| 첫 세션 | B 스트립+앵커 최상단 | 오늘 경기 최소 1개 (선결 버그) | 오늘 경기+CTA 최상단 |

### 라운드 2에서 무너진 / 수정된 주장
1. **Visionary "B+C 하루 이틀 혼합 출시" → 완파, 스스로 철회.**
   Realist가 "본인이 '경기당 1건 자동 생성'이라 명시 = 읽기 계산이 아니라 **쓰기 경로**(중복 방지·취소/연기·생성 타이밍 엣지케이스)"로 자기모순 지적. Visionary 라운드2에서 **"C를 B와 병행 즉시 배포하자던 원안은 과했다"**며 C를 계측 이후 Phase 2로 후퇴. → 사실상 원안 철회.
2. **Visionary "그레이스풀 디그레이데이션 = 리스크 비대칭적으로 낮다" → 완파.**
   Contrarian이 "하루 1명 + EPL 8월 개막 조건에서 n≥10 도달은 예외가 아니라 **거의 발생 안 하는 케이스** = 업사이드는 이론적 옵션일 뿐, '낮은 기대효과를 리스크 언어로 재포장'"으로 격파. Visionary 반박 못 함.
3. **Realist "C를 안전하게 만들수록 C는 사라지고 B가 남는다" → 스스로 수정.**
   "C는 댓글이 쌓일 수 있는 독립 콘텐츠 단위라 위젯(B)과 형태가 다르다"고 인정하며 입장 조정. Visionary의 "형태·수명·영속성(posts에 남고 URL 공유·아카이브)은 다르다" 반박을 수용. → **C와 B는 다른 물건**이라는 데 3자 수렴.
4. **Contrarian "C는 계측 이후로 순서 미룬다(구현 비용 과대평가)" → 스스로 수정.**
   "구현이 정말 그렇게 싸다면 '나중 별도 스프린트'가 아니라 **지금 만들되 `is_visible`로 잠가 숨기는 것**이 맞는 절충안"으로 전진. → C 코드는 지금, 노출은 게이트 뒤로.
5. **Contrarian이 새로 세운 논점 "관련성 격차" → 살아남음(아무도 반박 못 함).**
   "문이 열려도 스트립에 뜨는 건 KBO인데 핵심 유저는 아스날/EPL 팬. '경기가 있다'≠'이 팬이 관심있는 경기다'" — Visionary·Realist 모두 이 변수를 빠뜨렸고 반박도 없음. → **스트립 EPL/아스날 우선 정렬**이 설계 요건으로 편입.
6. **"계측 = Sentry 풀 복구 선행" (Contrarian 함의) → Realist가 완화.**
   "Sentry 전체 복구 기다릴 필요 없이 **CTA 클릭 로그용 경량 이벤트 테이블 1개**면 B 클릭률 즉시 측정 가능" — 1차의 무거운 계측 P0를 **경량 계측으로 대체 가능**하다고 조정. Contrarian도 최종 권고에서 "배포와 동시에 계측 심는다"로 수용.

### 서로 양보한 것
- **Visionary → 전원**: C 즉시 병행 철회, 계측 이후 Phase 2로. B가 먼저.
- **Contrarian → V/R**: C 구현 비용 과대평가 인정, "지금 짜되 숨김"으로 전진. 앵커 재설계가 표본 붕괴 리스크는 실제로 제거함도 인정.
- **Realist → Contrarian**: "게이팅은 부작용 제거일 뿐 매력 증명 아니다" 수용, C를 데이터 게이트 뒤로.

## 2. 쟁점 5개 확정 답

### 쟁점1 — 운영자 가설("메뉴 분리가 진입을 막는다") 판정
**부분 인정, 그러나 정정.** 진짜 원인은 "분리" 자체가 아니라 **"`/prediction`을 월드컵 집중용으로 GNB에서 지웠는데, 그 이벤트가 7/19 종료된 뒤 대체 동선을 안 남긴 자해 버그"**다 (Contrarian 진단, 3자 수렴).
- 근거: "분리가 원인"이라면 노출했던 기간과의 비교 데이터가 있어야 하는데 없다. 현재 데이터는 "분리는 나쁘다"가 아니라 **"숨기고 방치하면 나쁘다"**만 증명.
- 실무 함의: 가설을 과잉일반화해 피드 아키텍처를 갈아엎지 말 것. **고칠 건 딱 하나 — 지워진 진입점 복구.**

### 쟁점2 — A~D 중 무엇인가 / "합친다"의 올바른 해석
**정답: B(상단 고정 스트립) + `/prediction` 언히든. A(완전 인라인 통합)는 기각.** (3자 만장일치)
- 운영자가 원하는 **결과**는 "합쳐진 UI"가 아니라 **"예측이 발견된다"**. B가 그 결과를 A보다 적은 리스크·빠른 속도로 준다.
- A 기각 사유: 담벼락(수동 소비)×예측(거래 행동) 인라인 혼합 → 뉴스 독자에겐 스팸, 예측하러 온 사람은 뉴스에 묻힘. 하루 1명 트래픽에서 인터리빙 알고리즘+신규 카드 타입 공수를 정당화할 데이터 없음(board_view 死).
- **되돌리기 쉬운 B로 먼저 증명 → 클릭률 낮으면 그때 A로 단계 확장.** 되돌리기 어려운 A를 먼저 하고 실패 확인하는 건 1인 예산에 안 맞음.

### 쟁점3 — 앵커 스레드(C) 재설계로 1차 기각 사유가 해소되는가 (명시 판정)
**판정: 표본 붕괴 리스크는 해소된다(✅). 그러나 매력은 미증명(❓) — 조건부 성립.**
- **해소된 것**: 픽 분포/참여자 수 **n≥10 게이팅** + 미달 시 분포 섹션 자체를 렌더 안 함(빈 상태 노출 금지) → "소수파 민망함/죽은 공간 신호"는 제거됨. Visionary의 다운사이드 캡(최악이어도 봇 뉴스 수준) 논리 성립. Contrarian·Realist도 부작용 제거는 인정.
- **해소 안 된 것**: 게이팅은 **부작용 제거일 뿐 매력 증명이 아니다**(Contrarian, 반박 없이 살아남음). 하루 1명+8월 개막 조건에서 대부분 경기가 n<10에 머물러 "뉴스+스코어+CTA 껍데기"로 수렴할 확률이 높다.
- **C가 B와 다른 물건인 근거(살아남음)**: C는 `posts`에 남는 **영구 게시물**(URL 공유·검색·팀 담벼락 아카이브·댓글 축적 가능), B는 경기 종료와 함께 사라지는 UI 크롬. 형태·수명·venue가 다르다.
- **결론**: 재설계는 **"안전하게 만들 수 있다"까지만 증명됐고 "볼 가치가 있다"는 미증명.** → C는 **코드는 지금 짜되 `is_visible=false`로 잠그고, B의 CTA 클릭률이 기준(노출 대비 10%+) 넘을 때만 켠다.** 이게 운영자의 "앵커 스레드 원함"을 기각 사유(표본 붕괴)를 존중하며 살리는 유일한 형태다.

### 쟁점4 — 매일 1명 유입의 첫 세션
**첫 화면은 "오늘/이번 주 예측 가능한 경기 최소 1개 + CTA"가 최상단에 보이는 담벼락.** (3자 만장일치)
- 지금은 담벼락=봇 뉴스만, 월드컵 메뉴=끝난 결과, /prediction=메뉴에 없음 → **매일 오는 1명이 핵심 루프(예측)를 발견할 방법이 사실상 0.** 이건 A/B/C/D 무엇을 택하든 즉시 고쳐야 하는 선결 버그.
- betman 데이터는 트래픽과 무관하게 매일 존재(여름 KBO 등) → **유저 수에 의존하지 않는 유일한 콘텐츠 소스.** 단, 관련성 정렬(EPL/아스날 우선) 필수.
- 트리클(하루 1명)은 리스크 낮은 실험장 → **8월 대량 유입 전에 B를 이 소수 표본으로 먼저 검증**하는 게 합리적.

### 쟁점5 — 1차 P0(계측·적중카드)와의 우선순위 관계
**밀어내지 않는다. 병행하되 순서가 재편된다.** 3자 공통.
- **`/prediction` 언히든이 새 최우선(P0-1)으로 승격.** 적중카드보다 작고(코드 1줄) 즉시 가능한데, 깔때기 전체를 막던 버그이기 때문. → **1차 P0 순서 수정: 계측·적중카드보다 언히든이 앞선다.**
- B(스트립)는 P0와 같은 사이클 병행(신규 로직 최소).
- **1차 P0 "계측 복구"는 완화 유지**: Sentry 풀 복구 대신 **CTA 클릭 로그 경량 이벤트 테이블 1개**면 B 클릭률 측정에 충분(Realist 조정, Contrarian 수용). 1차의 무거운 계측은 적중카드/장기 개선용으로 남겨두되, 이번 통합 검증의 선행 조건은 경량판으로 낮춘다.
- C·A는 리소스 경쟁 대상 → 이번 사이클 뒤로.

### 1차 결론과의 정합성 판정 (명시)
- **유지**: 적중카드(d)=P0-B 그대로. "글쓰기 아닌 재방문/반응 목표", "봇 뉴스 퇴출 아님·CTA 재료" 원칙 유지.
- **수정 1 (순서)**: 1차는 "P0-A 계측 복구 → P0-B 적중카드" 순이었으나, **`/prediction` 언히든이 둘보다 앞선 P0-1로 신규 삽입.** 깔때기를 막던 버그가 1차 토론 시점엔 IA 팩트 미확인으로 안 잡혀 있었다.
- **수정 2 (계측 범위 완화)**: 1차 "계측 복구=P0 선행 필수(Sentry 클라 포함 무겁게)"를, 이번 통합 검증 한정 **"CTA 클릭 로그 경량 테이블 1개면 충분"**으로 낮춤. Sentry 풀 복구는 여전히 바람직하나 B/C 배포의 하드 블로커에서 해제.
- **정합 (모순 아님)**: 1차에서 보류했던 앵커 스레드(b)를 운영자 요청에 따라 재론했고, "코드는 짜되 노출은 클릭률 게이트 뒤"라는 형태로 1차 보류 사유(표본 붕괴)를 그대로 존중하며 조건부 부활시킴. **1차 결론을 뒤집지 않는다.**

## 4. 소수의견 + 부활 조건

**소수의견 #1 — A(완전 인라인 통합, 예측=콘텐츠)**
- 밀렸던 맥락: 운영자의 "이벤트 페이지를 담벼락과 합치자"의 문자적 해석. 기각 사유: 하루 1명 트래픽에 인터리빙 공수 정당화 불가 + 두 기능 정체성 훼손.

## 부록 — 이번 토론에서 재확인된 "하지 말 것"
- **A를 먼저 하기**: 되돌리기 어려운 큰 IA 변경을 검증 없이 선착수 금지.
- **KBO를 아스날 팬에게 그냥 노출**: 관련성 정렬 없이 "경기 있음"만 채우면 클릭률 안 나옴.
- **"코드 1줄/신규 인프라 0 = 효과 확정"으로 착각**: 구현 비용 낮음 ≠ 효과 있음. 배포와 동시에 클릭률 계측 없으면 "가교 완성" 선언 금지.
- **C를 계측 없이 노출**: 표본 붕괴는 게이팅으로 숨겼어도 매력 미증명. 클릭률 게이트 전엔 잠근다.
