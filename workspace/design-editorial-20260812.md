2026-08-12 · 역할: 편집디자이너

## 0. 들어가기 전에 — 코드에서 발견한 사실 2가지

브리프에 없지만 조판 결정에 직결되는 것이라 먼저 적는다.

**(1) 팀명이 화면에 두 번 인쇄되고 있다.**
`gen-team-news-cards.mjs`가 이미지 정중앙에 "토트넘 / TOTTENHAM"을 굽는다. 그런데 같은 카드
키커에는 `FlairChip`이 "● 토트넘"을 또 찍는다. 즉 **같은 단어가 한 카드에 두 번** 있다.
브리프 5번 "썸네일 파손"은 사실 파손 문제가 아니라 **중복 인쇄 문제**다. 잘려서 안 읽히는 글자는,
애초에 없어도 되는 글자였다. → §4 에서 다룬다.

**(2) `gongnori.fan` 워터마크가 자기 사이트 안에서 돌고 있다.**
같은 파일 `overlay()` 마지막 줄. 이건 OG 공유용 서명인데 자사 피드 썸네일에 들어가 있다.
104px 폭에서는 읽히지도 않는 회색 얼룩이다. 편집물에서 판권 표시를 본문 사진마다 넣지 않는다.

**(3) 원본 아트가 이미 보관돼 있다.** `RAW_DIR = public/images/_news-team-raw`.
주석에 "조판만 바꿀 때 재생성을 피한다"고 적혀 있다. **그러니 비율·조판 변경 비용은 0에 가깝다.**
sharp 재합성만 하면 된다. 이 문서의 썸네일 제안은 전부 API 재생성 없이 실행 가능하다.

## 1. 진단 — 이 카드는 "정보가 많아서" 조악한 게 아니다

정보 9종은 많지 않다. 29CM 상품 카드도 7~8종을 담는다. 문제는 **9종이 전부 같은 목소리로 말하고
있다는 것**이다. 실측 타입을 뽑아보면:

| 요소 | 현재 | 굵기 |
|---|---|---|
| 제목 | 14.5px | 650 |
| 투표 질문 | 11.5px | 700 |
| 투표 버튼 | 11.5px | 700 |
| BEST 라벨 | 11px | 800 |
| 키커(출처·말머리) | 11px | 700 |
| 작성자 | 11.5px | 600 |
| 좋아요/댓글 | 11.5px | 600 |
| 시간 | 11.5px | 500 |
| 투표 안내문 | 10.5px | 400 |
| 타로 훅 | 11.5px | 600 |

**크기 5단계(14.5/12.5/11.5/11/10.5), 굵기 6단계(400~800).** 그런데 실질 대비는 제목 14.5 vs 나머지
11.5 — **고작 3px**. 굵기는 650 vs 700으로 **투표 버튼이 제목보다 굵다.** 시선이 제목에 안 꽂히는 게
당연하다. 위계가 없는 게 아니라, **위계를 11.5px 한 칸 안에서 6번 미세조정하려다 뭉갠 것**이다.

편집물의 원칙: **미세한 차이를 여러 번 주는 것보다, 큰 차이를 세 번만 주는 게 항상 낫다.**

## 2. 도그마 — 모든 변주에 공통 적용 (여기서 벗어나면 그 변주는 폐기)

### 2-1. 타이포는 **3단**. 그 이상은 없다.

| 단 | 스펙 | 담는 것 |
|---|---|---|
| **T1 제목** | `16px / 700 / -0.02em / 1.34` · `--wc-ink` | 제목. 오직 제목. |
| **T2 본문** | `13px / 500 / -0.005em / 1.45` · `--wc-ink-2` | 투표 선택지, 댓글 미리보기 |
| **T3 캡션** | `10.5px / 600 / +0.05em` · `--wc-mute-2` | 키커, 메타, 액션 라벨 전부 |

- 제목을 14.5 → **16px**로 올린다. T1:T3 = 16:10.5 = **1.52배**. 지금 14.5:11.5 = 1.26배로는 부족하다.
  600px 컬럼에서 16px 제목은 절대 크지 않다 — 오히려 지금이 작다.
- **T3는 전부 같은 크기·같은 색이다.** 출처든 시간이든 좋아요든 투표 라벨이든 10.5px `--wc-mute-2`.
  중요한 걸 크게 하는 게 아니라, **중요하지 않은 걸 전부 같은 바닥에 깐다.** 그래야 T1이 뜬다.
- 굵기는 **700 / 500 / 600** 세 개만. 650·800·900 전부 삭제.
  (T3가 600인 건 10.5px에서 500이 흐려지기 때문. 크기가 이미 위계를 만들었으니 굵기로 또 싸울 필요 없음.)
- **버건디는 카드 한 장에 최대 한 번.** 지금은 BEST 라벨·타로 훅·투표 A버튼·오피셜 칩이 전부 버건디다.
  네 번 쓰면 강조가 아니라 배경색이다.

### 2-2. 여백이 유일한 그룹핑 도구다 — 선·박스 금지

**게슈탈트 규칙 하나만 지키면 된다: 그룹 사이 간격 ≥ 그룹 내 최대 간격 × 2.5**

```
키커                     ┐
   ↕ 5px                 │ 그룹 A (출처)
제목 첫 줄               ┘
   ↕ 5px  (행간)
제목 둘째 줄
   ↕ 20px  ← 5 × 4      ═══ 여기가 "경계선"이다. 선을 안 그어도 눈이 끊는다.
메타 · 액션              ┐ 그룹 B
```

- **투표 위젯의 `background` + `border` 를 삭제한다.** (`card-vs-vote.tsx` L138–142)
  카드가 이미 액자다. 액자 안에 액자를 넣는 순간 둘 다 약해진다.
  투표가 하나의 덩어리로 보여야 한다면 **위 여백 20px, 아래 여백 0** 이면 충분하다.
- **`CommentPreview`의 `borderTop: 1px solid --wc-line` 도 삭제.** (L423) 같은 이유.
- **카드 자체의 `--wc-shadow-1` 도 재고 대상.** shadow-1 = `0 1px 3px + 0 0 0 1px --wc-line`.
  즉 **모든 카드가 링(테두리)을 두르고 있다.** 스크롤 한 화면에 링 6~8개가 떠 있으면 목록이 아니라
  타일 더미다. → 대안: 흰 표면 **하나** 위에 카드들을 얹고 사이만 `1px --wc-line` hairline으로 나눈다.
  종이 한 장에 인쇄된 목록이 된다. (변주 E-1·E-3·E-7이 이 방식)
- **간격 스케일은 4의 배수 4종만: `4 / 8 / 20 / 32`.** 12·14·10·6 전부 금지.
  지금 코드엔 `mt-0.5 mt-1 mt-1.5 mt-2 mt-2.5 gap-1.5 gap-3 gap-3.5` 가 섞여 있다 — 8종.
  간격이 8종이면 그룹이 8개로 읽힌다.

### 2-3. 액션은 **한 톤**이다

투표(사각 박스 + 1.5px 보더)와 타로(둥근 pill + 틴트 배경)가 따로 노는 건 브리프 5번 지적 그대로다.
**둘 다 "채움 없는 T3 텍스트 링크"로 통일한다.**

```
현재:  [ 손흥민 잔류 ] [ 이적 ]        ← 1.5px 보더 박스 2개
       ( 🔮 이 이적, 성사될까 )         ← 틴트 pill

제안:  손흥민 잔류  ·  이적            ← 버건디 T3, 채움 없음, hover 시 hairline underline
       이 이적, 성사될까 ›              ← 동일 톤
```

- **이모지 🗳️ 🔮 삭제.** 이모지는 에디토리얼의 반대말이다. 시스템 폰트마다 다르게 렌더되어
  조판이 흔들리고, 11px에서는 색깔 얼룩으로만 보인다. 구분이 필요하면 T3 라벨 `투표` / `타로`.
- **안내문 "첫 표를 던져보세요 · 투표는 로그인 후" 전면 삭제.**
  60장 중 37장에 같은 문장이 반복된다 = 화면당 3~4회. 이건 안내가 아니라 배경 소음이다.
  로그인 안내는 탭한 **후** Clerk 모달이 알려준다 (이미 `clerk.openSignIn()` 호출 중).

### 2-4. 리듬 — "높이가 들쭉날쭉"은 정렬로 못 고친다, **정책으로 고친다**

핵심 사실을 다시 본다: **폴 62% / 미폴 38%.**
즉 투표 카드는 예외가 아니라 **다수**다. "투표 있으면 카드가 커진다"는 규칙은
**전체의 62%를 크게 만든다** — 이건 리듬이 아니라 그냥 두 종류의 목록이 섞인 것이다.

편집물에서 리듬을 만드는 방법은 둘뿐이다:

- **(가) 반복 단위를 고정한다** — 모든 행이 같은 높이. 변화는 4~6행마다 계획된 한 번만.
- **(나) 변주를 규칙화한다** — 1행 대형 / 2행 소형 / 1행 대형 … 예측 가능한 패턴.

**"내용에 따라 높이가 정해진다"는 세 번째 선택지는 편집디자인에 없다.** 그건 조판이 아니라 흘려짓기다.

그리고 참여 실측: **노출 79 → 투표 1 (1.3%)**. 조회 0.57.
**1.3%짜리 기능이 62%의 카드에서 세로 62px을 먹고 있다.** 이건 지면 배분 실패다.
투표는 위젯 자격이 없다. **한 줄** 자격이거나, **아예 지면 밖** 자격이다.
(투표를 버리자는 말이 아니다. 위젯을 버리자는 말이다.)

## 3. 썸네일 비율 — 정사각이다. 그것도 아주 확실히.

결론부터: **목록은 1:1, 편집 삽입면은 3:2. 시스템 전체에 비율은 이 둘뿐.**

**왜 정사각인가**
1. **정사각만이 가변 높이 텍스트와 안 싸운다.** 지금 104×76(1.37:1)은 텍스트 블록이 2줄일 때와
   3줄일 때 옆의 빈 공간이 달라진다. 정사각은 "고정 높이 행"이라는 규칙을 스스로 선언한다.
   행 높이 = 썸네일 변 + 상하 여백. 계산이 끝난다.
2. **1.37:1은 아무것도 아닌 비율이다.** 16:9(영상)도 3:2(사진)도 1:1(판)도 아니다.
   근본 없는 비율은 잘린 것처럼 보인다 — 실제로 잘리기 전에 이미 그렇게 보인다.
3. **작은 면적에서 가로 직사각은 항상 "깨진 TV"로 읽힌다.** 104×76은 영상 썸네일 실패작처럼 보인다.
   같은 면적을 정사각으로 쓰면(90×90) **판(plate)** 으로 읽힌다. 판은 잘려도 판이다.
4. 4:3 은? — 애매하다. 1.37에서 1.33으로 가는 건 아무것도 안 바꾼다.
   세로(4:5)는? — **2단 그리드일 때만** 쓸 만하다(변주 E-6). 1단 리스트에서 세로 썸네일은
   행 높이를 130px+로 밀어올려 스캔 밀도를 죽인다.

**치수 처방**
| 용도 | 비율 | 실제 크기 | 라운드 |
|---|---|---|---|
| 목록 행 | **1:1** | 88×88 (모바일 76×76) | 6px |
| 편집 삽입면 / 히어로 | **3:2** | 컬럼 전폭 × 0.667 | 12px |

라운드는 **6px**. 지금 8px(`rounded-lg`)은 88px 판에서 과하다. 12px 이상은 스티커가 된다.
카드 자체가 `rounded-xl(12px)`인데 그 안에 `rounded-lg(8px)`이 있으면 곡률이 두 번 말한다 —
**안쪽 곡률은 항상 바깥의 절반 이하.**

**크롭 안전 규칙**
1200×630(1.905:1)에서 1:1을 뽑으면 가로 **52%만** 남는다. 지금 파손의 근본 원인이 이거다.
→ **feed용은 raw(1536×1024)에서 직접 1:1로 재합성한다.** 3:2에서 1:1은 67% 유지 — 훨씬 낫다.
   `sharp(raw).resize(512,512,{fit:'cover',position:'center'})`. API 재호출 없음.

## 4. 구단 플레이스홀더 조판 — **텍스트를 굽지 마라**

브리프가 물은 핵심 질문. 답은 명확하다.

### 굽지 않는다. 이미지는 순수 아트, 팀명은 카드 UI가 말한다.

**근거 5개**

1. **이미 카드가 말하고 있다.** `FlairChip`이 "● 토트넘"을 출력 중이다. 이미지에도 "토트넘"을
   구우면 **한 카드에 같은 단어 2회**. 편집에서 이건 교정 대상이지 디자인 선택이 아니다.
2. **구운 활자는 크기에 반응하지 못한다.** `overlay()`의 한글은 1200px 폭 기준 68~118px.
   88px 썸네일에서는 실효 **5~9px**. 크롭을 아무리 잘 잡아도 **원리적으로 못 읽는다.**
   "가운데로 옮겨서 안 잘리게 한다"는 어제의 수정(코드 주석 L99–109)은 잘림은 고쳤지만
   **가독은 못 고친다.** 안 잘린 채로 뭉개질 뿐이다.
3. **활자를 구우면 비율이 잠긴다.** 지금 겪은 그대로다. 텍스트가 없으면 1:1이든 3:2든 4:5든
   같은 raw에서 자유롭게 뽑는다. **조판 자유도를 이미지에 저당 잡히지 않는 것**이 요점이다.
4. **아트가 살아난다.** 프롬프트를 보면 "clean geometric shapes, bold diagonal composition,
   premium sports magazine aesthetic" — 좋은 방향이다. 그런데 그 위에 **중앙 radial 스크림
   (검정 60%)** 을 덮고 있다. 정중앙 60% 검정 = 구도의 심장을 눌러 죽이는 것.
   88px 썸네일에서 보이는 건 **회색 원 하나**다. 스크림 삭제 → 색과 모티프가 즉시 살아난다.
   1:1 88px에서 사람이 인지할 수 있는 건 **색과 형태 한 개**뿐이다. 도르트문트는 노랑, 첼시는 파랑.
   그거면 충분하고, 그게 최선이다.
5. **워터마크는 OG의 몫이다.** 자사 피드에서 자사 도메인을 광고하지 않는다.

### 파이프라인 제안 (raw 1장 → 유도체 2종)

```
_news-team-raw/{id}.png  (1536×1024, 이미 보관 중)
   │
   ├─▶ news-team/og/{id}.webp     1200×630  · 팀명+영문+워터마크 구움 · 카톡/트위터 공유용
   │                               (지금 조판 그대로 유지 — 여기선 텍스트가 옳다)
   │
   └─▶ news-team/feed/{id}.webp    512×512  · 텍스트 0 · 스크림 0 · 순수 아트
                                    카드 썸네일용
```

`gen-team-news-cards.mjs`의 `main()`에서 composite를 2회 돌리는 것으로 끝. 21장 재생성 불필요.
프롬프트에서 한 줄만 바꾼다:
- 삭제: `"Left third must stay visually calm and uncluttered for text overlay."`
- 추가: `"Composition must read clearly when center-cropped to a square."`
(다음 세대 생성 시에만 적용. 기존 raw는 3:2 중앙 크롭으로 충분히 견딘다.)

### 그럼 어느 팀인지는 어떻게 아나?
**이미 알고 있다.** 키커의 말머리 칩 "● 토트넘"이 그 일을 한다.
추가로 원한다면 — 그 칩의 `●` 점을 **구단 컬러**로 칠하면 끝이다(`FlairChip`이 이미
`card.flair.color`를 받고 있다). 색 점 + 팀명 텍스트 + 같은 색조의 아트 썸네일.
**세 신호가 같은 방향을 가리키면 굽지 않아도 즉시 읽힌다.**

### E-1 「인덱스」 — 조용한 목록형

**의도**
액자 60개와 굵기 6종을 버리고, **종이 한 장 위의 목록**을 얻는다. 스캔 속도가 목적.

**구조**
```
┌ 흰 표면 하나 (카드별 shadow/ring 없음, 행 사이 1px --wc-line hairline) ─────────┐
│                                                                                │
│   오피셜 · 토트넘                                            ┌──────────┐      │  ← T3 10.5
│   ↕5                                                        │          │      │
│   손흥민, 토트넘과 재계약 임박… 구단 내부는                   │  88×88   │      │  ← T1 16/700
│   이미 합의 단계                                             │   1:1    │      │
│   ↕20                                                       │          │      │
│   댓글 12 · 3시간                        손흥민 잔류 · 이적   └──────────┘      │  ← T3, 우측 액션
│                                                                                │
├──────────────────────────────────────────────────────────────────────────────┤
│   유력 · 도르트문트                                          ┌──────────┐      │
│   ...                                                                          │
```
- 행 높이 **고정 116px** (썸네일 88 + 상하 14). 제목 2줄 초과 시 `line-clamp-2`.
- 텍스트 열과 썸네일 사이 20px. 좌우 패딩 16px.
- 메타행이 **좌: 사실 / 우: 행동** 으로 갈린다. 시선이 좌→우 한 번만 움직인다.
- 액션 없는 카드(38%)는 우측이 비지만 **높이는 같다** — 그 빈칸이 리듬을 만든다.

**버린 것 (4종)**
`작성자` — 60장 중 대부분 "공놀이봇". 반복 = 정보 0. ※운영자 2026-08-03 요청분이라 승인 필요.
  대안: 사람 작성자만 표시(봇이면 생략) → 오히려 사람 글이 눈에 띈다.
`좋아요` — 로컬 토글 위주라 숫자가 대체로 0. 0을 60번 인쇄하지 않는다. (하트 버튼은 상세로 이관)
`투표 안내문` — 전면 삭제.
`투표 박스` — 위젯 → 텍스트 한 줄로 강등(정보는 유지, 지면만 회수).

**썸네일** 1:1 88px / feed용 무텍스트 아트 / 라운드 6 / `object-position: 50% 50%`
(정사각이면 얼굴 감지 `useFaceFocus` 이득이 줄지만 유지해도 무해)

### E-2 「대수 대비」 — 제목만 크게

**의도**
"중요한 걸 키운다"가 아니라 **"나머지를 전부 최소치로 눌러" 제목 하나만 남긴다.**
읽을거리가 있다는 인상을 만드는 게 목적(체류·신뢰).

**구조**
```
   토트넘                                                    ← T3, 출처 삭제하고 말머리만
   ↕6
   손흥민, 토트넘과 재계약 임박                              ← 17.5px / 700 / -0.025em
   구단 내부는 이미 합의 단계                                   최대 2줄
   ↕22
   3시간 · 댓글 12                              ┌────────┐
                                                │ 80×80  │
   ──────────────────────────────────────────── └────────┘
```
- 제목만 **17.5px**, 나머지 전부 10.5px. 대비 **1.67배**.
- 썸네일을 **80px로 축소**하고 우측 하단 정렬 — 사진이 제목에 종속된다.
  (사진이 크면 사진이 주인공이 된다. 여긴 활자가 주인공.)
- 카드 배경 `--wc-card`, 카드 간 여백 8px, shadow 유지 가능.

**버린 것 (5종)**
`출처` — 말머리와 출처가 나란히 있으면 키커가 두 마디가 되어 T3 라인이 길어진다.
  오피셜만 예외로 남기고(신뢰 신호) 매체명은 상세에서. 티어1(로마노 등)은 제목 앞 `‹로마노›`로 흡수 가능.
`작성자` / `좋아요` / `투표 안내문` (E-1과 동일)
`투표` — **카드에서 완전히 제거.** 대신 5장마다 §E-5 방식의 쟁점 슬롯 1개.
  1.3% 참여에 62%의 지면을 주지 않는다.

**썸네일** 1:1 80px. 무텍스트. 이 안에서는 사진이 "라벨"에 가까워서 정사각이 특히 잘 맞는다.

### E-3 「판(plate)형」 — 큰 정사각 좌측 + 결과 바

**의도**
사진을 **왼쪽 고정 판**으로 세워 리스트에 수직 그리드를 만든다.
투표는 **높이를 0으로** 만들면서 살린다 — 제목 밑 hairline 결과 바.

**구조**
```
┌──────────┐                                                          
│          │   유력 · 토트넘                                    ← T3
│  96×96   │   ↕5
│   1:1    │   손흥민, 토트넘과 재계약 임박… 내부는 합의 단계    ← T1 16/700
│          │   ↕10
└──────────┘   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░  ← 3px 결과 바 (버건디/네이비)
               잔류 61        이적 39            ← T3, 바 양끝 정렬. 탭=투표
               ↕20
               댓글 12 · 3시간
```
- 좌측 96px 판이 **모든 행에서 같은 x좌표에 선다** → 세로 정렬선이 생긴다. 이게 그리드다.
- **결과 바가 곧 투표 UI다.** 좌반 탭=A, 우반 탭=B. 추가 높이 **13px**(바 3 + 라벨 10).
  현재 위젯 62px → **13px, 79% 절감.**
- 총표 <10 이면 바는 50:50 회색 hairline, 라벨만 표시(유령 사이트 방지 규칙 유지).
- 투표 없는 카드는 그 13px이 그대로 여백 → **높이차 13px**. 육안으로 리듬이 안 깨지는 한계치.
- 행 높이 **124px 고정**(96 + 14×2).

**버린 것 (4종)**
`작성자`, `좋아요`, `투표 안내문`, `투표 질문 텍스트`
  ← 질문("손흥민은 잔류할까?")은 대부분 제목의 재진술이다. **선택지 두 개만 남기면 질문은 자명하다.**
    이게 이 안의 핵심 절약. 질문 한 줄(11.5px×2줄 여지)이 사라지는 게 가장 크다.

**썸네일** 1:1 **96px** — 이 안에서만 크게 쓴다. 판이 그리드의 기둥이라 존재감이 필요하다.
무텍스트 아트 + 라운드 6. 96px면 도르트문트 노랑/첼시 파랑이 명확히 읽힌다.

### E-4 「스프레드」 — 얇은 행 + 계획된 대형 삽입

**의도**
"높이가 들쭉날쭉" 문제를 **들쭉날쭉을 규칙으로 만들어** 푼다.
잡지 펼침면 논리: 작은 기사 여럿 + 계획된 큰 사진 한 장.

**구조**
```
   토트넘 · 손흥민, 재계약 임박 내부 합의 단계              댓글12 · 3h   ← 1줄 행, 높이 44px
   ────────────────────────────────────────────────────────────────
   도르트문트 · 벨링엄 이적료 합의 근접                      댓글3 · 5h
   ────────────────────────────────────────────────────────────────
   리버풀 · 살라 거취 이번 주 결정                          댓글8 · 6h
   ────────────────────────────────────────────────────────────────

   ┌──────────────────────────────────────────────────────┐
   │                                                      │   ← 3:2 전폭 판
   │              600 × 400  순수 아트                     │      (4번째마다 1장)
   │                                                      │
   └──────────────────────────────────────────────────────┘
   아스날                                                     ← T3
   외데고르, 시즌 아웃 유력… 아스날 중원 재편 불가피            ← T1 18px
   찬성 · 반대                                    댓글 24 · 1h  ← T3

   ────────────────────────────────────────────────────────────────
   (다시 얇은 행 3개…)
```
- 얇은 행 **44px 고정** · 대형 삽입 **약 300px**. 비율 3:1로 반복.
- 대형 삽입 선정: **댓글 수 최상위** 또는 서버 온도 1위 (이미 온도순 정렬이므로 그룹 내 1위).
- 투표는 **대형 삽입 카드에만** 붙는다 → 62%가 아니라 25%만 투표를 가진다.
  1.3% 참여율이면 노출을 줄이고 자리를 좋게 주는 편이 낫다.

**버린 것 (6종 — 얇은 행 기준)**
`썸네일`(얇은 행에서), `작성자`, `좋아요`, `시간`(→ "3h" 축약만), `투표`(얇은 행), `투표 안내문`
- 얇은 행은 **말머리 · 제목 · 댓글 · 시간** 4종뿐. 한 줄. `truncate`.

**썸네일** 얇은 행 **없음** / 대형 삽입 **3:2 전폭**.
3:2는 raw(1536×1024)와 **정확히 같은 비율** → 크롭 0, 손실 0. 아트가 의도대로 100% 보인다.
텍스트는 굽지 않되, 이 크기에서는 하단 좌측에 카드 UI로 팀명을 올려도 좋다(칩 아님, 순수 활자).

### E-5 「투표 분리」 — 쟁점은 지면 밖으로

**의도**
카드에서 투표를 **완전히 들어내** 모든 행을 동일하게 만들고,
투표는 **한 자리에 모아** 오히려 존재감을 준다. 리듬 문제의 가장 확실한 해법.

**구조**
```
   (E-1 인덱스 행 × 5, 전부 116px 동일 — 예외 0)
   ...
   ...

   ╔══ --wc-soft (#f2efea) 배경 밴드, 좌우 전폭, 상하 24px ══╗
   ║                                                        ║
   ║   오늘의 쟁점                              3            ║  ← T3 + 개수
   ║   ↕14                                                  ║
   ║   손흥민은 잔류할까                                     ║  ← 14px/700
   ║   잔류 61 ─────────────── 39 이적                       ║  ← 결과 바 + 탭
   ║   ↕14                                                  ║
   ║   벨링엄 이적료는 적정한가                              ║
   ║   적정 44 ─────────────── 56 과하다                     ║
   ║   ↕14                                                  ║
   ║   살라 재계약 가능성은                                  ║
   ║   가능 72 ─────────────── 28 불가                       ║
   ║                                                        ║
   ╚════════════════════════════════════════════════════════╝

   (다시 인덱스 행 × 5)
```
- 밴드는 `--wc-soft` 틴트. 🚫다크 규칙상 여기서 다크를 쓸 여지는 있으나(선언 영역), **안 쓴다** —
  라이트 목록 흐름 중간의 다크 블록은 광고로 읽힌다.
- 밴드 하나에 쟁점 3개 = 개별 위젯 3개(186px)가 **하나의 편집 블록(약 200px)**이 된다.
  같은 높이인데 **박스 3개가 블록 1개로** 줄어든 것 — 이게 여백 그룹핑의 힘이다.
- 밴드 배치: 5·13번째(폴 위젯·이적시장 프로모와 충돌 없게 재배치 필요).

**버린 것 (5종)**
`카드 내 투표 전량`, `투표 질문의 카드 중복`, `작성자`, `좋아요`, `투표 안내문`

**썸네일** E-1과 동일 1:1 88px. 밴드에는 썸네일 없음 — **쟁점은 활자의 영역**이다.

### E-6 「캡션형 2단」 — 데스크탑 한정 그리드

**의도**
600px 컬럼을 **2단(290px)** 으로 쪼개, 사진 위·캡션 아래의 고전적 편집 배치.
정보 밀도를 유지하면서 사진을 크게 쓰는 유일한 길.

**구조**
```
┌─────────────────────┐  ┌─────────────────────┐
│                     │  │                     │
│   290 × 290  1:1    │  │   290 × 290  1:1    │   ← 또는 4:5(290×362)
│                     │  │                     │
└─────────────────────┘  └─────────────────────┘
  토트넘                    도르트문트              ← T3
  ↕6
  손흥민, 재계약 임박        벨링엄 이적료 합의       ← T1 15px, line-clamp-2
  내부는 이미 합의 단계      근접… 최종 조율 중
  ↕14
  댓글 12                   댓글 3                  ← T3, 단 하나만
```
- **셀 높이 완전 고정.** 제목 2줄 강제(1줄이어도 2줄 높이 확보) → 그리드가 절대 안 흔들린다.
- 모바일은 1단으로 떨어지되 썸네일을 전폭 1:1로 — 인스타 그리드 문법이라 학습 비용 0.
- 이 안에서만 **4:5 세로**가 유효하다. 2단 그리드에서 세로 사진은 지면을 채우고 잡지처럼 보인다.
  단 스크롤 길이가 40% 늘어난다 — 콘텐츠가 하루 13건이면 오히려 좋다.

**버린 것 (6종)**
`출처`, `작성자`, `좋아요`, `시간`, `투표`(→ E-5 밴드로), `투표 안내문`
- 290px 폭에서 T3 한 줄에 들어가는 건 **말머리 하나, 메타 하나**뿐이다. 물리적 제약이 결정한다.
- 이게 이 안의 미덕이자 위험: **가장 많이 버린다.** 정보 9종 중 3종만 남는다.

**썸네일** **1:1 290px**(안전) 또는 **4:5 290×362**(에디토리얼 최대치).
무텍스트 필수 — 290px에서 구운 글자는 오히려 저품질 스톡 이미지로 보인다.
플레이스홀더가 전면에 나오는 안이라 **아트 품질 의존도가 가장 높다.** 스크림 제거가 전제 조건.

### E-7 「활자판」 — 썸네일을 버린다

**의도**
가장 29CM스러운 대답. **사진이 좋지 않으면 사진을 빼는 게 편집이다.**
플레이스홀더 21종이 반복 노출되는 피드에서 사진은 정보가 아니라 벽지다.

**구조**
```
   ═══ 오늘의 떡밥 ════════════════════════════ 8월 12일 ═══   ← 섹션 헤더 1회

   오피셜 · 토트넘                                     3시간
   손흥민, 토트넘과 재계약 임박… 내부는 이미 합의 단계          ← T1 16/700, 전폭 2줄 가능
   잔류 · 이적                                        댓글 12
   ↕ 28                          ← 카드가 아니라 "항목". 선 없음, 배경 없음.

   유력 · 도르트문트                                    5시간
   벨링엄 이적료 협상 합의 근접, 최종 조율 단계
   댓글 3
   ↕ 28

   ┌────────────────────────────────────────────────────┐
   │            3:2 · 오늘 하나만                        │   ← 하루 1장, 온도 1위
   └────────────────────────────────────────────────────┘
   아스날 · 외데고르 시즌 아웃 유력
   ↕ 28

   토트넘 · 히샬리송 임대 논의 시작                       6시간
   ...
```
- **카드 표면 자체가 없다.** `--wc-paper` 위 활자만. shadow·ring·divider 전부 0.
  그룹핑은 **28px 여백** 하나가 전담한다. (§2-2 규칙: 그룹 내 최대 6px × 4.6배)
- 하루 1장만 사진. 나머지는 활자. **그 1장이 진짜 사진일 때만** 쓴다(플레이스홀더면 그날은 사진 없음).
- 항목 높이 88~104px 변동이지만 **표면이 없으므로 변동이 안 보인다.**
  들쭉날쭉이 보이는 건 상자가 있기 때문이다. 상자를 없애면 문제도 없어진다.
- 가장 큰 리스크: 시각 자극 0. 조회 0.57에서 더 떨어질 수 있다. **다만 브리프의 목표가
  전환이 아니라 "정돈돼 보이는 것"이라면 이 안이 그 목표의 최대치다.**

**버린 것 (5종 + 표면)**
`썸네일`(전량, 하루 1장 예외), `작성자`, `좋아요`, `투표 위젯`(→텍스트 2어절), `투표 안내문`

## 7. 편집디자이너의 추천

**E-5(투표 분리) + E-1(인덱스) 조합을 1순위로 추천한다.**

- E-1이 행을 **116px로 완전히 고정**하고, E-5가 그 고정을 **깨뜨리는 유일한 요소(투표)를 지면 밖으로**
  내보낸다. 둘이 합쳐지면 리듬 문제의 원인이 **구조적으로 제거**된다. 예외가 0이다.
- 브리프 6개 증상 전부 해소: ①액자 이중→투표 밴드 이동 ②위계→3단 타입 ③리듬→고정 116
  ④썸네일→1:1 무텍스트 ⑤액션 톤→텍스트 링크 통일 ⑥안내문→삭제
- 1.3% / 0.57 지표에 정직한 배분: 안 눌리는 것에 62%의 지면을 주지 않되, 없애지도 않는다.

**2순위 E-3(판형).** 투표를 카드에 남겨야 한다면 이게 유일하게 리듬을 지키는 방법이다(±13px).
결과 바가 "질문을 안 하고 결과를 먼저 보여주는" 방식이라 1.3% 참여에서도 화면이 안 비어 보인다.

**한 가지만 고른다면(가장 싼 개선):** 변주와 무관하게 §2 도그마와 §4 썸네일만 적용해도
증상 6개 중 5개가 사라진다. 타입 3단 + 여백 4종 + 투표 박스 제거 + feed용 무텍스트 정사각.
**레이아웃을 안 바꿔도 조판만으로 대부분 해결된다** — 이게 이 진단의 결론이다.

**하지 말아야 할 것 하나:** 투표를 "더 예쁜 박스"로 다시 그리는 것.
지금 조악해 보이는 이유는 박스가 못생겨서가 아니라 **박스가 있어서**다.
