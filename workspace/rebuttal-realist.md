# Realist 반박문 (라운드 2)

## ① 상대 주장 반박

**1. Visionary의 b(매치데이 앵커 스레드) "반나절 스코프" 주장은 구현비용 과소평가.**
픽 분포 바만이면 맞지만, Visionary 본인이 ②에서 제시한 설계는 경기당 게시글 자동 생성 + 라이브 갱신 + 결과 후 자동 코멘트("당신은 소수파")까지 포함한다. 이건 생애주기 관리(생성→갱신→종료) cron이 필요한 신규 서브시스템이다 — 내가 라운드1에서 🟡 Medium으로 분류한 이유. "이미 있는 인프라 조합"이라는 방어는 데이터 소스(betman/wisetoto)에만 해당하고, 생애주기 로직 자체는 새로 만들어야 한다.

**2. Contrarian의 "e는 죽은 것 옆에 죽은 것 붙이는 꼴" 비유는 비용 구조를 무시한다.**
e의 한계비용은 CTA 버튼 1개 + 조인 쿼리 수준이다(뉴스 태깅 인프라는 완성됨). 실패해도 손실이 거의 없는 저비용 실험을 "위험한 결합"으로 묶는 건 과잉 경계다. 문제는 e 자체가 아니라 **반응이 공개로 노출되는 방식**이다 — 이건 ②에서 게이팅으로 해결 가능하지 폐기할 이유는 아니다.

**3. Contrarian의 c(시즌 장기 예측) "병행" 제안은 예산 계산이 안 맞는다.**
c는 신규 예측 타입 + 신규 UI + 9개월 후행 페이오프로, 라운드1에서 내가 🔴 Heavy로 분류한 항목 그대로다. 1인 개발·1개월 예산에 d/e와 "병행"이라 부르기엔 실제 공수가 b보다도 크다. 우선순위에서 빠져야 한다.

## ② 인정할 지점

Contrarian이 옳다: 진성 83명 규모에서 **반응형 UI(이모지, 댓글, 픽 분포 코멘트)는 침묵 자체가 데이터로 노출돼 "죽은 공간" 신호를 스스로 만드는 리스크**가 있고, 이건 board_view 계측이 죽어 있어 내 쪽에서 반박할 실측 데이터가 없다. e를 "저비용이니 그냥 켜자"고 한 내 원래 입장은 이 리스크를 과소평가했다. Visionary의 "9와 1은 자연히 따라온다"는 낙관도 근거 없기는 마찬가지다.

## ③ 최종 가교 권고

**1순위: d(적중카드/개인 리캡)를 단독 우선 배포.** 개인 완결형이라 콜드스타트·침묵 노출 리스크가 없고, 정산 파이프라인(이미 존재)에 훅을 걸어 "이번 주 N전 M적중" 계산 + 기존 웹 알림 채널로 발송하면 된다. 신규 테이블 1개(리캡 로그) + 정산 cron 후처리 로직 정도로 며칠 스코프.

**2순위(조건부): e(뉴스-예측 브리지)는 반응 집계가 최소 임계값(예: 20명) 넘기 전엔 숨기는 게이팅을 넣어 소규모 실험으로 유지.** 이렇게 하면 Contrarian이 지적한 "침묵 노출" 리스크를 제거하면서도 근사비용 0인 재료를 버리지 않는다.

b(앵커 스레드)는 픽 분포 바 vertical slice까지만 이번 사이클에 포함하고 자동 생성 게시글/코멘트는 보류, c는 이번 예산에서 기각한다.
