대상 코드: `components/cardnews/card-news-feed.tsx` · `components/vs/card-vs-vote.tsx` · `scripts/gen-team-news-cards.mjs`

## 0. 먼저: 이건 "조악하다"가 아니라 "예측 불가능하다"

운영자는 보이는 걸 말했지만, 코드를 재보면 시각 문제 밑에 **조작 문제**가 깔려 있다.
같은 자리를 눌렀을 때 카드마다 다른 일이 일어난다.

| 누른 곳 | 투표 카드 | 타로 카드 |
|---|---|---|
| 액션 바로 위 4px | **아무 일도 안 남** (VS 박스가 링크를 덮음) | **기사로 이동** (pill 이 inline 이라 옆·위는 카드 링크) |
| 액션 좌우 여백 | 아무 일도 안 남 | 기사로 이동 |
| 액션 정확히 | 투표 | 타로 |

스크롤하며 훑는 사람은 두 번째 카드에서 이미 학습을 포기한다. 디자인 톤이 다른 게 문제(브리프 #5)가 아니라
**같은 좌표가 카드마다 다른 계약을 갖는 것**이 문제다.

### 0-1. 탭 타겟 실측 (코드에서 계산, 추정 아님)

`ghostAction = "-m-2.5 p-2.5 ..."`, VS 버튼 `compact → px-2 py-1.5 + 1.5px border`, 타로 `px-2.5 py-1` 기준.

| 요소 | 실측 히트 박스 | WCAG 2.5.8 (24px) | iOS HIG (44pt) |
|---|---|---|---|
| 카드 전면 링크 | 전폭 × ~200px | ✅ | ✅ |
| 좋아요 | 52 × **34** | ✅ | ❌ |
| 투표 버튼 | 223 × **30** (600px 컬럼) / 87 × 30 (360px) | ✅ | ❌ |
| 타로 pill | ~110 × **23** | ❌ | ❌ |
| 댓글 펼치기 | 전폭 × **~17** | ❌ | ❌ |

세 액션의 높이가 34 / 30 / 23 으로 전부 다르다. 브리프 #5("톤이 다름")의 뿌리는 장식이 아니라 기하다.

### 0-2. VS 위젯의 65% 는 죽은 면적이다

`CardVsVote` 래퍼가 `pointer-events-auto z-[2]` 로 **박스 전체**를 덮는다. 그런데 실제로 반응하는 건 버튼 30px 뿐이다.

```
박스 총 86px  =  p-2 8 + 질문 16 + mb-1.5 6 + 버튼 30 + mt-1 4 + 안내문 14 + p-2 8
살아있는 면적  =  30px  (34.9%)
먹통 면적      =  56px  (65.1%)  ← 이 영역은 기사 링크까지 막는다
```

즉 카드에서 가장 크고 가장 눈에 띄는 블록이, 눌러도 아무 일 없고 기사로도 못 가는 구멍이다.
참여율 1.3% 의 상당 부분은 "투표를 안 한 것"이 아니라 **"투표를 눌렀는데 안 먹은 것"**일 수 있다.

### 0-3. 높이 분산 = 리듬 파괴의 숫자

- 투표 카드 ≈ **200px** (py 24 + 키커 19 + 제목 40 + 메타 26 + mt 8 + VS 86)
- 타로 카드 ≈ **140px**
- 분산 **+44%**, 그것도 62:38 로 섞여 나온다. 스크롤 스냅 감각이 생길 수가 없다.

### 0-4. 썸네일: 크롭이 문제가 아니라 **글자 크기**가 문제다

104×76(1.368:1) 박스에 1200×630(1.905:1) 을 `object-cover` → 세로 기준 스케일 **0.1206**.

| 원본 조판 | 썸네일 실제 렌더 크기 |
|---|---|
| 팀명 한글 118px | **14.2px** — 겨우 읽힘 |
| 영문 27px + letter-spacing 9 | **3.3px** — 노이즈 |
| 흰 구분바 84×6 | 10×0.7px — 먼지 |
| `gongnori.fan` 25px | **3.0px** — 노이즈 |

가로는 **71.8% 만 생존**(안전 구역 x 169~1031). 브리프의 "구 소식 / 르트문트"는 좌측 정렬이던 1차 조판의 흔적이고,
스크립트는 이미 중앙 정렬로 고쳐졌다(`overlay()` 주석 2026-08-12) — **에셋 재생성만 아직 안 된 상태로 보인다.**

하지만 재생성해도 근본은 안 풀린다. **1200×630 한 장으로 OG(전체 노출)와 104px 썸네일을 동시에 만족시킬 수 없다.**
텍스트 3줄 중 2줄이 4px 이하로 렌더되는 조판을 피드가 계속 실어 나르고 있다.

> 부수 발견: `useFaceFocus` 는 `objectPosition` 의 x 를 20~80% 로 흔든다. 실사진엔 맞지만
> 구단 플레이스홀더에 오탐이 뜨면 팀명이 통째로 잘린다. `/images/news-team/` 경로는 face focus 를 건너뛸 것.

## 1. 관통 원칙 3개 (모든 변주가 지킨다)

**P1 — 링크 위에 버튼을 얹지 말고, 링크 밖으로 내보낸다.**
`absolute inset-0` 전면 링크 + `z-[2] pointer-events-auto` + `stopPropagation` 은 유지 비용이 계속 나가는 구조다.
액션은 **링크 박스의 형제**로 카드 하단에 띠(strip)로 분리한다. z-index 게임도, 데드존도 원천 소멸.

**P2 — 오탭의 비용을 "복구 가능"으로 낮추면 간격은 필요 없다.**
지금 오탭 비용 = 기사로 이탈(뒤로가기 + 스크롤 복원 필요) 또는 먹통(무한 재시도).
띠 안에서 A|B 를 1px 분할선으로 붙이면 오탭 비용 = **반대편에 투표됨 → 한 번 더 누르면 전환**(API 가 이미 전환 지원).
복구 가능한 오탭은 6px 간격보다 안전하다. 간격을 버리고 그 픽셀을 타겟 높이에 준다.

**P3 — 투표 후 카드 높이가 변하면 안 된다.**
탭 직후 손가락은 아직 화면 위에 있다. 높이가 늘면 다음 카드가 손가락 밑으로 밀려온다 — 피드에서 최악의 사고.
현재 `"첫 표를 던져보세요" → "참여 1명 · 62% vs 38%"` 는 길이가 바뀌어 줄바꿈 위험이 있다. 이 줄은 지운다.

## 2. 레이아웃 변주 8종

폭 가정: 데스크탑 카드 내부 가용폭 **568px**(600 − px-4×2) · 모바일 **296px**(360 − 페이지 16×2 − 카드 16×2).
썸네일 옆 텍스트 컬럼은 각각 **452px / 180px**.

### `I-1 하단 액션 띠 (Action Strip)` ★ 본안

**의도** — 액션을 링크 밖 전폭 44px 띠로 내보낸다. **메타 행을 없애고 그 자리에 띠를 넣어**, 타겟은 커지는데 카드는 오히려 66px 짧아진다.

```
┌────────────────────────────────────────────────────┐
│ (py-3)                                             │
│  잭 피트브룩 · 3시간 · 💬4              ┌─────────┐│  키커 11px/700 muted, 1줄
│  토트넘, 손흥민 재계약 협상 교착        │ 104×78  ││  제목 15px/700 lh1.35, 2줄
│  구단은 1년 연장 제시                   └─────────┘│
│ (mt-2)                                             │
├─────────────────────────┬──────────────────────────┤ ← 1px --wc-line, 링크 경계
│         잔류            │          이적            │ ← 44px, 각 half 가 100% 라이브
└─────────────────────────┴──────────────────────────┘ ← 카드 하단 라운드까지 full-bleed
```

- 띠는 **카드 좌우 끝까지 full-bleed**. 가장자리 타겟은 Fitts 상 가장 싸다. 카드 안에 또 카드(브리프 #1)도 자동 해소 — 띠는 프레임이 아니라 받침이다.
- 띠 배경 = `color-mix(--wc-burgundy 3%, transparent)`. 다크 아님, 신규 색 아님.
- 분할선 1px. **간격 0** (P2).
- `:active` 에 배경 −4% 즉시 반응 + `touch-action: manipulation` + tap-highlight 제거. `disabled:opacity-70` 은 삭제(낙관 반영이 이미 피드백).
- 액션 없는 카드도 띠를 유지: `댓글 4개 보기 →` 링크 44px. **모든 카드 동일 높이 = 134px, 분산 0%.**
- 타로 카드: 띠 전체가 `🔮 이 이적, 타로로 봐볼까 →` 한 줄 44px.
- 접근성: `role="radiogroup"` + `role="radio" aria-checked`. DOM 순서가 카드링크 → A → B 라 탭 순서도 자연스럽다.

**버린 것 (4종)**
1. **작성자 "공놀이봇"** — 봇 카드 전부 같은 값. 상수는 정보가 아니고, 진짜 귀속인 출처와 경쟁만 한다. 사람 글에만 표시.
2. **좋아요 버튼** — 34px 오탭 위험을 지고 있는데 조회 0.57 에서 수확이 0. 상세로 이관.
3. **투표 질문 텍스트** — 제목이 이미 맥락이다. "손흥민 재계약 교착" 밑의 `잔류 | 이적` 은 질문 없이 읽힌다.
4. **안내문 2줄** ("첫 표를 던져보세요 · 투표는 로그인 후") — 로그인 상태는 탭했을 때 Clerk 모달이 말해준다. 미리 사과하지 않는다.
   (+ 부가: **VS 박스의 테두리·배경** 삭제 = 이중 액자 소멸)

**썸네일 처리** — 피드 전용 **정사각 400×400 팀 타일 신규 생성, 텍스트 0**.
104px 폭에선 어떤 조판을 해도 글자가 4~14px 로 떨어진다. 팀 식별은 **컬러 필드 + 대형 모티프 1개**가 하고, 팀명은 키커의 말머리 칩이 한다.
기존 1200×630 은 OG·상세 전용으로 그대로 존치(중앙 조판 유지). `gen-team-news-cards.mjs` 에 `--square` 모드 추가, RAW 아트 재사용이라 재생성 비용 없음.
실사진은 현행 유지 + `news-team` 경로 face-focus 스킵.

### `I-2 투표가 곧 게이지 (Gauge-as-Vote)`

**의도** — 98.7% 는 투표하지 않는다. 그들에게도 값을 주려면 **투표 안 해도 읽히는 정보**여야 한다. 위젯을 지우고 게이지 하나만 남긴 뒤, 그 게이지의 좌/우 절반이 투표 버튼이 된다. 정보와 컨트롤이 같은 물체.

```
│  토트넘, 손흥민 재계약 협상 교착        │ 104×104 │
├────────────────────────────────────────────────────┤
│▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│ ← 44px, 채움이 곧 배경
│  잔류  62%                              38%  이적  │    (텍스트는 채움 위에 얹힘)
└────────────────────────────────────────────────────┘
```

- 채움: 좌 `--wc-burgundy 14%`, 우 `#2c4a6e 10%`. 라이트 유지.
- **총 10표 미만 = 채움 없음.** 빈 트랙 + 라벨만. "0표"가 아니라 "두 갈래"로 읽힌다. 유령 사이트 증거를 안 만든다(기존 `SHOW_PCT_MIN_VOTES` 규칙 계승).
- 투표 후: 채움이 실제 비율로 애니메이트(200ms), 내 쪽 라벨에 `✓`, **높이 불변**(P3). 새 픽셀 0.
- 폴 없는 카드는 같은 44px 자리에 타로 바 → 리듬 동일.

**버린 것** — 작성자 · 좋아요 · 질문 · 안내문 · **"참여 N명" 텍스트**(숫자는 게이지가 말한다) · 투표 박스 테두리.

**썸네일 처리** — I-1 과 동일한 정사각 타일이되 **104×104**. 게이지 줄이 붙으면서 텍스트 블록이 3줄로 커지므로 정사각이 세로를 채운다. 1:1 은 팀 타일 재생성 시 크롭 손실 0.

### `I-3 카드는 읽기만, 투표는 상세에서`

**의도** — 카드에서 액션을 전부 걷어낸다. 전면 링크 하나뿐인 카드는 오탭이 원리적으로 불가능하다. 정돈감 최대치.

```
┌────────────────────────────────────────────────────┐
│  🗳 쟁점 · 잭 피트브룩 · 3시간          ┌─────────┐│  키커에 쟁점 배지만
│  토트넘, 손흥민 재계약 협상 교착        │ 104×78  ││
│  구단은 1년 연장 제시                   └─────────┘│
└────────────────────────────────────────────────────┘   높이 112px 고정
```

- `🗳 쟁점` 배지는 **비인터랙티브 텍스트**. 상세로 가면 기존 `VsIssueWidget`(질문·이유 입력 포함 풀 위젯)이 받는다.
- 카드 = 100% 링크. 실수할 좌표가 존재하지 않음.

**버린 것** — 작성자 · 좋아요 · **투표 위젯 전체** · 타로 훅 · 안내문. (9종 중 4종 소멸)

**썸네일 처리** — 카드가 얇아져 78px 유지. 정사각 대신 **4:3 (104×78) 팀 타일** 별도 생성 — 텍스트는 넣되 **팀명 한 줄만, 200px 로 크게**(썸네일 렌더 24px). 영문·구분바·워터마크는 OG 판에만.

**솔직한 평가** — 가장 깨끗하고 가장 안전하지만, 2탭 표면으로 밀면 1.3% 는 사실상 0% 가 된다. **참여를 포기하는 대신 신뢰를 사는 안.** 브리프가 "목표는 전환률이 아니라 정돈"이라 했으므로 진지한 후보다.

### `I-4 2단 탭 (접힘 → 인플레이스 펼침)`

**의도** — 높이 분산을 없애되 투표는 카드 안에 남긴다. 기본은 44px 칩 하나, 누른 카드만 펼쳐진다. **관심 있는 사람만 카드를 키운다.**

```
접힘 (기본, 전 카드 동일)
├────────────────────────────────────────────────────┤
│  🗳 잔류 vs 이적                        62 : 38  ⌄ │ 44px 단일 타겟(전폭)
└────────────────────────────────────────────────────┘

펼침 (탭 후, +44px)
├────────────────────────────────────────────────────┤
│  🗳 잔류 vs 이적                              ⌃    │ 44
├─────────────────────────┬──────────────────────────┤
│         잔류            │          이적            │ 44
└─────────────────────────┴──────────────────────────┘
```

- 접힘 상태의 타겟이 **전폭 × 44px 하나** — 피드에서 가장 놓치기 어려운 형태.
- 펼침은 **아래로만** 자라고 카드 상단은 고정 → 제목이 안 움직인다.
- 투표 후 800ms 뒤 자동 접힘 + 접힘 줄의 숫자만 갱신. 피드가 원래 리듬으로 복귀.
- ⚠️ P3 위반 소지: 펼침이 다음 카드를 밀어낸다. 완화 = 펼치는 순간 그 카드를 뷰포트 상단으로 `scrollIntoView({block:'nearest'})`.

**버린 것** — 작성자 · 좋아요 · 질문 텍스트(라벨 두 개로 대체) · 안내문 · **첫 화면의 투표 버튼 자체**(2탭째로 이연).

**썸네일 처리** — I-1 정사각 타일. 접힘 기준 카드 높이가 134px 로 I-1 과 같아 동일 에셋 재사용.

### `I-5 바텀시트`

**의도** — 카드는 완전히 정적, 액션 칩 하나가 시트를 연다. 시트 안에서는 44px 이상을 마음껏 쓸 수 있다.

```
카드:  … 제목 …
       ├──────────────────────────────┤
       │  🗳 이 쟁점 투표하기      →  │ 44px
       └──────────────────────────────┘
시트:  질문 전문 · 옵션 2~4개 각 56px · 이유 입력 · 결과 게이지
```

**버린 것** — 작성자 · 좋아요 · 카드 안의 질문/버튼/안내문/게이지 전부.

**썸네일 처리** — I-3 과 동일(4:3 팀 타일, 팀명 한 줄 대형).

**판정: 지금은 기각.** 근거 — (a) 스크롤을 끊는 비용이 피드에서 가장 비싸다. (b) 1.3% × 2탭 완주율 ≒ 0.6%, 계측이 불가능해진다. (c) 시트를 열려면 어차피 44px 칩이 필요한데, 그 칩 자리에 그냥 투표를 넣으면(I-1) 1탭이다.
**단, 3지선다 이상 · `allow_reason` 폴은 카드에 못 들어간다** — 그 경우의 유일한 답이므로 폴백으로 보존한다.

---

### `I-6 링크 반전 (제목·썸네일만 링크)`

**의도** — 구조 변주. `absolute inset-0` 을 없애고 **제목과 썸네일만** `<a>` 로 감싼다. 카드 하단 전체가 "링크가 아닌 안전지대"가 되어 무엇을 놓든 오탭이 없다.

```
┌────────────────────────────────────────────────────┐
│  잭 피트브룩 · 3시간                    ┌─────────┐│
│ ╔══════════════════════════════════╗    │▓ 링크 ▓ ││  ╔╗ = <a> 실제 영역
│ ║ 토트넘, 손흥민 재계약 협상 교착  ║    └─────────┘│
│ ╚══════════════════════════════════╝              │
│  ── 안전지대 (링크 아님) ───────────────────────── │
│  [ 잔류 ]  [ 이적 ]            💬4          🔮     │  칩 36px, 여백 자유
└────────────────────────────────────────────────────┘
```

- 제목 링크는 2줄 클램프라 **높이 40px** — 그 자체로 훌륭한 타겟이고, `<h2><a>` 구조라 SEO·가운데클릭·링크복사가 정상 동작(현재 `aria-label` 중복 낭독도 해소).
- 안전지대에는 액션을 여러 개 놔도 서로만 조심하면 된다 → `z-[2]`/`stopPropagation`/`pointer-events` 전부 삭제.
- **비용**: 카드 여백 아무 데나 눌러 기사로 가던 관대함을 잃는다. 링크 면적 200px → 40px+썸네일.
- **I-1/I-2 와 결합 가능** — 사실 이 변주는 "액션 배치"가 아니라 "링크 정의"라, 본안의 하위 옵션으로 채택해도 된다.

**버린 것** — 작성자 · 좋아요 · 질문 · 안내문 · **전면 링크(오탭 원인 자체)**.

**썸네일 처리** — 썸네일이 링크의 일부가 되므로 hover/active 시 4% 딤 필요. 에셋은 I-1 정사각 타일.

---

### `I-7 구단 마크 축소형 (썸네일 문제를 정면으로 지움)`

**의도** — "잘린 글자 조각"의 유일한 확실한 해법은 **자를 게 없게 만드는 것**. 팀 카드일 땐 썸네일을 40×40 원형 마크로 축소하고, 남은 폭 전부를 제목에 준다.

```
┌────────────────────────────────────────────────────┐
│ (●)  잭 피트브룩 · 3시간                            │  ● = 40×40 팀 컬러 원형
│ 40   토트넘, 손흥민 재계약 협상 교착 구단은 1년     │  제목 폭 +104px → 2줄에 더 담김
│      연장 제시                                      │
├─────────────────────────┬──────────────────────────┤
│         잔류            │          이적            │ 44px
└─────────────────────────┴──────────────────────────┘   높이 126px
```

- 실사진이 있는 기사는 기존 104×78 유지 → **"사진 있는 카드 vs 팀 카드"가 시각적으로 구분**된다. 지금은 둘 다 회색 판때기처럼 보여 구분이 안 된다.
- 40px 원형은 크롭 개념이 없다(1:1 소스). 팀 식별 = 컬러 + 모티프 실루엣.

**버린 것** — 작성자 · 좋아요 · 질문 · 안내문 · **팀 카드의 대형 썸네일 슬롯**(9종 중 썸네일을 부분 삭제) · **말머리 칩**(원형 마크가 대신함 — 지금은 썸네일에 "토트넘"이 대문짝만하게 박혀 있는데 옆에 또 "토트넘" 칩을 다는 완전 중복이다).

**썸네일 처리** — 신규 에셋 `news-team/{id}_mark.webp` **96×96, 텍스트 0, 팀 컬러 + 단일 모티프**. 21장 × ~6KB. 1200×630 은 OG 전용 존치.

### `I-8 쟁점 카드 분리 (피드 인터리브)`

**의도** — 62% 에 붙은 폴을 전부 떼어내고, **N장마다 "오늘의 쟁점" 카드 1장**으로 모은다. 뉴스 카드는 전부 동일 높이가 되고(분산 0), 투표는 자기 카드에서 44~56px 을 마음껏 쓴다.

```
[뉴스 카드] 112px
[뉴스 카드] 112px
┌──────── 오늘의 쟁점 ───────────────────────────────┐
│  손흥민, 잔류할까 이적할까?                        │  질문 15px/700 (여기선 살린다)
│ ┌──────────────────┐ ┌──────────────────┐          │
│ │      잔류        │ │      이적        │          │  56px × 2
│ └──────────────────┘ └──────────────────┘          │
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░  62 : 38 · 24명            │
└────────────────────────────────────────────────────┘
[뉴스 카드] 112px
```

- 폴이 **자기 표면**을 가지면 질문·게이지·참여수를 다 보여줘도 노이즈가 아니다(브리프 #6 해소 — 안내문이 카드마다 반복되지 않고 3~4장에 한 번).
- 뉴스 카드는 링크 하나뿐 → I-3 수준의 안전성.
- 리스크: 폴이 기사와 분리되어 맥락이 약해진다. 완화 = 쟁점 카드 하단에 `관련 기사 →` 한 줄.
- 기존 인피드 슬롯(폴 위젯 3번째, 이적 상황판 6번째, 디스코드 9번째)과 **경쟁**한다 — 삽입 슬롯 예산을 다시 짜야 함.

**버린 것** — 작성자 · 좋아요 · 타로 훅 · **뉴스 카드에서 투표 위젯 100% 제거**(가장 큰 삭제).

**썸네일 처리** — 뉴스 카드는 I-1 정사각 타일. **쟁점 카드는 썸네일 없음** — 이미지가 붙으면 또 다른 크롭 문제를 만들고, 질문 텍스트가 주인공이어야 한다.

## 3. 브리프가 물은 4가지에 대한 판정

### Q1. 카드 전체가 링크인데 안에 버튼이 있는 구조 — 오클릭 위험과 해법

**현 구조의 위험은 두 종류이고, 방향이 반대라 더 나쁘다.**
- *먹통형* (투표 카드): 래퍼가 링크를 덮어 65% 가 죽은 면적. 눌러도 아무 일 없음.
- *이탈형* (타로 카드): pill 이 `inline-flex` 라 주변이 전부 링크. 조준 실패 = 기사로 튐.

같은 세로 좌표가 카드에 따라 다르게 동작 → **모델 학습 불가**.

**해법 순위**
1. **물리적 분리 (P1).** 액션을 링크의 자식이 아니라 형제로. `z-index`·`pointer-events`·`stopPropagation` 이 전부 필요 없어진다. → I-1 / I-2 / I-4 / I-8
2. **링크 축소 (I-6).** 제목+썸네일만 링크. 하단은 통째로 안전지대. 관대함을 잃는 대신 구조가 정직해진다.
3. **액션 제거 (I-3).** 가장 확실. 참여를 포기하는 값을 치른다.

세 가지 다 "덮기 싸움"을 하지 않는다는 점이 공통이다. **`stopPropagation` 이 필요한 레이아웃은 이미 진 레이아웃이다.**

### Q2. 44px 최소 타겟 vs 카드 밀도 — 둘 다 되는 배치가 있는가

**있다. 타겟을 키우는 게 아니라 행을 합치면 된다.**

지금 카드 하단엔 두 개의 행이 있다: 메타 행(작성자·좋아요·댓글·시간, 시각 ~26px) + 액션 블록(VS 86px 또는 타로 23px). 합 **~112px**, 그런데 그중 실제 타겟은 30px.

이 둘을 **하나의 44px 띠**로 병합하고 메타를 키커 줄로 올리면:

| | 현재 | I-1 |
|---|---|---|
| 투표 카드 높이 | 200px | **134px** (−33%) |
| 타로 카드 높이 | 140px | **134px** |
| 높이 분산 | +44% | **0%** |
| 최소 타겟 높이 | 23px | **44px** |
| 데드존 | 56px | **0px** |
| 1화면(844pt) 카드 수 | 4.2장 | **6.3장** |

**밀도가 올라가면서 타겟이 커진다.** 트레이드오프가 아니었다 — 지금 쓰고 있는 픽셀의 대부분이 타겟이 아니라 액자·질문·안내문이었을 뿐이다.

전제 조건 두 가지:
- 띠는 **full-bleed** 여야 한다. 좌우 패딩 안에 갇히면 가장자리 타겟의 이점을 잃는다.
- 띠 안 요소는 **`h-full`** 로 띠를 꽉 채운다. 칩을 36px 로 두고 4px 여백을 남기면 그 4px 이 다시 데드존이 된다.

### Q3. 투표를 "카드 안에서" 하는 게 맞는가

**맞다. 단 "위젯"이 아니라 "행"으로. 그리고 정당성은 참여가 아니라 정보에서 나온다.**

- 2탭 표면(시트·펼침)은 1.3% 에서 산술적으로 죽는다. 완주율 50% 가정 시 0.6%, 계측 유의성도 사라진다.
- 반대로 in-card 의 유일한 정당성은 **투표하지 않아도 얻는 것**이다. 지금 위젯은 0표라 %도 숨기므로 98.7% 에게 **순수 비용**(86px + 데드존)이다. 그래서 지금은 "카드 안이 틀렸다"가 아니라 **"카드 안에 놓을 자격이 없는 형태"**인 것이다.
- 게이지형(I-2)으로 바꾸면 미투표자에게도 "여론이 62:38 로 갈렸다"는 읽을거리가 남는다. 그 순간 in-card 가 정당해진다.

**카드 안에 넣지 말아야 하는 경우 (명시적 예외)**
- 옵션 3개 이상 → 44px 띠에 못 들어간다 → I-5 시트
- `allow_reason` 이 켜진 폴 → 텍스트 입력은 피드에 절대 금지 → 상세
- 질문이 제목에서 유추 불가능한 폴 → 질문을 지울 수 없으므로 I-8 쟁점 카드

### Q4. 투표 완료 후 상태를 카드에서 어디까지 보여줄 것인가

**세 가지만. 그리고 셋 다 새 픽셀을 쓰지 않는다.**

1. **내 선택 반전** — 고른 쪽 반쪽이 채워지고 라벨 앞에 `✓`. (기존 배경 교체, 0px)
2. **게이지 채움** — 트랙이 실제 비율로 200ms 애니메이트. 트랙은 원래 있었다. (0px)
3. **퍼센트** — 라벨 반대편 끝에 우측 정렬로 등장. 띠 안. (0px)

**보여주지 않는 것**
- "참여 24명" 별도 줄 → 게이지가 이미 말한다. 그리고 24명은 자랑거리가 아니다.
- 토스트/스낵바 → 피드에서 뜨는 오버레이는 다음 탭을 가린다.
- "투표 완료!" 확인 문구 → 상태 변화 자체가 확인이다.
- **10표 미만일 때의 퍼센트** — 1표가 100% 로 그려지는 건 유령 사이트 증거다. 기존 `SHOW_PCT_MIN_VOTES = 10` 유지.

**불변 조건**: 위 3개 중 어느 것도 **높이·줄바꿈을 바꾸지 않는다**(P3). 퍼센트는 라벨과 같은 줄, 폭 고정(`tabular-nums`, 3자리 예약).

추가로 — 미투표 상태에서 총 10표 미만이면 **채움 없는 빈 트랙 + 라벨만**. "0표"가 아니라 "두 갈래"로 읽히게. 지금의 `첫 표를 던져보세요` 는 빈 데 대한 사과인데, 사과는 빈 것을 더 크게 만든다.

### Q5. 모바일(전체폭) / 데스크탑(600px) 동일 구조 성립 여부

**성립한다. 단 라벨 길이 한 가지가 유일한 파열점이다.**

| | 모바일 360 | 데스크탑 600 |
|---|---|---|
| 카드 폭 | 328 | 600 |
| 텍스트 컬럼(썸네일 옆) | 180 | 452 |
| **전폭 띠 폭 (I-1)** | **328** | **600** |
| 띠 반쪽(투표 1개) | **164** | **300** |
| 라벨 가용 (padding 24 제외) | **140px ≈ 한글 9자** | 276px ≈ 18자 |

**결정적 포인트**: 액션을 텍스트 컬럼 안에 두면 모바일 반쪽이 **87px(한글 5자)** 로 무너진다 — 현재 구조가 딱 이렇다. **띠를 전폭으로 빼는 순간 164px 로 거의 2배가 된다.** 즉 full-bleed 띠는 미학이 아니라 모바일 생존 조건이다.

그래도 남는 제약:
- **라벨 상한 8자.** 데이터 레벨에서 강제(`aLabel`/`bLabel` 생성 시 8자 컷). "손흥민 잔류" → "잔류". 두 라벨의 공통 접두어 제거 규칙을 넣으면 대부분 자동 해결된다.
- 9자 초과가 불가피하면 그 폴은 **카드에서 제외 → I-8 쟁점 카드**로 라우팅.
- 데스크탑 300px 반쪽은 과하게 넓다 → 라벨을 좌우 끝이 아니라 **각 반쪽의 중앙 정렬**로 두면 두 라벨이 시선 안(약 200px 간격)에 함께 들어온다.
- 세로 44px 은 두 폭에서 동일 — 데스크탑 마우스에서도 44px 은 손해가 아니다.

## 4. 추천

**본안: `I-1 하단 액션 띠` + `I-2 게이지` 결합.**
띠 구조(I-1)가 오탭·밀도·리듬을 동시에 해결하고, 게이지(I-2)가 미투표자 98.7% 에게 값을 준다.
`I-6 링크 반전`은 옵션으로 얹으면 z-index 코드를 완전히 지울 수 있다.

**보험**: 옵션 3개 이상·이유 입력 폴은 `I-5 시트`로 폴백, 라벨 9자 초과 폴은 `I-8 쟁점 카드`로.

**착수 순서 (각 단계가 독립적으로 배포 가능)**
1. **삭제만 먼저** — 작성자·좋아요·질문·안내문·VS 박스 테두리. 코드 순삭, 카드 200→150px. 여기까지만 해도 "조악함"의 절반이 사라진다.
2. **띠 분리** — `CardAction` 을 `<article>` 직속 형제로 이동, 44px full-bleed. `z-[2]`/`pointer-events-auto`/`stopPropagation` 삭제.
3. **게이지 형태로 전환** — `CardVsVote` 에 `variant="strip"` 추가(모달용 기존 형태 보존).
4. **정사각 팀 타일 21종 생성** — `gen-team-news-cards.mjs --square`, RAW 아트 재사용이라 이미지 API 재호출 없음.

**검증 (디자인 승인과 별개로 반드시)**
- 데드존 0 확인: 띠 영역 임의 좌표 20곳 탭 → 전부 투표 또는 전부 타로. "아무 일도 안 남" 0건.
- 레이아웃 시프트: 투표 전후 카드 `getBoundingClientRect().height` 동일.
- 타겟 감사: Playwright 로 모든 인터랙티브 요소 높이 ≥ 44 assert (회귀 방지용 테스트로 고정).
- 썸네일: 정사각 타일 21장을 104px 로 렌더한 스크린샷 시트 — 색만 보고 팀을 구분할 수 있는지 육안 확인.

## 5. 코드에서 지금 바로 고칠 것 (디자인 결정과 무관한 명백한 결함)

1. `CardVsVote` 래퍼의 `pointer-events-auto` 가 버튼 아닌 영역까지 링크를 막는다 → 래퍼는 `pointer-events-none`, 버튼만 `auto`. **한 줄로 데드존 56px 이 링크로 복구된다.**
2. 타로 pill 높이 23px — `py-1` → `py-2.5` + `min-h-[44px]`. WCAG 2.5.8 위반 상태.
3. 댓글 펼치기 버튼 높이 ~17px — 패딩 없음. 접근성 감사에서 바로 걸린다.
4. `useFaceFocus` 를 `/images/news-team/` 경로에서 스킵. 오탐 1회에 팀명이 통째로 잘린다.
5. VS 버튼 `disabled:opacity-70` 제거 — 낙관 반영이 이미 즉시 피드백인데 딤이 겹쳐 "실패한 것처럼" 보인다.
6. `:active` 스타일 부재 + `touch-action: manipulation` 미설정 — 탭 직후 무반응 구간이 체감된다.
7. `aria-pressed` 2개 → `role="radiogroup"` + `aria-checked` (단일 선택 의미가 맞다).
8. 전면 링크 `aria-label={card.title}` 과 `<h2>` 가 제목을 두 번 낭독한다.
