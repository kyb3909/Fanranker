# 정보구조(IA) 관점 — 떡밥 피드 카드 (2026-08-12)

역할: IA. 내 일은 배치를 예쁘게 만드는 게 아니라 **무엇을 지울지 정하는 것**이다.
모든 요소에 같은 질문을 던졌다 — "이게 없으면 사용자가 무엇을 못하는가."
답이 없으면 지운다.

---

## 0. 전제 — 이건 레이아웃 문제가 아니다

브리프는 "디자인이 조악해졌다"로 시작하지만, 코드를 읽고 나니 증상 6개가
전부 같은 원인 하나에서 나온다:

> **카드가 "이 글에 대해 알 수 있는 것"을 전부 담는 그릇이 되었다.**
> 담을 이유는 매번 있었고(운영자 요청·워룸 결정·참여 실험), 뺄 이유는 한 번도
> 검토되지 않았다.

코드 주석이 그 역사를 그대로 보존하고 있다 — 2026-07-28 오버레이 통일,
07-30 좋아요 서버 동기화, 07-31 인카드 투표, 08-03 글쓴이 추가, 08-12 타로.
**추가만 6번, 삭제는 0번.** 레이아웃을 아무리 다시 짜도 11종을 600px 안에
넣는 한 같은 결과가 나온다.

그리고 브리프가 센 것보다 실제로는 **2종이 더 있다**(코드 실측):

| # | 요소 | 브리프 | 코드 |
|---|---|---|---|
| 10 | 댓글 미리보기 (BEST 한 줄 + 펼침) | 누락 | `CommentPreview` — 구분선 + 접힘/펼침 |
| 11 | 유튜브 재생 뱃지 (썸네일 위 원형) | 누락 | `card.media.provider === "youtube"` |

즉 **9종이 아니라 11종**이다. 세는 것부터 틀렸다는 게 이 문제의 크기를 말해준다.

## 1. 심문 — 요소별 "지웠을 때 잃는 것"

각 항목은 한 줄로 답한다. 답이 "없음"이거나 "다른 데서 이미 말한다"면 삭제 대상이다.

| 요소 | 지웠을 때 잃는 것 | 판정 |
|---|---|---|
| **① 출처** (잭 피트 브룩) | 매체명 자체는 **아무것도 안 잃는다** — 한국 사용자에게 "잭 피트 브룩"은 문자열이다. 잃는 건 *티어*("오피셜인가")뿐. | **반쪽 삭제**: 티어만 남기고 매체명 삭제 |
| **② 말머리** (토트넘) | 자기 팀 소식을 훑어 고르는 능력. 다만 봇 제목이 `[출처] 주어, 서술` 꼴이라 **주어가 팀명인 경우 제목과 100% 중복**. | **조건부 삭제**: 제목 앞부분에 팀명이 있으면 칩 제거 |
| **③ 제목** | 전부. 카드에서 유일하게 "무슨 일이 났는지"를 말하는 요소. | **불가침** |
| **④ 작성자** (공놀이봇) | **아무것도 안 잃는다.** 피드는 `NEWS_BOT_USER_ID` 단일 계정만 조회한다(`cardnews.ts:59,93`). 60장 전부 같은 값 = **정보량 0비트**. | **삭제 1순위** |
| **⑤ 좋아요** | 마찰 없는 반응 장치 하나. 그러나 값은 사실상 0이고, 무엇보다 **"카드당 액션 하나" 규칙을 이 하트가 이미 어기고 있다**(투표/타로 + 하트 = 둘). | **삭제**, 상세로 이동 |
| **⑥ 댓글수** | 논쟁이 붙었는지. 다만 현재 코드는 0일 때 **숫자만 숨기고 아이콘은 남긴다**(`commentCount > 0 && <span>`) → 대부분 카드에 **빈 말풍선 아이콘**이 떠 있다. 의미 없는 기표. | **조건부**: 0이면 아이콘까지 제거 |
| **⑦ 시간** | "방금 건가?" 그런데 피드는 **24h 창 + 순수 최신순**(`cardnews.ts:96,104`)이다. 전부 하루 안쪽이고 **순서가 이미 시간을 말한다**. 카드마다 반복할 이유가 없다. | **삭제**, 피드 구분선으로 이동 |
| **⑧ 투표 위젯** | 이건 하나가 아니라 **네 부속**이다 — ⓐ프레임(배경+테두리) ⓑ질문 ⓒ버튼2개 ⓓ안내문. 잃는 건 ⓒ뿐. ⓐ는 액자 이중화의 범인, ⓑ는 축약 가능, **ⓓ는 순삭**(아래 참조). | **3/4 삭제**, 버튼만 생존 |
| **⑨ 썸네일** | 스캔 앵커. 단 **실사진일 때만.** 구단 플레이스홀더는 정보량 0인 장식이 증거인 척하는 것(§4). | **이원화**: 사진만 유지 |
| **⑩ 댓글 미리보기** | 공방 맛보기. 그러나 `commentCount > 0`인 카드가 극소수라 대부분 렌더 안 됨 → **있는 카드만 혼자 키가 커져 리듬을 또 깬다.** | **삭제**, 상세로 |
| **⑪ 유튜브 재생 뱃지** | 28px 원 안의 재생 아이콘 — "영상이다". 썸네일이 이미 유튜브 썸네일이라 중복도가 높다. | **삭제 가능** (낮은 우선순위) |

### ⓓ 안내문은 왜 순삭인가 — 코드가 자기모순이다

```ts
// card-vs-vote.tsx:28
/** 소표본에 % 를 숨기는 하한 — 1표가 "0% vs 100%" 로 그려지면 유령 사이트 증거가 된다 */
const SHOW_PCT_MIN_VOTES = 10
```

10표 미만이면 %를 숨기는 이유가 "유령 사이트로 보이지 않기 위해"다. 그런데 같은
컴포넌트 6줄 아래에서:

```ts
{total === 0 ? "첫 표를 던져보세요" : ...}
{!isSignedIn && " · 투표는 로그인 후"}
```

참여 1.3%면 **거의 모든 카드가 `total === 0`** → 피드를 내리는 내내
"첫 표를 던져보세요"가 반복된다. 이건 *아무도 안 눌렀다는 사실을 카드마다 광고*하는 것이다.
%를 숨긴 그 판단과 정면 충돌한다.

"투표는 로그인 후"도 마찬가지다. 코드는 이미 비로그인 클릭 시
`clerk.openSignIn()`을 띄운다(`card-vs-vote.tsx:68`). **모달이 말해줄 것을 미리 예고할
이유가 없다.** 사전 고지는 마찰을 줄이지 않고 밀도만 올린다.

→ **안내문 한 줄 삭제로 카드당 텍스트 1행 + 여백 2곳이 사라진다.** 비용 0, 손실 0.

## 2. 삭제 후보 순위

지울 순서. 위에서부터 자르면 어디서 멈춰도 카드가 성립한다.

| 순위 | 대상 | 근거 | 잃는 것 | 되돌리기 |
|---|---|---|---|---|
| 1 | **작성자 "공놀이봇"** | 60/60 동일값. 정보량 0비트 | 없음 | 쉬움 |
| 2 | **투표 안내문** | 코드 자기모순(§1). 상호작용 전엔 0비트 | 없음 | 쉬움 |
| 3 | **투표 위젯 프레임** | "카드 안에 또 카드" 증상 1의 직접 원인 | 경계 인지 → 여백으로 대체 | 쉬움 |
| 4 | **시간** | 24h 창 + 최신순이 이미 표현. 카드 60장에 60번 반복 | 정밀 시각 → 구분선이 대체 | 쉬움 |
| 5 | **좋아요 (하트)** | 값 0 + "액션 하나" 규칙 위반 | 최저마찰 반응점 1개 | 중간 |
| 6 | **출처의 매체명** | 상세 본문 **첫 문장이 이미 "~보도에 따르면"으로 귀속**한다(드라이 톤 규칙). 100% 중복 | 티어 미달 기사의 출처 인지 | 쉬움 |
| 7 | **댓글수(0일 때 아이콘까지)** | 빈 기표 제거 | 없음 | 쉬움 |
| 8 | **댓글 미리보기** | 소수 카드만 렌더 → 리듬 파괴 기여 | 공방 맛보기 | 중간 |
| 9 | **말머리(제목과 중복 시)** | 봇 제목 형식상 상당수 중복 | 없음(중복분만) | 쉬움 |
| 10 | **플레이스홀더 썸네일** | 정보량 0인 장식(§4) | 시각 리듬 → 다른 기표로 | 중간 |
| — | **제목** | — | 전부 | **불가** |

**1~4번만 지워도 카드당 텍스트 3행·박스 1개가 사라진다.** 이게 브리프 증상
1·2·3·6을 동시에 없앤다. 레이아웃을 다시 그리기 전에 이것부터 해야 한다.

## 3. 이동표 — 지우는 게 아니라 옮기는 것

"삭제"가 무섭다면 대부분은 **삭제가 아니라 이사**다. 다만 이사 갈 집이
이미 있는지를 확인해야 이사지, 없으면 그냥 유기다. 확인했다.

| 요소 | 카드에서 | 어디로 | 그 집이 이미 있나 |
|---|---|---|---|
| 매체명 | 제거 | 상세 본문 첫 문장 | **있다** — 드라이 톤 규칙이 "누구 보도에 따르면"을 강제 |
| 작성자 | 제거 | 피드 상단 한 줄 ("AI 뉴스룸이 모은 오늘의 소식") | 신설 1회 (카드 60회 → 1회) |
| 시간 | 제거 | 피드 구분선 (`오늘 오전` / `어젯밤`) | 신설 — 카드 60개당 구분선 3~4개 |
| 좋아요 | 제거 | 상세 하단 | **있다** — `/api/posts/[id]/vote` |
| 댓글수 0 | 제거 | 없음(0은 정보가 아니다) | — |
| 댓글 미리보기 | 제거 | 상세 `#comments` | **있다** |
| 투표 %·총표 | 제거 | 투표 **직후 인라인**으로만 노출 | 부분 — 클릭 후 같은 자리에서 버튼→결과 전환 |
| 투표 질문 | 축약 | 상세 `VsIssueWidget` 이 전문 보유 | **있다** — 별개 컴포넌트로 이미 존재 |
| 안내문 | 제거 | Clerk 모달 | **있다** — `clerk.openSignIn()` |

**호버로 옮기는 안은 반대한다.** 실측 62%가 투표 카드고 주력 디바이스가
모바일이다(코드가 `lg:hidden` 인피드 슬롯을 쓰는 이유). 호버는 모바일에 없는
표면이라 "옮겼다"가 아니라 "모바일에서만 지웠다"가 된다. 두 플랫폼이 다른
정보를 보는 건 IA 실패다.

**펼침(accordion)도 반대한다.** 이미 `CommentPreview`가 펼침이고, 그게 카드
높이를 가변으로 만들어 리듬을 깨는 원인 중 하나다. 문제를 만든 장치로 문제를
풀 수 없다.

→ 남는 건 **상세 페이지**와 **피드 레벨(구분선·헤더)** 두 곳이다. 이 둘로 충분하다.

## 4. 썸네일 — 비율을 바꿔도 안 고쳐진다

브리프는 "1.37:1 안에서 1.90:1이 좌우 14%씩 잘린다"고 했다. 맞다. 계산도 맞다
(스케일 76/630 = 0.1206 → 표시폭 상당 원본폭 104/0.1206 = **862px**, 1200-862=338,
좌우 각 **169px = 14.1%**). 생성 스크립트 주석이 같은 숫자를 이미 적어뒀다
(`gen-team-news-cards.mjs:102` — "안전 구역 x 169~1031").

### 4-1. 비율만 바꿨을 때

| 표시 비율 | 크기 | 원본 보존 | 좌우 손실 |
|---|---|---|---|
| 1.37:1 (**현재**) | 104×76 | 71.8% | 각 14.1% |
| 1.5:1 | 104×69 | 78.8% | 각 10.6% |
| **1.78:1 (16:9)** | 104×58 | **93.3%** | 각 3.3% |
| 1.905:1 (원본과 동일) | 104×55 | 100% | 0 |

**즉 썸네일을 더 납작하게 만들면 크롭이 거의 사라진다.** 지금은 정사각에
가까워지려다 잘리고 있다. 16:9로만 바꿔도 손실이 14.1% → 3.3%로 떨어진다.
이건 CSS 한 줄이다.

⚠️ 반대 방향(1:1 정사각 80×80)은 **더 나쁘다** — 좌우 각 23.8% 손실. "정사각이
정돈돼 보인다"는 직관을 따르면 문제가 악화된다.

### 4-2. 그런데 그게 근본 원인이 아니다

진짜 원인은 이거다:

> **1200×630 한 장으로 og 이미지·히어로·썸네일을 전부 덮으려 한 것.**

세 표면의 요구가 다르다 — og는 가로형 + 큰 글자, 히어로는 가로형 + 아트,
썸네일은 104px 폭에서 **한 단어가 읽혀야** 한다. 한 장으로는 불가능하다.

다행히 **재생성 비용이 0이다.** 스크립트가 원본 아트를 `public/images/_news-team-raw/`
에 이미 보관하고 있다(`gen-team-news-cards.mjs:151` — 1차 때 합성본만 저장했다가
21장을 다시 생성해야 했던 교훈). **조판만 다시 얹으면 된다.**

### 4-3. 제안 — 파생 2종

| 용도 | 크기 | 조판 |
|---|---|---|
| og / 히어로 | 1200×630 (현행) | 현행 유지 (중앙 팀명 + 영문 + gongnori.fan) |
| **피드 썸네일 (신규)** | **416×234 (16:9)** | 아트를 **버리고** 팀 컬러 단색 + 팀명 한 단어. 영문·사이트마크·구분선 전부 제거 |

104px 폭에 표시될 이미지에 아트·영문·사이트마크·구분선 4겹을 넣는 건 실패가
예정돼 있다. 104px에서 살아남는 건 **색 하나 + 단어 하나**뿐이다.

### 4-4. 더 나아간 안 — 플레이스홀더 썸네일을 아예 없앤다

플레이스홀더는 **이 기사에 대해 아무것도 말하지 않는다.** 사진은 증거지만
플레이스홀더는 장식이고, 그게 사진 자리에 앉아 있으면 증거인 척한다.

게다가 코드를 보면 플레이스홀더의 실제 역할이 드러난다:

```ts
// cardnews.ts:118
cards: cards.filter((c) => !!c.image),   // 사진 없는 글은 떡밥에서 배제
```

**플레이스홀더는 정보가 아니라 피드 진입 자격을 통과하기 위한 장치다.**
게이트 해킹이 화면 절반을 차지하고 있다.

→ 대안: 플레이스홀더 카드는 썸네일을 **비우고** 팀 컬러 칩(말머리 도트)만 남긴다.
그러면 **사진 있는 카드가 진짜로 눈에 띈다** — 지금은 모든 카드에 이미지가
있어서 이미지가 신호 역할을 못 한다.

⚠️ 좌측 컬러 보더는 쓰지 않는다(영구 금지 규칙). 팀 색은 **칩 안의 도트**와
**카드 배경 틴트**로만 표현한다.

## 5. 투표 카드는 별도 컴포넌트인가

**아니다. 같은 틀의 변주여야 한다.** 그리고 지금 리듬이 깨지는 건 설계 실수다.

### 근거 — 62:38은 편집 의도가 아니라 파이프라인 사정이다

투표가 붙는 기준은 `confidence >= 0.7`인 활성 폴이 있는가다
(`cardnews.ts:394`). 즉 **"이 기사가 더 중요해서" 투표가 붙은 게 아니라
"폴 생성기가 이 기사에서 쟁점 추출에 성공해서"** 붙었다.

사용자에게 이 둘은 **같은 종류의 물건**(오늘의 축구 소식)이다. 시스템 내부
사정을 사용자가 시각적 위계로 읽게 만드는 것 — 이게 IA 실패의 교과서적 정의다.
지금 피드는 "폴 추출 성공/실패"를 카드 높이 차이로 방송하고 있다.

### 해법 — 액션 슬롯을 규격화한다

```
[ 카드 = 고정 골격 ]
  칩 행       (24px 고정)
  제목        (2행 고정, line-clamp-2, min-height 로 1행 글도 2행분 차지)
  액션 슬롯   (32px 고정) ← 여기에 셋 중 하나가 들어간다
                ├ 투표: [A] [B]  두 pill 나란히
                ├ 타로: [ 이 이적, 카드는 뭐라고 할까? ] pill 하나
                └ 없음: 빈 32px (여백으로 남긴다 — 접지 않는다)
```

핵심은 **"없음"일 때도 32px을 남기는 것**이다. 슬롯을 접으면 높이가 다시
갈라진다. 32px 여백 하나가 아까워서 리듬을 포기하는 건 나쁜 거래다.

이것 하나로 브리프 증상 **3(리듬 파괴)·5(톤 불일치)·1(액자 이중화)**이 동시에
해결된다 — 투표가 프레임 없는 pill 2개가 되면 타로 pill과 같은 언어가 되고,
프레임이 없으니 액자도 안 겹치고, 높이가 같으니 리듬도 산다.

### 위계 붕괴(증상 2)는 슬롯이 규격화된 뒤에 자동으로 풀린다

현재 제목 14.5px/650 vs 투표 버튼 11.5px/700 — 무게가 거의 같다.
투표를 **프레임 없는 텍스트 pill**로 낮추면(11.5px/600, 배경 틴트만),
제목을 16px/700로 올릴 여지가 생긴다. 카드에서 3~4종을 지웠으니 그 공간이 있다.

## 6. 피드에 여러 종류가 섞일 때 — 최소 장치

현재 피드에 섞이는 것: 뉴스 카드 · `PollWidget`(3번째 뒤) ·
`TransferPromoCard`(6번째 뒤) · `DiscordInviteBanner`(9번째 뒤).

### 하지 말아야 할 것

**뉴스 카드끼리 종류 뱃지를 다는 것.** "투표", "타로", "속보" 같은 레이블을
붙이면 카드당 요소가 다시 +1이고, 액션 슬롯이 이미 그걸 보여준다
(투표 버튼이 보이면 투표 카드다). **같은 것을 두 번 말하지 않는다.**

### 최소 장치 — 이진 규칙 하나

> **카드 형태(흰 배경 + shadow-1 + radius) = 기사.**
> **기사가 아닌 것은 카드 형태를 쓰지 않는다.**

프로모·폴·디스코드는 **그림자를 버리고** 종이색(`--wc-paper`) 배경 위에
얹는다. 그러면 카드가 아니라 "피드 사이의 삽입물"로 읽힌다. 레이블도, 아이콘
범례도, 색 코딩도 필요 없다 — **높이(elevation) 하나가 종류를 가른다.**

현재 `TransferPromoCard`는 `background: var(--wc-card)` + `boxShadow: var(--wc-shadow-1)`
로 **기사 카드와 완전히 같은 표면**을 쓰고 있다(`card-news-feed.tsx:279`).
사용자가 기사인 줄 알고 누르면 프로모다. 이건 밀도 문제가 아니라 신뢰 문제다.

| 무엇 | 표면 | 그림자 |
|---|---|---|
| 기사 카드 | `--wc-card` (흰) | shadow-1 |
| 프로모 / 폴 / 디스코드 | `--wc-paper` (종이) | **없음** |
| 시간 구분선 | 배경 없음, 텍스트만 | 없음 |

⚠️ 다크는 쓰지 않는다. 밴드·푸터 같은 선언 영역이 아니라 목록 안이다.

## 7. 레이아웃 변주 8종

A-1은 종합안, A-2~A-8은 **각각 한 가지 삭제를 극단까지 민 것**이다.
직교하는 것끼리는 조합 가능(§8 매트릭스).

공통 전제: 브리프 하드 제약 준수 — 라이트만, 좌측 액센트 보더 없음,
토큰 색만, 카드당 액션 1개.

### A-1 조용한 신뢰선 (Quiet Trust Line) — 종합안

**의도:** 매체명·작성자·시간·지표 4종을 버리고, "믿을 만한가"와 "무슨 일인가"
둘만 남긴다. 카드가 답해야 할 질문은 그 둘뿐이다.

```
┌─ article  px16 py14  radius12  bg:--wc-card  shadow-1 ────────────┐
│                                                                    │
│  ● 오피셜   토트넘                          ┌──────────────────┐  │
│  11px/700   11px/600                        │   104 × 58       │  │
│  버건디     mute+도트                       │   16:9  radius8  │  │
│                                             │                  │  │
│  손흥민 재계약 협상, 구단이 2년             └──────────────────┘  │
│  연장안을 제시했다                                                 │
│  16px / 700 / lh1.36 / clamp2 / min-h 2행                         │
│                                                                    │
│  [ 이 이적, 카드는 뭐라고 할까? ]     ← 액션 슬롯 32px 고정        │
│    또는  [ 재계약한다 ] [ 못 한다 ]                                │
└────────────────────────────────────────────────────────────────────┘
카드 간격 12px. 총 높이 ≈ 148px 고정.
```

**버린 것 (11종 중 5):** ④작성자 · ⑤좋아요 · ⑥댓글수 · ⑦시간 · ⑩댓글 미리보기.
추가로 ①출처는 매체명 삭제·티어만 생존, ⑧투표는 프레임/안내문 삭제·버튼만 생존.

**썸네일:** 16:9 (104×58) — 크롭 손실 14.1% → 3.3%. 플레이스홀더는 416×234
파생본(팀 컬러 + 팀명 한 단어). 실사진은 face-focus 유지.

### A-2 제목 목록 (Headline List) — 썸네일까지 버린다

**의도:** 밀도를 최대로. 이미지가 정보가 아니라면 이미지를 없애면 화면당
기사 수가 2.4배가 된다. 조회 0.57의 문제가 "안 보여서"라면 이게 답이다.

```
┌─ px16 py12  bg:--wc-card ─────────────────────────────────────────┐
│ ● 오피셜  손흥민 재계약 협상, 구단이 2년 연장안을 제시했다        │
│           15px/650 clamp1                                          │
│           [ 재계약한다 ]  [ 못 한다 ]          ← 24px 슬롯        │
└────────────────────────────────────────────────────────────────────┘
높이 ≈ 76px. 600px 화면에 7~8장 (현재 3장).
```

**버린 것 (11종 중 7):** ②말머리(제목에 이미 팀명) · ④작성자 · ⑤좋아요 ·
⑥댓글수 · ⑦시간 · **⑨썸네일** · ⑩댓글 미리보기 · ⑪재생 뱃지.

**썸네일:** 없음. 그래서 `cards.filter(c => !!c.image)` 게이트도 풀 수 있다 —
사진 없는 기사가 피드에 들어온다(현재 인스타/X 임베드 글과 텍스트 글이 통째로
배제되고 있다). **플레이스홀더 21종을 생성할 이유 자체가 사라진다.**

⚠️ 리스크: "카드뉴스"라는 이름과 정면 충돌. 시각적 매력 상실. 이건 급진안이고
A/B 로 확인할 값어치는 있다(밀도 vs 매력).

### A-3 쟁점 먼저 (Question First) — 투표 프레임을 해체한다

**의도:** 투표를 카드 안의 별도 위젯이 아니라 **카드의 마지막 문장**으로
만든다. 액자가 겹치는 이유는 투표가 자기 집을 가졌기 때문이다. 집을 뺏는다.

```
┌─ px16 py14 ────────────────────────────────────────────────────────┐
│  ● 유력                                    ┌──────────────────┐   │
│                                            │  104 × 58        │   │
│  기마랑이스, 토트넘 이적 협상이            └──────────────────┘   │
│  최종 단계에 들어섰다                                              │
│  16px/700 clamp2                                                   │
│                                                                    │
│  성사될까?   [ 간다 ]  [ 안 간다 ]                                 │
│  12px/600    ← 질문과 버튼이 같은 행. 프레임·배경·테두리 전부 없음 │
│              pill: bg color-mix(burgundy 7%), radius999, px10 h28  │
└────────────────────────────────────────────────────────────────────┘
```

질문은 `line-clamp-1`이 아니라 **6~10자로 재작성**한다("성사될까?", "누가 맞을까?").
전문은 상세 `VsIssueWidget`이 이미 갖고 있다.

**버린 것 (11종 중 5 + 위젯 3부속):** ④작성자 · ⑤좋아요 · ⑥댓글수 · ⑦시간 ·
⑩댓글 미리보기, 그리고 ⑧의 프레임·안내문·퍼센트 표시.

**썸네일:** A-1과 동일 (16:9).

### A-4 증거 이원화 (Evidence Split) — 플레이스홀더를 버린다

**의도:** 사진과 플레이스홀더는 다른 물건이다. 하나는 증거고 하나는 장식이다.
장식을 지우면 **증거가 신호가 된다.**

```
[ 사진 있는 기사 ]                      [ 플레이스홀더였던 기사 ]
┌─ px16 py14 ──────────────────┐        ┌─ px16 py14 ──────────────────┐
│ ● 오피셜  ┌────────────────┐ │        │ ● 오피셜  ● 도르트문트       │
│           │  140 × 79      │ │        │           ↑ 팀 컬러 도트     │
│ 제목 두 줄│  16:9 크게     │ │        │ 제목 두 줄까지 — 전폭 사용    │
│ 16px/700  └────────────────┘ │        │ 16px/700  clamp2              │
│ [ 액션 슬롯 32px ]           │        │ [ 액션 슬롯 32px ]            │
└──────────────────────────────┘        └──────────────────────────────┘
     높이 ≈ 152px                            높이 ≈ 128px
```

⚠️ 높이가 갈라진다(152 vs 128). **A-7과 반드시 함께 써야 한다** — 액션 슬롯
고정 + 제목 min-height 2행으로 맞추면 차이가 24px로 줄고, 사진 카드를
"드물게 나타나는 큰 카드"로 의도적 리듬 변화로 읽히게 만들 수 있다.

**버린 것 (11종 중 5):** ④작성자 · ⑤좋아요 · ⑥댓글수 · ⑦시간 ·
**⑨썸네일의 플레이스홀더 분기 전체**.

**썸네일:** 사진만 16:9로 **더 크게**(140×79). 플레이스홀더는 렌더하지 않고
팀 컬러 도트로 대체. 게이트(`!!c.image`)는 "실사진 또는 텍스트"로 완화 —
플레이스홀더 생성 파이프라인을 **폐기**할 수 있다.

### A-5 시간을 피드로 (Time to Divider)

**의도:** 60장에 60번 반복되던 시간을 3~4개의 구분선으로 압축한다.
시간은 개별 기사의 속성이 아니라 **피드의 축**이다.

```
  오늘 오전                             ← 13px/700 mute, py8, 배경없음, sticky
┌─ 카드 ───────────────────────────┐
└──────────────────────────────────┘
┌─ 카드 ───────────────────────────┐
└──────────────────────────────────┘
  어젯밤
┌─ 카드 ───────────────────────────┐
└──────────────────────────────────┘
  어제 낮
   ...
```

구간: `오늘 오전` / `오늘 새벽` / `어젯밤` / `어제 낮`. 24h 창이라 4구간이면 덮는다.
`suppressHydrationWarning`이 카드마다 붙던 것도 사라진다(구분선 4개에만 필요).

**버린 것 (11종 중 4):** ④작성자 · ⑤좋아요 · **⑦시간(카드에서 완전 제거)** ·
⑩댓글 미리보기.

**썸네일:** A-1과 동일. (이 변주는 썸네일에 관여하지 않음 — 다른 변주와 조합용)

### A-6 지표 침묵 (Silent Metrics)

**의도:** 0은 정보가 아니다. 0인 지표를 **아이콘까지** 지우면, 지표가 붙은
소수의 카드가 진짜로 두드러진다. 지금은 빈 아이콘이 전 카드에 깔려 있어서
숫자가 있어도 안 보인다.

```
[ 대부분의 카드 — 지표 0 ]              [ 드문 카드 — 댓글 3개 ]
┌──────────────────────────┐            ┌──────────────────────────┐
│ ● 오피셜  토트넘         │            │ ● 유력   아스날          │
│ 제목 두 줄               │            │ 제목 두 줄               │
│ [ 액션 슬롯 ]            │            │ [ 액션 슬롯 ]   댓글 3   │
└──────────────────────────┘            └──────────────────────────┘
                                          지표는 액션 슬롯 우측 끝에만.
                                          아이콘 없이 "댓글 3" 텍스트 12px/600.
```

**버린 것 (11종 중 4~6):** ④작성자 · ⑤좋아요(전부) · **⑥댓글수(0일 때 아이콘까지)** ·
⑦시간 · ⑩댓글 미리보기 · ⑪재생 뱃지.

말풍선/하트 **아이콘 자체를 안 쓴다.** 60장 중 3장에만 나오는 지표에 아이콘
범례를 유지할 이유가 없다 — 텍스트가 더 짧고 더 명확하다.

**썸네일:** A-1과 동일.

### A-7 액션 한 슬롯 (One Slot) — 리듬 복구 전용

**의도:** 이건 삭제안이자 **골격 규약**이다. 투표·타로·없음이 모두 같은 32px
슬롯을 쓰게 만들어 카드 높이를 상수로 고정한다.

```
모든 카드가 정확히 같은 높이:
┌────────────────────────────────────────────────────┐
│ 칩 행                      24px  (없으면 빈 24px)  │
│ 제목                       44px  (min-height 2행)  │
│ 액션 슬롯                  32px  (없으면 빈 32px)  │
│ padding 14 + 14                  28px              │
└────────────────────────────────────────────────────┘
                                    총 128px — 예외 없음
```

슬롯 내용물 3종은 **같은 시각 언어**를 쓴다:

| 종류 | 형태 | 스타일 |
|---|---|---|
| 투표 | pill 2개 나란히 | h28 radius999 px10 / bg burgundy 7% / 11.5px 600 |
| 타로 | pill 1개 | 동일 |
| 없음 | 빈 여백 | — |

**버린 것 (11종 중 6):** ④작성자 · ⑤좋아요 · ⑥댓글수 · ⑦시간 · ⑩댓글 미리보기,
그리고 ⑧투표의 프레임·안내문·퍼센트 (버튼만 생존).

**썸네일:** 16:9 104×58. **높이 고정의 전제 조건이다** — 76px 썸네일은
128px 카드 안에 안 들어간다. 58px이면 들어간다.

### A-8 팀 레인 (Team Lane) — 말머리를 그룹으로 올린다

**의도:** 팀명이 카드마다 반복되면 칩이지만, 위로 올리면 **구조**가 된다.
팬덤 사이트의 사용자는 "오늘 뭐 있나"가 아니라 "우리 팀 뭐 있나"로 본다.

```
  토트넘  3                          ← 14px/700, 팀 컬러 도트, sticky
┌─ 카드 (말머리 칩 없음) ──────────┐
└──────────────────────────────────┘
┌─ 카드 ───────────────────────────┐
└──────────────────────────────────┘
┌─ 카드 ───────────────────────────┐
└──────────────────────────────────┘
  아스날  2
┌─ 카드 ───────────────────────────┐
   ...
  기타  9                            ← 1건짜리 팀은 묶는다
```

**버린 것 (11종 중 5):** **②말머리(카드에서 완전 제거)** · ④작성자 · ⑤좋아요 ·
⑦시간 · ⑩댓글 미리보기.

**썸네일:** A-1과 동일. 단 플레이스홀더는 **완전 삭제 권장** — 그룹 헤더가

## 9. 내가 고르는 것

**A-1 + A-7 + A-6** (종합안 + 슬롯 규격화 + 지표 침묵).
썸네일은 16:9 + 파생본 2종.

이유는 위험 대비 회수다:

- **A-7이 브리프 증상 6개 중 3개(1·3·5)를 혼자 해결한다.** 액자 이중화,
  리듬 파괴, 톤 불일치가 전부 "액션이 자기 집을 가졌다"는 한 원인에서 나온다.
- **A-6이 증상 2(위계 붕괴)를 해결한다.** 지표를 지워서 생긴 공간으로 제목을
  14.5px → 16px, 650 → 700으로 올릴 수 있다. 무게 차이가 생긴다.
- **증상 6(안내문 반복)은 삭제 2순위 한 줄로 끝난다.** 비용 0.
- **증상 4(썸네일 파손)는 16:9 전환으로 손실 14.1% → 3.3%.** CSS 한 줄.
  파생본 생성은 그 다음.

A-2(썸네일 제거)와 A-4(플레이스홀더 제거)는 **회수가 더 크지만 되돌리기가
어렵다** — 파이프라인(게이트 필터, 21종 생성 스크립트)에 닿는다. 위 3종을
먼저 넣고 관측한 뒤에 판단할 문제다.

### 실행 순서

| 단계 | 작업 | 비용 | 되돌리기 |
|---|---|---|---|
| 1 | 작성자 제거 · 안내문 제거 · 투표 프레임 제거 | 삭제만 | 쉬움 |

## 10. 마지막 — 측정에 관한 경고

브리프가 정직하게 적어뒀다: "디자인의 목표는 전환률이 아니라 정보가 정돈돼
보이는 것 자체다(신뢰·체류)." 동의한다. 그래서 덧붙인다.

**이 개편을 클릭률로 평가하면 안 된다.** 조회 0.57·투표 1.3%에서 요소를 4종
지우면 클릭은 거의 확실히 **안 오르거나 살짝 떨어진다** — 지운 것 중 하나가
클릭 가능한 요소(하트)이기 때문이다. 그걸 실패로 읽으면 지운 것을 다시
집어넣게 되고, 6개월 뒤 같은 브리프를 다시 쓰게 된다.

측정한다면 이것들이다:

- **카드 높이 분산** — 지금은 투표 유무로 2배 차이. 목표는 상수(A-7이면 0).
- **카드당 DOM 노드 수** — 삭제가 실제로 일어났는지의 물증. 되돌아가면 다시 는다.
- **피드 1스크롤당 기사 수** — 밀도. 3장 → 4~5장.
- **스크롤 깊이** — "정돈돼 보인다"의 유일한 행동 대리 지표.

그리고 규약 하나를 남길 것을 제안한다:

> **카드에 요소를 추가하려면 하나를 지워야 한다.**

지금 카드가 11종을 담게 된 건 나쁜 결정 6개 때문이 아니라, **좋은 결정 6개에
삭제 규약이 없었기 때문**이다. 규약이 없으면 이 문서의 수명은 다음 요청까지다.
