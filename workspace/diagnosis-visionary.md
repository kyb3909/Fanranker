## Product Visionary — 차별화 콘텐츠 후보 5

> 전제: 30개 기각 축(퀴즈/인덱스/베팅연관/대규모/AI그림퀄/커뮤활성화전제/유틸보드아류) 전부 회피. 유저 0명 성립, 비로그인 즉시 가치, 1인 1주 vertical slice, 수동 DB 구축 없음.

---

### 1. 라이브 AI 캐스터 실황 — "경기를 안 봐도 라디오처럼 들리는 텍스트 중계"

**콘셉트**
경기 진행 중, wisetoto 라이브 스코어(골/카드/코너/교체 등 이벤트 diff)를 감지할 때마다 LLM이 고정된 캐릭터 목소리(예: "성질 급한 늙은 삼촌팬" 페르소나)로 **원문 대본을 새로 써서** 타임라인에 흘려보낸다. 경기 데이터를 그대로 보여주는 게 아니라, 그 데이터를 소재로 매번 다른 원고를 즉석 집필하는 것. 베팅/배당 언급은 하지 않음 — 순수 엔터테인먼트 중계.

**"이거 뭐야?" 순간**
스코어보드만 있는 스포츠 앱에서, 골이 들어간 직후 몇 초 만에 "와 이 캐스터 미쳤네" 싶은 감정 섞인 원고가 뜬다. 한국에 텍스트형 AI 라이브 캐스터를 상시 운영하는 스포츠 서비스가 없다 — 사람이 중계하거나(느림·비용) 스코어만 주거나(무미건조) 둘 중 하나뿐.

**왜 gongnori만 할 수 있나**
- 뉴스 에이전트 파이프라인(`data/agents`)의 LLM 호출+검수 인프라를 재사용 (신규 구축 아님)
- wisetoto 실시간 스코어 sync(`/api/wisetoto/sync`, 매분)가 이미 프로덕션에서 돌아감
- 두 인프라를 동시에 보유한 곳은 gongnori 외 국내에 없음 (언론사는 스코어 인프라는 있어도 자동 원고 생성 파이프라인이 없고, 스포츠 데이터 앱은 원고 생성 니즈 자체가 없음)

**첫 주 vertical slice**
- 아스날 경기 1건 하드코딩 대상, 페르소나 1개만
- wisetoto 이벤트 diff → 프롬프트 템플릿(페르소나 고정) → GPT 호출 → `match_commentary` 테이블 append
- 프론트: 단일 페이지 폴링(3~5초) 타임라인 렌더 (SSE는 2주차 이후)
- 검수 없이 자동 게시 (짧고 휘발성 콘텐츠라 사후 삭제로 충분 — 뉴스 기사와 다른 리스크 등급)

### 2. 경기 부검 리포트 — "종료 3분 만에 뜨는 블랙유머 진단서"

**콘셉트**
경기 종료 직후, betman 스탯(슈팅/점유율/카드 등) + 크롤된 관련 뉴스 소스를 조합해 "이 팀이 왜 이겼는지/졌는지"를 **사망진단서 포맷**("사인 / 결정적 순간 / 예후")으로 자동 작성. 기존 뉴스 검수 파이프라인(초안→credibility→desk review→발행)을 그대로 통과시켜 담벼락에 게시.

**"이거 뭐야?" 순간**
경기 끝나고 스포츠 뉴스 사이트들이 아직 기사도 안 올렸을 시점에, "출혈사 (과다출혈: 실점 3회, 지혈 실패)" 같은 블랙코미디 진단서가 이미 떠 있다. 형식 자체가 스포츠 저널리즘에 없던 장르.

**왜 gongnori만 할 수 있나**
- fetch→credibility→작성→검수 파이프라인이 이미 존재 (data/agents), 새 프롬프트 템플릿만 추가하면 됨
- betman 크롤 데이터(스탯)를 이미 갖고 있음 — 언론사는 이 raw 스탯에 실시간 접근이 없거나 사람이 취합해야 함
- 발행 속도 경쟁에서 "사람이 안 쓴다"는 것 자체가 구조적 우위

**첫 주 vertical slice**
- 아스날 경기 1건, 종료 감지(betman sync 완료 이벤트) → 스탯 pull → 고정 프롬프트 템플릿 → 초안 생성
- 기존 desk review 큐(`agg_reservoir` drafted)에 그대로 태워서 수동 승인 1클릭 발행
- 신규 DB 불필요, 기존 posts 테이블 + 기존 검수 UI 재사용

### 3. 심야 라디오 사연 낭독 — "매일 같은 시간, 같은 목소리로 오는 루틴"

**콘셉트**
Wordle/뉴닉류의 "정해진 시간에 오는 습관형 콘텐츠"를 오디오로. 팬이 제출한 사연(짧은 텍스트) + 그날 크롤된 뉴스 중 감성적인 소재를 골라, 고정 DJ 페르소나 대본으로 TTS 낭독 + 배경음 + 자막 1장. 매일 23:00 KST 고정 발행. 제출이 0건인 날도 뉴스 소재만으로 자동 성립 — 커뮤니티 활성화를 전제하지 않음.

**"이거 뭐야?" 순간**
스포츠 커뮤니티인데 밤 11시에 라디오 DJ 목소리로 "오늘 하루 고생한 구너들에게" 하는 낭독이 뜬다 — 스포츠 앱에서 기대 못 하는 정서적 톤 전환. 습관이 되면 "오늘 자기 전에 그거 들어야지"가 생김.

**왜 gongnori만 할 수 있나**
- 뉴스 크롤 소스(Reddit+Naver 55개) + LLM 파이프라인을 소재 공급원으로 재사용
- TTS는 표준 API(OpenAI TTS 등) 붙이면 끝 — 신규 인프라 아님
- 축구+팬 커뮤니티+뉴스 파이프라인을 동시에 가진 곳에서만 "소재 고갈 없이" 매일 지속 가능

**첫 주 vertical slice**
- DJ 페르소나 1개, 대본 템플릿 1개
- 제출 폼 없이 시작 — 그날 뉴스 크롤 중 1건을 소재로 자동 대본 생성 → TTS 변환 → 정적 mp3 + 자막 1장 게시물로 발행
- 팬 사연 제출은 2주차 이후 추가 (사연 0건이어도 시스템은 죽지 않음)

### 4. 라이벌전 도발 카드 — "경기 전날 SNS에 캡처해서 올리고 싶은 한 장"

**콘셉트**
빅매치 전날, 상대 팬덤을 향한 풍자적 "도발 카드"(짧은 카피 + 상대 전적 약점 1개 + 기존 팀 뱃지/스타디움 픽셀 에셋을 템플릿에 얹은 정적 이미지)를 자동 생성. **신규 AI 이미지 생성이 아니라 기존 팀 로고·픽셀 에셋을 고정 레이아웃 템플릿에 텍스트만 갈아끼우는 방식**이라 퀄리티 리스크 없음.

**"이거 뭐야?" 순간**
경기 전날 "내일 토트넘전, 이거 스샷 각인데?" 싶은 한 장이 자동으로 뜬다. 스포츠 앱에서 밈처럼 공유하고 싶은 콘텐츠가 나온다는 것 자체가 낯섦 — 대부분 앱은 경기 일정표만 준다.

**왜 gongnori만 할 수 있나**
- 팀 뱃지·픽셀 에셋(`team_map_pins`, stadium 리소스)이 이미 존재 — 신규 아트워크 제작 불필요
- betman 일정 데이터로 "내일 빅매치" 자동 판별 가능
- LLM은 카피 문구 생성에만 쓰여 이미지 퀄리티 리스크가 없음 (레이아웃은 고정 템플릿)

**첫 주 vertical slice**
- 고정 카드 템플릿 1개(Canvas/SVG 서버 렌더), 상대 팀 뱃지 + 카피 텍스트 슬롯만
- 내일 아스날 빅매치 1건 하드코딩 → LLM 카피 3안 생성 → 검수(1클릭) → PNG 렌더 → 담벼락 게시 + 다운로드 버튼
- 다음 상대 자동화는 2주차

### 5. 크로스오버 브리핑 — "축구와 아이돌이 만나는 유일한 지면"

**콘셉트**
같은 날 크롤된 축구 뉴스와 여돌 뉴스 중, 우연히 겹치는 지점(같은 도시 출신, 같은 날 생일, 컴백/이적 시점 겹침, 팬덤 응원법 유사성 등)을 LLM이 찾아내 짧은 "우연의 일치" 브리핑으로 엮는다. 매일 1편, 짧은 칼럼 형식.

**"이거 뭐야?" 순간**
스포츠 커뮤니티에서 "오늘 벤화이트(아스날)와 XX(아이돌)가 같은 날 데뷔 N주년이라는 우연" 같은 글을 만난다 — 완전히 다른 두 팬덤이 겹칠 이유가 없는데 겹친다. 이 조합을 시도하는 매체가 국내에 없음(스포츠 매체와 아이돌 매체는 완전히 분리된 시장).

**왜 gongnori만 할 수 있나**
- 축구 크롤 인프라(Reddit 44+Naver 11) **와** 여돌 크롤 인프라를 동시에 가진 곳은 gongnori뿐 — 두 버티컬을 한 회사가 동시에 운영하는 경우 자체가 드묾
- LLM이 두 소스를 매칭해 소재를 찾는 것은 사람이 매일 하기엔 비효율적이지만 자동화하면 저비용
- 인덱싱이 아니라 "두 원본 소스를 재료 삼아 새로 쓴 글"이라 저작권/톤 리스크도 낮음

**첫 주 vertical slice**
- 당일 축구 크롤 헤드라인 상위 5개 + 여돌 크롤 헤드라인 상위 5개를 LLM에 동시 입력
- "겹치는 지점 찾기" 프롬프트로 후보 3개 생성 → 사람이 1개 선택(수동 큐레이션, 검수 큐 재사용) → 짧은 칼럼으로 발행
- 겹치는 지점이 빈약한 날은 "오늘은 쉬어감" 스킵 로직 (억지 매칭 방지)
