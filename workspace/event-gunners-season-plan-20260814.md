# 아스날 시즌 이벤트 "건너스 레이스" 구현 계획 (2026-08-14)

컨셉 확정: v3-1 (메인 매치 + 전 리그 보드) + v3-2의 "내 오늘 픽·스트릭" 패널 이식.
**설계 1원칙: 예측은 입구, 목적지는 게시물** — 언론사 계약 지표(기사 조회·체류·재방문)가 진짜 KPI.

## 기존 리소스 재사용 맵 (새로 만드는 걸 최소화)

| 이벤트 요소 | 기존 리소스 | 재사용 방식 |
|---|---|---|
| 경기 공급 (전 리그) | `betman_games` + `/api/betman/games` (데일리 윈도우) | 그대로 — 축구 전 리그가 이미 흐름. 새 크롤 0 |
| 예측/픽 | `/prediction` + `prediction_slips` + `use-betting` | **별도 풀 안 만듦** — 기간 내 축구 슬립을 이벤트로 집계 (월드컵의 event_id 방식보다 단순) |
| 아스날 메인 매치 | betman `home/away_team_name` 아스날 매칭 (타로 fixture.ts 별칭 재사용) | 이벤트 집계 시 배점 보너스만 |
| 점수 모델 | 월드컵 검증 완료 모델: **슬립 단위 net 손익** (points_earned=배당 함정 회피) | 산식 재사용, 아스날 경기 포함 슬립 ×2 |
| 랭킹 | 월드컵 랭킹 쿼리 + 실시간 전환 경험 | TOP 5 공개 + 내 순위 (월드컵의 "TOP10 비공개"는 이번엔 해제 — 운영자가 랭킹 노출 선호 확인) |
| 홈 진입점 | `components/home/matchday-band.tsx` (담벼락 경기 밴드) | 밴드에 이벤트 칩/링크 추가 — 신규 배너 대신 기존 동선 |
| 이벤트 운영 | `events` 테이블 + `/admin/event` 콘솔 (월드컵 인프라) | 기간·상금·상태 관리 재사용 |
| 관련 소식 | 뉴스 봇 기사 (`posts` + 표기/팀 매칭) | ↓ 콘텐츠 전환 루프의 재료 |

## 콘텐츠 전환 루프 (가장 중요 — 이게 이벤트의 존재 이유)

1. **픽 제출 직후 주입** (메모리 실측: 최대 레버)
   - 슬립 제출 성공 응답 화면에 "픽한 팀 소식 3개" 카드 — 픽한 팀명으로 봇 기사·게시물 검색해 주입.
   - "리버풀 승 픽 완료 → 리버풀 최신 소식 보러 가기" — 클릭 시 `?ref=event-pick` 태깅.
2. **이벤트 페이지 안에 담벼락 모듈** — 랭킹 아래 "지금 뜨는 글" (온도순 상위 5) — 이벤트 페이지가 막다른 골목이 되지 않게.
3. **메인 매치 카드에 아스날 최신 기사 2개 상시 노출** — 예측 전에도 읽을거리 먼저.
4. **계측**: 위 링크 전부 `ref=` 파라미터 — 언론사 미팅용 "이벤트발 기사 조회" 수치가 소급 불가하므로 시작부터 심음 (GA4 + 내부).

## 구현 순서 (각 단계 독립 배포 가능)

1. **이벤트 레이어**: events 레코드(gunners-season) + 집계 쿼리/RPC (기간 내 축구 슬립 → 포인트, 아스날 보너스) + `/api/event/gunners-season/standing`
2. **이벤트 페이지** `/event/gunners-season`: v3-1 레이아웃 — 메인 매치 카드(+기사 2), 전 리그 보드(기존 /prediction 컴포넌트 링크/임베드), 내 레이스 현황, TOP 5, 지금 뜨는 글
3. **전환 루프**: 슬립 제출 성공 UI에 "픽한 팀 소식" 주입 (prediction 쪽 공용 컴포넌트)
4. **홈 연결**: matchday-band 이벤트 칩 + 온보딩 채널용 랜딩 파라미터
5. **운영**: /admin/event 재사용 확인, 정산은 기존 betman 정산에 얹힘 (신규 정산 0)
