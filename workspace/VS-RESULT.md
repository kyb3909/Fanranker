# VS 쟁점 생성: 전면 자동 vs 사람 개입 — 최종 결론 (2026-07-30)

## 0. 결론 한 줄

**"기본 켜짐 + 발행 화면에서 눈에 보이고 1클릭으로 끌 수 있음(opt-out) + 쟁점 신뢰도 낮으면 자동으로 기본 꺼짐"** 으로 간다.
A/B/C 중 택일이 아니다. 브리프의 선택지 정의가 틀렸기 때문에 셋 다 최선이 아니다(아래 2절).

---

## 1. 합의점과 진짜 대립축

### 1-1. 세 관점이 실제로 합의한 것 (더 논쟁할 필요 없음)

| 합의 사항 | 근거 | 누가 |
|---|---|---|
| **B안 "기본 꺼짐 + 수동 켜기"는 사장된다** | 1인 운영은 상시 포화. 절대 시간 비용이 하루 몇 분에 불과해도 default bias가 "안 켜기"로 수렴 | 전원 (Realist가 "비용이 아니라 기본값이 리스크"로 정식화) |
| **"화력 상위 기사만 생성"(C안 임계)은 기각** | 화력 상위 = 이적설 복붙형 어그로. 억지 사례(콜로 무아니)가 정확히 그 카테고리. 인기 ≠ 논쟁. 게다가 발행 직후엔 화력 데이터가 없어 지연 생성 cron이 필요 | Contrarian이 논파, Visionary는 공급 축소라 반대, Realist는 구현 부담 인정 → 3:0 |
| **no_issue 가드 83% 통과는 "관대"가 아니라 "사실상 없음"** | 백필 12건 중 10건 통과, 그중 억지 다수 | 전원 |
| **admin 사후 끄기 토글은 만든다** | 반나절, 기존 admin2 워크벤치 편입 | Visionary(킬스위치), Realist(quick win). Contrarian만 "발견해야 작동"이라 불충분하다고 봄 |
| **8월 이벤트 시점에 폴 공급이 마르면 최악** | 게이트 인정 액션·치킨 응모 연결 | Visionary/Realist. Contrarian은 "그러니 더 보수적으로"라고 방향만 반대(사실 자체는 부정 안 함) |

### 1-2. 표면상의 대립축 (브리프가 설정한 것)

"지금 자동으로 계속 내보내며 데이터를 쌓는다(A/C)" vs "이번 주는 100% 사람 확인으로 품질부터 잡는다(Contrarian)".

### 1-3. 진짜 대립축 두 개

브리프가 만든 "자동 vs 사람"은 가짜 축이다. 세 문서를 겹쳐 놓으면 실제로 갈린 건 이 둘이다.

**축 A — "쟁점 없음"을 기계가 판별할 수 있는가?**
- Visionary/Realist: 판별 가능한 **엔지니어링 문제**다. fact-only 기사 감지, 복붙형 이적설 감지를 few-shot으로 넣으면 줄어든다.
- Contrarian: 판별이 아니라 **카테고리 오류**다. 수익 발표 기사에는 애초에 갈등이 없으므로, 프롬프트를 강화하면 없는 갈등을 만들어내는 클릭베이트화로 갈 뿐이다.
- → **Contrarian이 진단에서 이겼다.** 지금 프롬프트는 "찬반 쟁점을 만들어라"라고 지시하고 있다. 생성을 명령받은 LLM은 항상 생성한다. 83% 통과율은 가드의 관대함이 아니라 **과업 정의의 결함**이다.
- 단, Contrarian의 결론("그러니 사람이 봐야 한다")은 과도하다. 고칠 것은 지시문이다: 쟁점을 만들라고 하지 말고 **"이 기사에 찬반이 갈릴 지점이 있는가? 있으면 무엇인가"를 먼저 판정시키고 판정 신뢰도를 받는다.** 판별을 사람에게 넘기는 게 아니라 판별을 과업으로 승격시키는 것.

**축 B — 2주 뒤 우리가 측정하려는 건 무엇인가?**
- Visionary: **노출량**. 폴이 촘촘히 깔려야 훅 그리드가 완성되고 이벤트 재고가 쌓인다.
- Contrarian: **참여 여부 자체**. "VS 쟁점이 노출되면 참여가 생긴다"가 아직 0건 검증이다. 이 전제가 거짓이면 A/B/C 논쟁 전체가 무의미하다.
- → **Contrarian이 여기서도 옳다.** 하지만 그의 처방(100% 사람 확인)은 자기 논증에 걸린다. 그는 B안을 "안전을 산다면서 학습을 판다"고 정확히 논파했는데, 자신의 처방도 사람 처리량이 병목이 되는 순간 같은 방식으로 표본을 말린다.
- 정확한 해법: **노출은 유지하되(표본 확보) 사람 눈이 노출 전에 지나가게 만든다.** 이 둘은 배타적이지 않다.

### 1-4. 이 논쟁에서 나온 가장 값진 발견

**브리프의 B안이 두 개의 독립 변수를 한 묶음으로 묶어 제시했기 때문에 논쟁이 오염됐다.**

진짜 변수는 두 개다:
- 변수 1: 기본값 = 켜짐 / 꺼짐
- 변수 2: 사람 개입 시점 = 발행 전 / 발행 후

2×2로 펼치면:

| | 사람 개입: 발행 전 | 사람 개입: 발행 후 |
|---|---|---|
| **기본 켜짐** | **여기 (아무도 선택지에 안 넣음)** | A안 / A변형 / C안 |
| **기본 꺼짐** | B안 (전원 기각) | (성립 안 함 — 안 켜졌으니 끌 게 없음) |

브리프는 "발행 전 개입"과 "기본 꺼짐"을 B안 하나로 묶어버렸다. 그래서 B를 기각하면 자동으로 "발행 전 개입"까지 기각되는 것처럼 보였고, Visionary와 Realist는 사후 대응(A변형/C)으로 밀렸고, Contrarian은 사전 개입을 지키려다 "100% 사람 확인"까지 갈 수밖에 없었다.

**빈 칸이 정답이다.** 기본 켜짐 + 발행 전 노출(눈에 보임) + 1클릭 opt-out.
- Contrarian의 요구("사람 눈이 노출 전에 한 번 지나간다") 충족 — 빠른검수 화면에 이미 앉아 있으므로 추가 방문 0회.
- Visionary/Realist의 요구("기본값이 켜짐이라 사장·공급 리스크 없음") 충족 — 바쁘면 아무것도 안 해도 그대로 나간다.
- Contrarian이 지적한 B안의 실패 모드("바쁘면 100% 무시")가 여기서는 **안전한 실패(fail-open)** 가 된다. default bias를 우리 편으로 돌린 것.

이건 절충이 아니다. 배타적이라고 착각했던 두 요구가 실제로는 서로 다른 변수를 잡고 있었다는 걸 드러낸 것이다.

## 2. 최종 권고안 — 구체 스펙

### 2-1. 무엇을 기계가 하는가

1. **쟁점 판정을 2단으로 분리 (프롬프트 재작성)**
   - 1단: "이 기사에 독자 의견이 갈릴 지점이 있는가?" → `has_issue: bool` + `confidence: 0.0~1.0` + `reason`
   - 2단: 1단이 통과한 경우에만 찬반 문구 + 3줄 요약 생성
   - 지금처럼 "쟁점을 만들어라"라고 지시하지 않는다. 생성 명령을 받으면 LLM은 항상 생성한다.
   - few-shot에 **기각 예시**를 먼저 넣는다: 수익/매출 발표, 순위표, 일정 발표, 단순 부상 소식, 소스 1개짜리 복붙 이적설. (백필 10건 중 억지로 판정된 것들이 그대로 재료 — 4절 참조)
   - 어미 규칙 하드 제약: 문장은 반드시 의문형으로 끝난다. `~인가?` / `~해야 할까?` / `~맞나?`. `~이다?` 금지.

2. **confidence로 기본값을 분기 (이게 C안 임계의 대체물)**
   - `confidence >= 0.7` → **기본 켜짐**. 발행하면 그대로 노출.
   - `0.4 <= confidence < 0.7` → **기본 꺼짐 + 제안 상태**. 빠른검수 화면에 회색으로 문구가 보이고, 켜고 싶으면 1클릭.
   - `confidence < 0.4` → 생성 자체를 안 한다(현행 no_issue 경로).
   - 임계 0.7 / 0.4는 **가설이다.** 코드 상수로 빼두고 2주 뒤 실측으로 교체한다(3절).
   - 화력(조회수·댓글수) 기반 임계는 쓰지 않는다. 인기는 논쟁성의 대리 지표가 아니고, 발행 직후엔 값이 없어 지연 생성 cron이 필요해진다. 기각.

3. **떡밥 카드(안 1) 노출은 별도의 높은 바** — 5절 참조.

### 2-2. 무엇을 사람이 하는가

빠른검수 화면(이미 매 기사 열어보고 있는 화면)에 카드 하나가 인라인으로 붙는다:

```
[VS 쟁점]  신뢰도 0.82  (켜짐)
"네이마르의 은퇴, 아쉬운 결정인가?"   찬성 / 반대
                                   [끄기]  [문구수정]
```

- **기본 켜짐 건**: 아무것도 안 하면 그대로 발행된다. 클릭 0.
- **끄고 싶을 때**: `[끄기]` 1클릭.
- **문구만 어색할 때**: `[문구수정]` → 인라인 textarea, 약 20초. (필수 아님. 어색하면 그냥 끄는 게 정답)
- **제안 상태(회색) 건**: 아무것도 안 하면 안 나간다. 살릴 만하면 `[켜기]` 1클릭.
- **사후 킬스위치**: 발행글 목록에서 `vs_issue_enabled` 토글. 주 1회 5분 훑기. (Visionary의 킬스위치 + Realist의 quick win 그대로)

### 2-3. 1인 운영 클릭 비용 (실측 기준)

전제: 하루 발행량 N을 아직 모른다. Realist 추정 5~15건. **이 숫자는 오늘 바로 확인 가능하므로 3절 지표 0번으로 넣었다.**

| 항목 | 클릭 | 시간 |
|---|---|---|
| 기본 켜짐 건 통과 (예상 60~70%) | 0 | 0초 (화면을 이미 보고 있음) |
| 끄기 (예상 15~20%) | 1 | 약 2초 |
| 제안 건 켜기 (예상 10~15%, 대부분 무시) | 0~1 | 0~2초 |
| 문구 수정 (예상 5% 이하) | 1 + 타이핑 | 약 20초 |
| **하루 합계 (N=10 가정)** | **약 2~4클릭** | **약 30초~1분** |
| 주 1회 사후 킬스위치 리뷰 | 5~10 | 5분 |

**B안 대비 절감의 본질은 시간이 아니라 의사결정 횟수다.** B안은 기사 N건마다 "켤까?"라는 판단을 강제한다(N번의 결정). 이 안은 "이건 아니다"라는 거부만 요구한다(예상 1~2번의 결정). 거부는 판단보다 싸고, 판단을 미루면 좋은 방향(발행)으로 기울어진다.

### 2-4. 구현 규모 / 순서

| 작업 | 규모 | 비고 |
|---|---|---|
| 1. 프롬프트 2단 분리 + 기각 few-shot + 어미 제약 | 반나절 | `data/agents` 프롬프트만. 마이그 불필요 |
| 2. `vs_issue_enabled` boolean + `vs_issue_confidence` numeric 컬럼 | 반나절 | 마이그 1개. 기존 토글 UI 패턴 재사용 |
| 3. 빠른검수 화면 인라인 카드 (표시 + 끄기/켜기 + 문구수정) | 하루 | 상태머신 불필요 — boolean 하나면 끝. B안의 draft/proposed/confirmed 3상태는 만들지 않는다 |
| 4. 발행글 목록 사후 토글 | 반나절 | admin2 워크벤치 편입 |
| 5. 떡밥 카드 노출 필터 + 피드 내 폴 카드 상한 | 안 1 작업에 포함 | 5절 |
| 기각 | — | 화력 기반 지연 생성 cron, A/B 실험 인프라, 3상태 워크플로 |

합계 약 2.5일. 브리지 모달(2일) 등 P0와 경합하므로 **1·2·3을 먼저(2일) 붙이고 4는 다음 주로 미룰 수 있다.** 4가 늦어도 3이 사전 게이트 역할을 하므로 치명적이지 않다.

### 2-5. 왜 이게 절충이 아니라 논리로 이긴 답인가

- Contrarian의 **진단**을 전면 수용했다: 83%는 가드가 아니라 과업 정의의 실패. 화력 임계는 하필 최악 카테고리에 생성을 몰아준다. "노출되면 참여가 생긴다"는 무검증 전제 → 그래서 3절에 kill criteria를 넣었다.
- Contrarian의 **처방**만 기각했다: 100% 사람 확인은 표본을 사람 처리량에 묶어, 그가 B안에 던진 비판("안전을 산다면서 학습을 판다")을 자기가 맞는다.
- Visionary의 **기본값 논리와 이벤트 공급 논리**를 수용했다. 다만 그의 "밀도는 무조건 자산" 주장은 떡밥 카드 표면에 대해서만 반쯤 기각했다(5절) — 피드는 쇼윈도라 바가 다르다.
- Realist의 **기본값이 진짜 리스크**라는 정식화가 이 결론의 축이고, C안의 유일한 약점(화력 임계)만 confidence 임계로 교체했다.

## 3. 2주 후 데이터로 재검토할 결정 목록

기준일: 2026-08-13. 8월 중순 이벤트 직전이라 이때가 마지막 조정 창이다.

### 지표 0 (지금 당장, 데이터 축적 불필요)
- **하루 뉴스 발행량 N**, VS 생성 건수, confidence 분포 히스토그램. Realist가 "모른다"고 한 숫자. 이걸 모르면 2-3절 클릭 비용 추정이 공중에 떠 있다.

### 결정 1. VS 기능을 존속할 것인가 (kill criteria — 최우선)
- 지표: **폴 노출 UV당 투표율.**
- 판정: 8% 이상 → 확대. 3~8% → 유지·개선. **3% 미만 → 기능 축소 또는 철수.**
- Contrarian의 숨은 전제 지적을 제도화한 항목. 이 결정을 목록 맨 위에 두지 않으면 나머지 튜닝은 전부 매몰비용 방어가 된다.
- 임계 8%/3%는 가설. 1탭 투표(로그인 불필요 구간 포함) 기준.

### 결정 2. confidence 신호가 실제로 유효한가 → 사전 게이트 자체를 없앨지
- 지표: `confidence >= 0.7` 그룹 vs `0.4~0.7` 그룹의 투표율 차이.
- 판정: 유의한 차이 있음 → 임계를 실측값으로 재조정. **차이 없음 → confidence 분기를 폐기하고 전면 자동(A안)으로 단순화.** 즉 Visionary가 2주 뒤 이길 수 있는 조항.

### 결정 3. 사람 게이트를 유지할 것인가 (운영자 off율)
- 지표: **운영자 끄기 비율(off rate).**
- 판정:
  - 20% 초과 → 가드가 여전히 후하다. confidence 임계 상향 + 기각 few-shot 보강.
  - 5~20% → 정상 대역. 유지.
  - 5% 미만 → 두 갈래다. (a) 가드가 정확해졌다 → 인라인 카드를 접어도 된다(클릭 비용 0으로). (b) 사람이 그냥 통과시키고 있다 → 게이트가 형식뿐. **구분법: 2주째에 무작위 10건을 직접 스팟체크해 억지 비율을 센다.**

### 결정 4. 8월 이벤트용 공급량을 얼마나 풀 것인가
- 지표: 이벤트 기간 하루 필요 폴 수 = (예상 신규 유입 × 게이트 액션 완료율 목표) / 인당 투표 가능 폴 수. 그리고 현재 하루 켜진 폴 수.
- 판정: 부족하면 confidence 임계를 0.7 → 0.55로 내린다. **코드 상수 한 줄이므로 이벤트 3일 전 결정으로 충분.** 지금 미리 풀 이유 없다.

### 결정 5. 떡밥 카드 폴의 피드 밀도
- 지표: 폴 붙은 카드 CTR vs 일반 카드 CTR, 카드 내 투표 완료율, 폴 노출 직후 이탈률(뒤로가기/스크롤 이탈).
- 판정: 폴 카드 CTR이 일반보다 높음 → 상한 완화. 이탈률이 유의하게 높음 → 상한 강화 또는 노출 바 상향.

### 결정 6. 어떤 유형의 쟁점이 도는가 → 프롬프트 역주입
- 지표: 투표율 상위 20% / 하위 20% 폴의 기사 카테고리·문구 패턴.
- 조치: 상위는 positive few-shot, 하위는 기각 few-shot으로 프롬프트에 역주입. Visionary가 제시한 자기개선 루프를 2주째부터 가동. (기존 `project_news_correction_learning` / Hermes 교정 학습과 같은 패턴이므로 인프라 재사용)

### 부수 관측 (임계 없음, 정성)
- 신고/피드백 채널에 "이 투표 이상하다" 류 반응 존재 여부.
- 투표한 유저의 D1 재방문 vs 미투표 유저 — 습관 형성 가설의 첫 증거.

## 4. 기존 백필 10건 처리 방침

**지금 손으로 10건 전수 판정한다. 총 10클릭, 10분 이내.**

여기서만은 Contrarian의 "100% 사람 확인"이 정확히 맞다. 이유: 표본이 10건으로 유한하고 1회성이며, 이 10건은 신기능의 첫인상이 걸린 최초 노출분이고, 무엇보다 **이 판정 자체가 프롬프트 few-shot 학습셋이 된다.** 사람 손이 이보다 싼 곳은 없다.

3분류로 처리:

| 분류 | 기준 | 조치 | 예 |
|---|---|---|---|
| **유지** | 실제로 의견이 갈리는 질문 | 켜둔 채로 두고 2주 데이터의 baseline 표본으로 쓴다 | "네이마르 은퇴, 아쉬운 결정인가?", "로티토는 계속 구단주여야 할까?" |
| **문구 수정 후 유지** | 쟁점은 있는데 어미/표현만 어색 | 의문형으로 다듬어 유지 | `~이다?` 로 끝나는 것들 |
| **끄기** | 기사에 애초에 갈등이 없음(카테고리 오류) | `vs_issue_enabled = false` 로 비노출. **행을 삭제하지 않는다** | "레알 마드리드가 최고 수익이다?"(수익 발표), "콜로 무아니 영입이 적절한가?"(단일 소스 이적설 복붙) |

**삭제 금지가 핵심이다.** 끈 행에 `off_reason` 을 남긴다: `fact_only` / `boilerplate_transfer` / `awkward_wording` / `no_conflict`. 이 라벨이 그대로 2-1절 기각 few-shot의 원재료이고, 결정 2·3·6의 판정 기준선이 된다. 지금 억지 판정 이력을 버리면 2주 뒤 "가드가 나아졌는가"를 비교할 대조군이 없어진다.

부수 효과: 이 10건 판정에 걸리는 실제 시간을 재보면 2-3절 클릭 비용 추정이 실측으로 교체된다. 10건에 10분 넘게 걸린다면 인라인 카드 UI를 더 단순화해야 한다는 신호다.

## 5. 떡밥 카드 투표(안 1)와의 상호작용

### 5-1. 안 1은 이 논쟁의 판돈을 키우는 승수다

떡밥 카드에 투표가 붙으면 폴의 노출 표면이 기사 본문에서 **피드 전체**로 확장된다. 밀도의 편익과 품질의 비용이 **동시에** 증폭된다. 브리프의 긴장 1(희소성 vs 밀도)이 어려웠던 이유가 이것이다.

### 5-2. 해법: 두 표면의 품질 바를 다르게 둔다

Contrarian은 "노출 위치는 부차적"이라고 했지만, 여기서만은 위치가 답이다.

| 표면 | 성격 | 노출 기준 |
|---|---|---|
| **떡밥 카드(피드)** | 쇼윈도. 비로그인·신규 유입의 첫인상 | `confidence >= 0.7` **이고** 운영자가 끄지 않은 것. 2주 뒤부터는 실측 투표율 상위군 우선 |
| **기사 본문** | 재고. 이미 읽으러 들어온 사람 | 켜진 폴 전부(제안 상태에서 수동 켠 것 포함) |

이렇게 하면 희소성/밀도가 이분법이 아니라 **자리 배분**으로 풀린다. 피드에서는 폴이 희소하고 신뢰할 만하며, 본문에서는 밀도가 유지되어 8월 공급 재고가 쌓인다. Visionary의 공급 논리와 Contrarian의 첫인상 논리가 서로 다른 표면에서 각각 옳다.

### 5-3. 피드 내 폴 카드 상한

폴 카드가 피드를 도배하면 커뮤니티가 설문 사이트처럼 보인다. 초기 규칙:
- 첫 화면(above the fold)에 폴 카드 최대 1개.
- 이후 카드 5개당 최대 1개.
- 같은 팀/같은 사건의 폴은 피드에 1개만.

상한은 결정 5의 지표로 2주 뒤 조정한다.

### 5-4. 순서상의 함의 (중요)

**안 1(떡밥 카드 투표)이 2주 데이터의 계측 표면이다.** 본문 하단 폴만으로는 노출 UV가 작아 결정 1(kill criteria)의 표본이 안 모인다.

따라서 실행 순서는:
1. 프롬프트 2단 분리 + confidence 컬럼 + 빠른검수 인라인 카드 (2일)
2. **안 1 배포** — 여기서 노출/투표 계측이 반드시 함께 나가야 한다. 폴 노출 UV, 투표 이벤트, confidence 값을 같은 이벤트에 실어야 결정 1·2·5를 한 번에 판정할 수 있다.
3. 백필 10건 손정리 (10분, 1과 병행 가능)
4. 사후 킬스위치 토글 (다음 주로 미룰 수 있음)

### 5-5. 이벤트 게이트와의 연결

8월 게이트 인정 액션에 VS 투표를 쓴다면, **떡밥 카드 폴만 인정 액션으로 카운트한다.** 본문 하단 폴까지 인정하면 공급 압박이 confidence 임계를 낮추는 방향으로 밀어대고, 그러면 신규 유입의 첫 액션이 하필 억지 쟁점이 되는 최악의 조합이 나온다. 게이트는 좁은 문에 걸고, 공급은 넓은 방에 쌓는다.
