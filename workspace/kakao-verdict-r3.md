## 1. 질의 1 — 수용안(즉시 8 + 대안 8) 전부 이행 가정 시 승인 가능한가

**결론: 조건부 승인. 단, 수용안 "그대로"는 안 된다 — 대안수정안 2건(R11, R8 게이트)이 이행되어도 구멍이 남는 불완전한 안이다.**

이행 가정 하에 R1~R10, R12, R13, A2, A3은 전부 해소된다. 남는 것:

### 잔존 반려 사유 1건 — R11 이행 범위 결함
수정안은 3개 라우트(`page`, `result`, `games`)에만 `redirect("/prediction")`를 넣는다. 검증 결과 라우트는 **7개**다. 수정안대로 이행하면:
- `app/worldcup/leaderboard/page.tsx` — 순위표(= 경품 지급 기준이 된 랭킹) 그대로 공개
- `components/worldcup/leaderboard-client.tsx:297` — `<a href="/worldcup/register">` 참가 신청 CTA 잔존
- `app/worldcup/register/page.tsx`, `register/done/page.tsx`, `my-predictions/page.tsx` — 전부 접근 가능
심사관이 URL 4개를 더 쳐보면 "성적 1~3위 경품" 이벤트의 랭킹·신청 화면이 그대로 나온다. **R11은 미해소로 판정한다.** 해소 조건은 §3에 명시.

### 잔존 정합성 결함 1건 — R11 소명문 ↔ 약관 부칙 모순
소명문(R2 문서 §3)은 "현행 약관 제6조의2(**2026-07-29 개정**) 시행 이전에 기획·종료된 이벤트"라고 주장한다. 그러나 실제 약관 부칙(`components/legal/terms-content.tsx:233-238`)은 "**본 약관은 2026년 3월 3일부터 시행합니다**" 한 줄뿐이고 개정 이력이 없다. 이 소명을 제출하는 순간 심사관은 약관을 열어보고, 7-29 개정의 흔적이 없음을 확인하고, **소명 자체를 허위 진술로 기록**한다. 부칙에 개정 이력을 실제로 남기지 않으면 이 소명문은 제출 금지다.

### 운영자 게이트 (거버넌스 자인 + 심사관 추가)
거버넌스의 재신청 전 게이트 4종(①실값 ②이메일 실수신 ③grep 0건 ④redirect)은 타당하나 2가지를 강화한다:
- ③의 grep 패턴 `"베팅|배팅|프로토"`에 **`배당`, `수익`을 추가**하라 (R8 조건 이행 검증 — 아래 §2 참조).
- **통신판매업 신고가 실제로 완료**되어 있어야 한다. "미신고 시 신고 후 기재"라는 각주로는 부족하다 — 신고번호 없이 유료 결제 조항(약관 제7조)을 게시한 상태의 재신청은 즉시 반려한다. 신고 완료가 재신청의 전제 조건이다.

## 2. 질의 2 — 반박·부분 반박 항목별 판정

### A4 (반박: 카카오 로그인 문서 선기재) — **인정**
카카오 동의항목 심사는 수집 항목·목적의 처리방침 선행 기재를 전제하는 것이 맞다. 도입 전 기재는 불일치가 아니라 정합적 순서라는 논리를 받아들인다. **조건**: R3 수정안의 조건부 문구("카카오 로그인 도입 시 …제공받으며")가 실제 반영될 것. 현행처럼 "구글, 카카오 등"으로 이미 수집 중인 것처럼 읽히는 문구를 방치하면 인정을 철회한다.

### R8 (부분 반박: 배수 표시 구조 유지) — **인정 (조건부)**
무료 포인트 게임에서 난이도 가중치 공개는 게임 규칙 요소라는 논거, 그리고 배수 없이 점수 산정 근거를 숨기는 것이 더 나쁘다는 논거는 타당하다. 금전 어휘("수익률"→"점수율", "수익금"→"획득 점수") 즉시 치환과 "배당"→"배점" 명칭 통일을 전제로 구조 유지를 허가한다.
**조건**: (1) 유저 노출 문자열에서 "배당" 0건 — 재신청 게이트 grep에 포함. (2) 주석 포함 치환(거버넌스가 이미 수용). **기록 사항(승인 후 리스크)**: 표시되는 배수가 betman(체육진흥투표권 시스템)의 **실제 배당 원본 수치**라는 사실은 명칭을 바꿔도 소멸하지 않는다. 카카오 측이 수치 대조를 하면 재차 소명이 필요할 수 있다. 자체 배점 체계(반올림·구간화 등)로의 이행을 중기 과제로 기록하라. 이번 심사의 차단 사유로는 삼지 않는다.

### R11 (소명: 종료 이벤트 비노출) — **방향 인정, 이행안 기각**
"문구 수정 = 기록 왜곡, 비노출이 정직하다"는 판단은 옳다. 추첨이 아니었던 이벤트를 추첨이었다고 고쳐 쓰는 안이 왔다면 그게 반려 사유였을 것이다. 그러나:
- 이행 범위(3/7 라우트)는 §0에서 확인한 대로 **결함** — 기각. 요구 수준은 §3.
- 소명문의 "2026-07-29 개정" 주장은 약관 부칙과 모순 — 부칙 정비 없이는 **소명문 제출 불가**.
- 2차 이벤트(EVENT_SEASON_OPEN)의 "활동 기준 추첨" 설계 방침은 인정하며, 카피 작성 시 약관 제6조의2 제3항 체크리스트 명시 약속을 조건으로 기록한다.

### R12 (부분 반박: 프리미엄 비노출) — **인정**
검증 결과 프리미엄 렌더 UI 0곳·구매 진입점 0곳, 골드 구매 버튼 핸들러 부재 — 전부 사실이다. "유저 비노출 상수 문구"를 반려 사유로 유지하지 않는다. **조건**: 자진 정비 3건(골드 탭 숨김, shop-page:414 문구 수정, portone/constants.ts:13 "프리미엄 예측 정보" 삭제)은 반박과 무관하게 **전부 이행**할 것 — 거버넌스 스스로 약속한 것이며, 상수 문구는 다음 개발자가 그대로 UI에 올리는 경로다. **참고**: 약관 제6조·제7조가 골드 유료 구매·결제를 기술하는데 실서비스에 구매 경로가 없는 상태 — A4와 같은 "문서 선기재" 논리로 존치를 허용하되, 골드 경제 오픈 시 방침·약관·화면 삼자 일치를 재점검하라.

### R13 (소명: 생년월일 대신 체크박스) — **인정**
최소수집 원칙 논거는 정당하다. 생년월일 수집을 요구한 바 없고, 요구할 생각도 없다 — 요구한 것은 "확인 절차의 존재"였다. 가입 1단계 필수 체크박스 + 미체크 차단은 국내 통상 관행에 부합하며 충분하다. **조건**: `canProceed`에 실제로 연결되어 미체크 시 진행 불가일 것 (체크박스만 그려놓고 게이트 미연결이면 R13 부활).

## 3. 질의 3 — "이 정도론 부족하다" 항목과 요구 수준

### ① R11 라우트 차단 — 페이지 3곳 redirect(기각) → **세그먼트 전체 차단**
- 요구: `app/worldcup/layout.tsx` **신설**, 최상단에서 `redirect("/prediction")`. 이 한 파일로 7개 라우트(`/worldcup`, `/games`, `/register`, `/register/done`, `/leaderboard`, `/my-predictions`, `/result`)가 전부 차단된다. 개별 페이지 3곳에 redirect를 심는 안은 나머지 4개가 뚫리므로 기각.
- 외부 진입 링크 2곳(home-client:196-198 블록, prediction-client:54-76 블록) 제거는 수정안대로 이행.
- 재신청 게이트에 추가: `/worldcup`, `/worldcup/leaderboard`, `/worldcup/register` **3개 URL 실접속 → 전부 redirect 확인** (게이트 ④를 1개 URL에서 3개로 확대).

### ② R11 소명문 — 약관 부칙 정비 선행
- 요구: `components/legal/terms-content.tsx` 부칙에 개정 이력 추가. 최소 형식: "본 약관은 2026년 3월 3일부터 시행합니다. / 2026년 7월 X일 개정: 제6조의2(승부 예측 서비스의 성격) 신설." 개정 이력이 문서에 실재해야 "약관 개정 이전의 이벤트였다"는 소명이 성립한다. **부칙 미정비 상태로 해당 소명문 제출 시, 이 판정서의 조건부 승인은 무효.**

### ③ R8/R7 검증 게이트 — grep 패턴 확장
- 거버넌스 게이트 ③ `"베팅|배팅|프로토"` → **`"베팅|배팅|프로토|배당|수익"`**으로 확장. "배당"→"배점" 스윕과 "수익률/수익금" 치환은 약속만 있고 검증 게이트에 빠져 있었다. 약속은 게이트에 없으면 이행되지 않는다 — KAKAO_BIZ_APP.md의 허위 ✅가 그 증거다. (단 "수익"은 어드민·약관 내 정당 사용례를 수동 제외하는 방식으로 운용.)

### ④ R5/R6 — 통신판매업 신고 완료를 명시적 전제로
- "플레이스홀더로 배포 금지"(거버넌스 명시)는 옳다. 여기에 추가: **통신판매업 신고번호는 '신고 후 기재'가 아니라 '신고 완료 후 재신청'이다.** 유료 결제 약관(제7조)을 게시한 통신판매업 미신고 사업자는 카카오 심사 이전에 전자상거래법 문제다. 신고가 늦어진다면 차라리 제7조·결제 조항을 약관에서 들어내고 무료 서비스로 신청하는 편이 빠르다 — 양자택일하고, 어정쩡한 중간은 없다.

### ⑤ 문의 이메일 — 수신 테스트 증빙
- "실제 수신 가능해야 함"(거버넌스 명시)에 추가: 재신청 전 외부 주소에서 테스트 메일 1통 발신 → 수신 확인. 부재중 자동응답이라도 좋다. 존재하지 않는 고객센터를 법정 문서 2곳이 참조했던 전력이 있는 서비스다 — 이번엔 증빙을 남겨라.

## 4. 최종 판정

## **조건부 승인**

즉시 수용 8건 + 대안 수용 8건의 이행을 전제로, 반박 1건(A4)과 부분 반박 4건(R8·R11방향·R12·R13)을 인정한다. 단, 아래 **필수 조치 5건**이 추가 이행되지 않으면 조건부 승인은 성립하지 않는다:

| # | 필수 조치 | 근거 |
|---|---|---|
| 1 | `app/worldcup/layout.tsx` 신설로 7개 라우트 전체 차단 (3곳 redirect안 기각) + 게이트 ④를 3개 URL 확인으로 확대 | §3-① |
| 2 | 약관 부칙에 제6조의2 개정 이력 명시 — 미정비 시 R11 소명문 제출 금지 | §3-② |
| 3 | 재신청 grep 게이트를 `베팅\|배팅\|프로토\|배당\|수익`으로 확장 | §3-③ |
| 4 | 통신판매업 **신고 완료** 후 재신청 (또는 결제 조항 제거 후 무료 서비스로 신청 — 양자택일) | §3-④ |
| 5 | 문의 이메일 외부 발신 수신 테스트 증빙 | §3-⑤ |

이행 순서: 개발 수정(R2 문서 §2 + 본 판정서 §3) → 운영자 실값 입력·신고·이메일 개설 → 게이트 5종 통과 → 재신청. 재심사에서는 게이트 통과 증빙(grep 출력, URL 접속 결과, 수신 캡처)을 파일로 요구한다.

심사관 총평: 거버넌스의 대응은 이번 라운드 기준 수준 이상이다 — 사실을 부풀리지 않았고, 자사 체크리스트의 허위를 자백했고, 기록 왜곡 대신 비노출을 택했다. 그 정직성 때문에 조건부 승인을 준다. 다만 라우트 7개 중 3개만 세어놓고 "비노출"이라 부른 것은, 14곳의 베팅 문구를 "순화 완료 ✅"라 부른 것과 같은 병이다. 세는 것부터 다시 하라.
