# 안건: VS 쟁점 생성 — 전면 자동 vs 사람 개입 (2026-07-31)

## 배경
VS 쟁점 = 뉴스에 찬반 폴+3줄 요약을 붙여 "읽기→1탭 투표→진영 댓글" 계단을 만드는 기능. 어제 출시(발행 시 LLM 자동 생성), 오늘 떡밥 카드에서 바로 투표(안 1)까지 합의된 상태.

운영자 의문: **"투표거리 없는 기사에도 억지로 쟁점을 넣는 게 맞나? 사람이 개입해야 하나?"**

## 실측 증거
- 백필 12건 중 10건 생성(83% 통과) — LLM no_issue 가드가 후함
- 품질 갈림: 좋은 것("네이마르 은퇴, 아쉬운 결정인가?", "로티토는 계속 구단주여야 할까?") vs 억지("레알 마드리드가 최고 수익이다?"=수익 발표 기사, "콜로 무아니 영입이 적절한가?"=모든 이적설 복붙형)
- 어미 어색("~이다?") 사례 존재
- **오늘 아침 유사 사고**: 뉴스 자동발행이 오타·영어 미번역·무이미지 글을 무검수로 내보내 정지됨(opt-in 전환). 발행은 빠른검수 수동 체제로 복귀 — 즉 발행 경로에 이미 사람이 앉아 있음
- 투표 데이터는 아직 없음 (기능 출시 직후)

## 선택지
- A안 전면 자동 (현행): 발행 시 LLM이 생성, no_issue 가드만. 프롬프트 강화로 통과율을 낮출 수 있음
- B안 사람 확정: LLM은 "제안"만, 빠른검수 화면에서 운영자가 켜기/문구수정/끄기(기본 꺼짐). 발행에 이미 사람이 있어 추가 클릭 1~2회
- C안 자동 + 사후 관리: 자동 생성하되 admin에서 끄기 가능 + 화력 상위 기사만 생성 등 임계 강화

## 긴장 지점 (각자 정직하게 다뤄야 함)
1. **희소성 vs 밀도**: 모든 기사에 투표가 붙으면 아무 투표도 특별하지 않다 ↔ 떡밥 카드 투표(안 1)를 깔면 폴 있는 카드가 적을수록 피드 참여 표면이 좁아진다
2. **검수 부담**: 자동발행 정지로 운영자 검수량이 이미 복귀·증가한 상태. VS 확정 클릭까지 얹으면? 기본 꺼짐이면 바빠서 아무것도 안 켜져 기능이 사장될 위험
3. **품질 비용의 비대칭**: 억지 쟁점 1개가 위젯 신뢰를 깎는 비용 vs 좋은 쟁점 1개를 놓치는 비용, 어느 쪽이 큰가
4. **시즌 이벤트 맥락**: 8월 중순 유입 때 VS 투표가 게이트 인정 액션·치킨 응모와 연결될 예정 — 그때 폴 공급량이 중요해질 수 있음

## 제약
- 1인 운영. 이벤트까지 개발 여력 제한 (PM 우선순위: 브리지 모달 2일 등 대기 중)
- 품질 실측 데이터(투표 참여율, 폴별 성과)는 몇 주 내 쌓일 예정 (퍼널 계측 살아있음)
