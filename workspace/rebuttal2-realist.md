# Realist 반박문 (2차 토론)

## ① 반박

**1. Visionary의 "C는 신규 인프라 없다, 읽기 시점 계산일 뿐" 주장은 자기모순이다.**
본인이 ②에서 "posts에 타입 플래그 추가, **경기당 1건** 자동 생성"이라 명시했다 — 이건 읽기 계산이 아니라 게임 등록 시점에 post row를 insert하는 **쓰기 경로**다. 중복 방지, 경기 취소/연기 시 처리, 생성 타이밍(등록 즉시 vs 킥오프 임박) 같은 엣지케이스가 그대로 남는다. "신규 cron 없다"는 스코어 렌더링에만 해당하고 게시글 생성 자체의 공수는 여전히 존재한다.

**2. Visionary의 "B+C를 하루 이틀 스코프로 혼합 출시" 제안은 범위를 과소평가한다.**
B(스트립)만 며칠, C(자동 게시글+게이팅+뉴스 첨부)는 별도 컴포넌트·데이터 모델·엣지케이스가 필요한 독립 작업이다. 둘을 한 스프린트에 묶으면 실질 공수는 "하루 이틀"이 아니라 B의 2~3배에 가깝다 — P0(계측·적중카드)와 리소스 경쟁이 실제로 발생한다.

**3. Contrarian의 "언히든이 새 P0-1"이라는 순서화는 동의하지만, "계측 복구 이후에만 C 검증"이라는 전제는 과도하게 무겁다.**
Sentry 클라이언트 전체 복구를 기다릴 필요 없이, CTA 클릭 로그용 경량 이벤트 테이블 하나만으로 B의 클릭률은 즉시 측정 가능하다 — C 착수 여부 판단에 풀 계측 복구가 선행 조건일 필요는 없다.

## ② 수용하는 지점

Contrarian의 "게이팅은 부작용 제거일 뿐 매력 증명이 아니다"는 옳다. 라운드1에서 내가 "C를 안전하게 만들수록 B로 수렴한다"고 한 건 과했다 — C는 댓글이 쌓일 수 있는 독립 콘텐츠 단위라는 점에서 위젯(B)과 형태가 다르다. 다만 그 매력이 검증되지 않았다는 지적은 그대로 받아들여, **C 착수를 데이터 게이트 뒤로 미루는 게 맞다**로 입장을 조정한다.

## ③ 최종 권고

**1단계(즉시, P0-1)**: `header-nav.tsx` `/prediction` 언히든. 반나절, 리스크 0.
**2단계(며칠, P0와 병행)**: 담벼락 상단 "오늘의 경기" 스트립(B) — betman games + wisetoto 조인, 카드 탭 시 경량 이벤트 로그 테이블(신규 1개, board_view 대체 최소 계측)에 클릭 기록. Sentry 풀 복구 불필요.
**3단계(조건부 게이트)**: B의 CTA 클릭률이 일정 기준(예: 노출 대비 클릭 10%+) 넘을 때만 C(앵커 스레드 자동 게시글) 착수 — 매력이 증명된 뒤에 쓰기 경로 공수를 투입한다. A(완전 인라인 통합)는 이번 사이클 기각 유지.
